<design_resolution>
**The research's recommendation does not satisfy the locked decision, and this plan
overrides it.**

16-RESEARCH.md (Don't Hand-Roll, and Open Question 2) recommends storing the
attestation as fields on the persisted S3 networking-persona INSTANCE, to avoid a
migration. That cannot work: the distill call happens BEFORE any instance exists —
the instance is created FROM the distilled persona. An attestation stored on the
instance records the tick only AFTER the gate it was meant to guard has already been
passed. It is a receipt, not a gate.

The research is nonetheless right about what to rule out: decision 8 explicitly
rejects "a once-per-student acknowledgement that later sessions skip", and Phase 10's
`User.videoAnalysisConsentAt` (`prisma/schema.prisma:63`) is exactly that shape and
carries no wording-version field at all. Copying it would violate the decision that
claims to follow it (16-RESEARCH.md Pitfall 1).

**Chosen shape: a small append-only table, one row per distillation event.**

- `NetworkingAttestation { id, userId, attestedAt, wordingVersion, consumedAt }`.
- The wizard's attestation step POSTs a tick -> one row is INSERTED with the wording
  version the client was shown; the row id is returned to the client.
- The distill call carries that id. The server validates it (owned by the caller,
  un-consumed, fresh, current wording version) and stamps `consumedAt` BEFORE the
  model call. One tick, one distillation.

Why this satisfies both halves of decision 8:
- Persisted with user, timestamp and wording version: three real columns.
- Enforced server-side before distillation: the consume happens in `16-05`'s route
  ahead of the distiller call, and a failure returns 403 with no model call made.
- Not once-per-student: `consumedAt` makes each row single-use, so the second paste
  needs a second tick. The table is the audit trail, queryable in Postgres — which an
  S3 JSON blob would not be.

Cost accepted: one additive migration, handled under this repo's existing
human-run-local-only discipline (HANDOFF.md section 3). That cost is the price of a
gate that actually gates.
</design_resolution>

  <name>Task 2: Write the wording registry and the record/consume primitives, and prove them</name>
  <files>lib/networking/attestation.ts, scripts/verify-networking-attestation.ts</files>
  <action>
**`lib/networking/attestation.ts`** — the module 16-05's routes are built on. Export:

- `NETWORKING_ATTESTATION_WORDING: Record<string, string>` — a version-key -> wording
  map. Seed it with ONE entry, key `"v1"`, holding DRAFT wording. Mark the string with
  a `// DRAFT — pending human sign-off (Task 3)` comment: 16-RESEARCH.md flags the
  exact phrasing as a product/legal call, not an engineering one. Draft content should
  name what is being attested: that the student has a legitimate basis for entering
  this description of a real person, that the text is used once to shape a role-play
  persona and is never stored, and that the resulting persona is private to them and
  can never be shared with other students.
- `CURRENT_ATTESTATION_WORDING_VERSION = "v1"` — the only version a new attestation
  may be recorded against. Doc comment: "Bumping this invalidates every un-consumed
  attestation, which is the point: a student who ticked old wording has not agreed to
  the new wording."
- `ATTESTATION_FRESHNESS_SECONDS = 30 * 60` — doc comment: "An attestation is a tick
  the student made moments ago in the wizard, not a standing permission. Thirty
  minutes is generous for a wizard and far short of a session boundary."
- `recordAttestation({ userId, wordingVersion }): Promise<{ ok: true; attestationId: string } | { ok: false; reason: "stale-wording" }>` —
  rejects any `wordingVersion !== CURRENT_ATTESTATION_WORDING_VERSION` WITHOUT writing
  a row, then inserts and returns the id.
- `consumeAttestation({ attestationId, userId, now }): Promise<{ ok: true } | { ok: false; reason: "not-found" | "not-owned" | "already-consumed" | "expired" | "stale-wording" }>` —
  the gate. Must:
  1. Load the row by id. Missing -> `not-found`.
  2. `row.userId !== userId` -> `not-owned`. **Return the same opaque 403 shape at the
     route layer for `not-found` and `not-owned`** so an id cannot be probed for
     existence — the same posture `loadOwnedScenario` takes at
     `lib/scenario/validation.ts:252`.
  3. `row.consumedAt !== null` -> `already-consumed`.
  4. `now - row.attestedAt > ATTESTATION_FRESHNESS_SECONDS` -> `expired`.
  5. `row.wordingVersion !== CURRENT_ATTESTATION_WORDING_VERSION` -> `stale-wording`.
  6. Stamp `consumedAt` with a CONDITIONAL update (`updateMany` with
     `where: { id, consumedAt: null }`) and treat a zero-count result as
     `already-consumed`. This makes the single-use guarantee race-safe; a plain
     `update` after a read is not.
  Take `now` as an argument so the script can test expiry deterministically.

File header comment must state: this module is the SERVER-SIDE GATE for
16-CONTEXT.md decision 8; `consumeAttestation` must be called and must return `ok`
BEFORE any persona-distillation model call runs; and the reason this is a table rather
than a `User` column (quote the decision's rejected "once-per-student acknowledgement
that later sessions skip").

**`scripts/verify-networking-attestation.ts`** — a `tsx` script in the house style
(numbered sections, prints each assertion, non-zero exit on failure), run against the
LOCAL dev DB only. It must create its own throwaway test user, assert, then clean up
its own rows. Assertions:

1. `recordAttestation` with the current version returns an id and a row exists with
   that `userId`, a non-null `attestedAt` and `consumedAt === null`.
2. `recordAttestation` with `"v0"` returns `stale-wording` AND writes no row (count
   before === count after).
3. `consumeAttestation` with the right user, fresh, current version -> `ok: true`, and
   `consumedAt` is now non-null.
4. **Single use.** Consuming the SAME id a second time -> `already-consumed`.
5. **Ownership.** A second user consuming the first user's id -> `not-owned`, and the
   row's `consumedAt` is still null.
6. **Freshness.** A row with `attestedAt` backdated beyond
   `ATTESTATION_FRESHNESS_SECONDS` -> `expired`, and the row is NOT consumed.
7. **Stale wording.** A row written with `"v1"` then read while
   `CURRENT_ATTESTATION_WORDING_VERSION` is simulated as `"v2"` -> `stale-wording`.
   (Pass the current version in or stub the constant — whichever keeps the function
   pure enough to test; if it requires a parameter, add an optional
   `currentWordingVersion` argument defaulting to the constant and note it.)
8. **Unknown id.** A random uuid -> `not-found`.
9. **Phase 10 is untouched.** Assert `User.videoAnalysisConsentAt` still exists and
   that no code under `lib/networking/` reads or writes it
   (`grep` for `videoAnalysisConsentAt` under `lib/networking` returns nothing).

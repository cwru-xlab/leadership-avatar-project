  <action>
**`app/api/networking/persona/route.ts`**

`POST` — create a persona from an ALREADY-DISTILLED sentence:
- Body: `{ persona: string; displayName: string; source: "pasted" | "written" | "generated"; attestationId: string }`.
- Reject with 400 if a `profileText` key is present at all (the tripwire from
  `<non_negotiables>`), or if `persona`/`displayName` fail validation, or if `source`
  is not one of the three.
- **Verify the attestation receipt.** Load the `NetworkingAttestation` row by
  `attestationId`. Require: it exists, `userId === currentUser.id`, and
  `consumedAt !== null` — it must ALREADY have been spent, by the distill route in
  16-05. A still-unspent attestation here means the caller skipped the distill gate, so
  reject with 403. Return the same opaque error for not-found and not-owned. Comment
  that this is the SECOND of two enforcement points for decision 8: the gate itself is
  `consumeAttestation` before distillation (16-05), and this check ensures an ungated
  distillation cannot be laundered into a saved networking persona.
  - `source: "generated"` and `source: "written"` ALSO require an attestation here.
    Rationale to put in the comment: the student's own writing may still describe a real
    person, and a "generated" description may have been hand-edited into one. Only the
    built-in characters (16-06) are attestation-free, and they are not instances.
- Build the record: fresh uuid `personaId`, `ownerId: currentUser.id`, `createdAt` now,
  and copy `attestedAt` / `attestedWordingVersion` from the attestation row. Save it.
- Return 201 `{ personaId, displayName, createdAt }`. **Do not echo `persona` back** —
  the client already has it, and not echoing keeps the response free of the sentence.
- Log only `{ userId, personaId, source, personaLength }`.

`GET` — list the caller's own personas:
`{ personas: [{ personaId, displayName, source, createdAt }] }`. **Never include
`persona` or `attestationId` in the list DTO** — a picker needs a name and a date.
Never accept a `userId` query param; the caller is the owner, full stop (the posture
`app/api/metrics/consent/route.ts` states in its doc comment).

**`app/api/networking/persona/[personaId]/route.ts`**

`GET` — `loadOwnedNetworkingPersona(personaId, currentUser.id)`; `null` -> 404
`{ error: "Not found" }`. On success return the full record MINUS `ownerId` and
`attestationId` (private fields the client has no use for) — follow whatever
private-field-stripping DTO idiom Phase 13's `lib/report/dto.ts` established; read it
and reuse it rather than hand-stripping if it generalizes.

`DELETE` — `deleteOwnedNetworkingPersona`; `false` -> 404; `true` -> 204.

Both route files get a header comment stating: there is deliberately no `PATCH`
(a persona is immutable once distilled — re-distilling means a new attestation and a
new persona) and deliberately no publish/share verb of any kind (decision 7).

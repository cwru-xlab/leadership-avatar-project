  <action>
Create `lib/networking/wizard-client.ts` — a thin, typed client over the four routes, so
the component holds UI state and this module holds the ORDER. Export:

- `generateDescription(hint): Promise<{ description: string }>` -> `POST /api/networking/persona/generate` (16-01).
- `fetchAttestationWording(): Promise<{ wording: string; wordingVersion: string }>` -> `GET /api/networking/attestation`.
- `recordAttestationTick(wordingVersion): Promise<{ attestationId: string } | { staleWording: true; wordingVersion: string }>` -> `POST /api/networking/attestation`, mapping 409 to the stale shape so the component can re-fetch and re-display.
- `distillWithAttestation({ profileText, attestationId }): Promise<{ ok: true; persona; displayName; attestationId } | { ok: false; reason: GateReason }>` -> `POST /api/networking/persona/distill`, mapping the 403 machine codes from 16-05 into a `GateReason` union.
- `saveBroughtInPersona({ persona, displayName, source, attestationId }): Promise<{ personaId: string }>` -> `POST /api/networking/persona` (16-04).
- `listSavedPersonas(): Promise<{ personaId; displayName; source; createdAt }[]>` -> `GET /api/networking/persona`.

File header comment must state the required ORDER and why: tick -> distill (gate spends
the tick) -> save (requires the tick already spent). A client that reorders these gets a
403 from the server, which is the design working. Also state: the hint, the pasted text
and the generated description exist only in React state for the life of the step and are
never persisted client-side.

Every function: `credentials: "same-origin"`, `cache: "no-store"`, and a narrow typed
error rather than a thrown string.

recommended presentation, adopted):

*Card A — "Pick someone to practice with".* Selecting it reveals a grid of
`listNetworkingCharacters()` cards: `displayName`, `headline`, `blurb`, and the
seniority/field as small labels. These are CODE RECORDS — render them directly, no fetch,
no loading state. Selecting a character sets `customization.characterId` and the step is
immediately complete. **No attestation is shown on this branch** (the characters are

*Card B — "Bring in someone real".* Selecting it reveals:
1. A list of the student's SAVED personas from `listSavedPersonas()`, each relaunchable
   in one click (sets `instanceId` and completes the step, no re-pasting, no new
   attestation — the persona is already attested). Empty state: a plain line, not an
   error. This is what makes decision 7's "relaunch without re-pasting" real.
2. Three input modes, as a segmented control: **Paste** (a textarea for LinkedIn or
   similar text), **Write** (the same textarea with different placeholder copy), and
   **Generate** (a single free-text hint input, `MAX_HINT_LENGTH`, a Generate button,
   then the generated description dropped into the SAME editable textarea — one textarea
   for all three modes, so the "edited text is what gets distilled" property is
   structural rather than remembered).
3. A display-name input (`<= 60`, the distiller's `MAX_DISPLAY_NAME_LENGTH`), prefilled
   from the distiller's returned `displayName` and editable.
4. The attestation: a checkbox whose label is the wording returned by
   `fetchAttestationWording()`. Show a loading state while fetching and a plain retry on
   failure — never render a fallback wording of your own.
5. A "Use this person" button, disabled until the textarea is non-empty AND the checkbox
   is ticked. On click, in order: `recordAttestationTick` -> `distillWithAttestation`
   with the textarea's CURRENT value -> `saveBroughtInPersona`, then set `instanceId` and
   complete the step. Show the distilled persona sentence back to the student before
   completing (read-only) so they see what the avatar will actually be given.
6. Error handling per `GateReason`: `stale-wording` -> re-fetch the wording, un-tick the
   box, and say the agreement was updated; `expired` -> ask them to tick again; anything
   else -> a plain retry. A `staleWording` response from the tick itself does the same.

The step reports "cannot advance" until either a `characterId` or an `instanceId` is set.
Exactly one of the two may be set; selecting the other card clears the first.

**`NetworkingGoalStep.tsx`** — one required textarea, ~2 rows, with a modest length cap
(choose 300 chars; record the choice). Copy must say what to put in it with two concrete
examples from 16-CONTEXT.md ("a referral into their team", "advice on breaking into
consulting") and must say plainly: **the person you are practicing with will not be told
this.** Reports "cannot advance" on empty/whitespace. Sets `customization.goal`.

Both components: no `localStorage`/`sessionStorage`, no URL params carrying any of this
text, and no analytics/logging call carrying the paste, the hint, the description or the

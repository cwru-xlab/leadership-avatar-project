<objective>
Put the attestation gate in front of persona distillation — server-side, before any
model call — without adding a second distillation path and without breaking the Phase 8
interview flow that already calls the distill route.

Purpose: 16-CONTEXT.md decision 8 requires the attestation be enforced server-side
BEFORE distillation runs, while decision 1 forbids a second distillation path. The only
shape that satisfies both is: extract the one distiller into a shared module, leave the
existing interview route's contract untouched, and add a networking route that consumes
an attestation and then calls the SAME distiller.

networking routes, one verification script. NO engine file, NO migration, NO component.

<design_note>
**Why the existing route stays ungated, and why that is not a bypass.**

`app/api/interview/persona/distill/route.ts` is ALREADY CALLED by the Phase 8 interview
flow with `{ profileText }` and no attestation. Adding a required attestation field to
it would break that caller, and 16-CONTEXT.md does not ask for the interview flow to be
gated — decision 8 scopes the attestation to the networking brought-in-person path.

So the gate is NOT conditional on a calling context (a `source: "networking"` flag in
the body would be a trivially forgeable bypass and is explicitly rejected here). Instead
the gate is a DIFFERENT ROUTE, and the networking path is gated at two points:

1. `POST /api/networking/persona/distill` consumes an attestation before distilling.
2. `POST /api/networking/persona` (plan 16-04) refuses to save a persona unless its
   `attestationId` names an attestation owned by the caller and ALREADY SPENT.

A client that bypassed (1) by calling the interview route directly gets a persona
sentence it cannot save as a networking persona and cannot launch a networking session
with — because (2) and the session-start path both demand a spent attestation id. The
reachable bypass yields nothing usable, which is the enforceable version of this
requirement given the pre-existing public caller. Record this reasoning in the SUMMARY;
if a future phase wants the interview path gated too, that is its own decision.
</design_note>

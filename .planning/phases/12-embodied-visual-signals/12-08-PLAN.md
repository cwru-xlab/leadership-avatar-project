<task type="auto">
  <name>Task 2: Set the tuned thresholds from the recorded readings</name>
  <files>lib/metrics/body-thresholds.ts, scripts/verify-visual-metrics.ts</files>
  <action>
Using the four recorded sessions, replace each provisional constant with a tuned
value and change its comment from PROVISIONAL to TUNED, citing the observed
reading it came from (e.g. "still session measured 2.1 gestures/min, normal 11.4,
big-gesture 34.8 → still < 5, excessive >= 24").

Set, at minimum: `GESTURE_RATE_STILL_MAX`, `GESTURE_RATE_EXCESSIVE_MIN`,
`GESTURE_AMPLITUDE_MIN`, `HANDS_NEAR_FACE_RADIUS`, `HANDS_NEAR_FACE_TRIP_PCT`,
`POSTURE_DRIFT_TRIP`, `POSTURE_DRIFT_SUSTAINED_S`, the per-signal drift
normalisation scales, `FIDGET_MAX_AMPLITUDE`,
`FIDGET_MIN_DIRECTION_CHANGES_PER_S`, `PHONE_MIN_VISIBLE_S`, and
`LANDMARK_VISIBILITY_FLOOR` if the recordings show the default floor was wrong
for a typical webcam framing.

Calibration rules:
- Place cutoffs so the NORMAL session lands in the middle band for every signal.
  A tuning pass that marks ordinary behaviour as excessive is worse than no
  signal at all.
- Prefer the conservative edge for `GESTURE_RATE_EXCESSIVE_MIN`: a false
  "excessive" is a student being told off for something the sensor misread.
- Cross-check fidget against gesture across the four runs. If the two track each
  other 1:1, they are measuring the same motion — widen the amplitude gap between
  the bands rather than shipping a redundant signal, and record that in the
  tuning file.

Write `.planning/phases/12-embodied-visual-signals/12-TUNING.md` recording, per
session: what the behaviour was, the raw readings, and which cutoff decisions
each one drove. This is the provenance for a grade a student may challenge, so it
needs to exist outside a code comment.

Then update the band-boundary assertions in `scripts/verify-visual-metrics.ts` to
the tuned numbers, and add one assertion per recorded session: feeding that
session's actual measured readings through `visualBodyLanguageBands` /
`visualObservationRows` produces the band a human would call correct for it (still
session → still band, big-gesture session → excessive band, normal → middle).
Those four assertions are what stops a later refactor silently re-tuning the
phase.

Remove the temporary raw-reading console dump added for the checkpoint.

<objective>
Turn the raw pose and hand readings into the SCORED body-language signals: a
self-calibrated posture baseline and drift from it, the three-band gesture curve,
hands-near-face, and the timestamped episodes for all of them.

Purpose: this is the half of the phase that becomes a grade, so its fairness
property has to be structural. The posture score is drift against the student's
OWN opening posture, never a fixed upright ideal — which is precisely why a
wheelchair user, someone with chronic pain or a spinal condition, or someone at a
standing desk needs no opt-out and no disclosure: the baseline is always their
own. Keeping the absolute reading descriptive-only (plan 12-07) is the other half
of that same decision.
Output: populated scored fields, four new episode kinds extracting correctly, and
a per-session `not_measured` that tells the truth.
</objective>

  <name>Task 1: Posture baseline calibration and drift</name>
  <files>lib/metrics/visual-capture.ts</files>
  <action>
Implement the self-calibrated baseline as a PURE, EXPORTED function plus a thin
stateful caller, following the `computeVisualRates` precedent — the pure seam
exists because the divide-by-face-detected bug survived to production by being
reachable only through a live camera, and this is the most consequential new
arithmetic in the phase.

Export:
```ts
export interface PostureReading {
  tS: number;
  shoulderTiltDeg: number | null;
  forwardHeadOffset: number | null;
  torsoLeanDeg: number | null;
  torsoOpennessRatio: number | null;
}
export interface PostureBaseline {
  shoulderTiltDeg: number | null;
  forwardHeadOffset: number | null;
  torsoLeanDeg: number | null;
  torsoOpennessRatio: number | null;
  signals: VisualPostureSignal[];   // which ones the window could actually establish
  sampleCount: number;
}
export function computePostureBaseline(readings: PostureReading[]): PostureBaseline
export function computePostureDrift(reading: PostureReading, baseline: PostureBaseline): {
  driftMagnitude: number | null;    // 0-1, normalised; null when no shared signal
  perSignal: Partial<Record<VisualPostureSignal, number>>;
}
```
Rules:
- The baseline uses readings inside the first `POSTURE_BASELINE_WINDOW_S` of
  CAPTURE time and requires at least `POSTURE_BASELINE_MIN_SAMPLES` usable
  samples for a given signal before that signal gets a baseline. A signal with no
  baseline is simply absent from `signals` and contributes no drift — it is never
  defaulted to an upright value, which would smuggle a fixed ideal back in.
- Per-signal baselines are independent: shoulder line can calibrate while hips
  never become visible.
- Drift is `abs(current - baseline)` per signal, normalised to 0-1 by a per-signal
  scale constant in `body-thresholds.ts`, then averaged across the signals that
  have a baseline. Returning `null` when nothing is comparable is required —
  `clampFinite` turning `undefined` into 0 would print a clean posture reading for
  a student nobody ever measured.
- Store readings as scalars only and cap the retained baseline-window array at
  the window length; drift beyond the window is computed streaming, not retained.

Caller side: accumulate `postureDriftSum`/`postureDriftSamples` for the session
mean, and track the longest contiguous run above `POSTURE_DRIFT_TRIP` in seconds
for `posture_drift_max_s`. Fold a per-window drift mean into `CaptureWindow`
(replacing the 12-05 placeholder) so the `posture_drift` episode kind has
something to trip on.

Populate on the `stop()` return: `posture_drift_mean`, `posture_drift_max_s`, and
`posture_signals_measured` — the set of signals that cleared the visibility floor
often enough to be usable at all, which is what REQ-51's unconditional "states
which signals were available" row renders from. Omit the drift fields entirely
(rather than emitting 0) when no signal ever calibrated.
  </action>
  <verify>`npx tsc --noEmit` clean. New assertions in Task 3 cover the arithmetic. Live: a camera-on session where you deliberately slump halfway through logs a non-zero `posture_drift_mean` and a `posture_drift_max_s` roughly matching how long you stayed slumped; a session sitting unusually but steadily throughout logs a near-zero drift.</verify>
  <done>Drift is computed per-signal against a self-calibrated baseline, absent signals contribute nothing, and a never-visible body yields no drift fields at all.</done>

<task type="auto">
  <name>Task 2: Gesture curve, hands near face, and the new scored episode kinds</name>
  <files>lib/metrics/visual-capture.ts, lib/metrics/types.ts</files>
  <action>
Derive and populate the remaining scored body fields, then wire all four new
episode kinds.

Gesture derivation (pure and exported, same reasoning as above):
```ts
export interface GestureCounts {
  handSamples: number;
  gestureDisplacementSum: number;  // normalised wrist displacement, gesture band only
  gestureEventCount: number;       // displacements over GESTURE_AMPLITUDE_MIN
  handsAboveShoulderSamples: number;
  handsNearFaceSamples: number;
  sessionSeconds: number;
}
export function computeGestureRates(counts: GestureCounts): {
  gestureRatePerMin: number;
  gestureAmplitudeMean: number;
  handsAboveShoulderPct: number;
  handsNearFacePct: number;
}
```
- `gestureRatePerMin` divides gesture events by session MINUTES, not by hand-
  detected samples. Dividing by hand-detected samples would make the rate
  structurally unable to fall for absence — the identical defect
  `camera_centered_pct` already had and that its doc comment warns about.
- `handsNearFacePct` denominator is hand-detected samples where a face box was
  also available, since the signal is undefined without both; document the
  exception explicitly rather than letting it look like an inconsistency.
- Only displacements above `GESTURE_AMPLITUDE_MIN` feed the gesture sums — the
  low-amplitude band belongs to fidgeting (12-07) and the two counters must stay
  independent from the first line of accumulator code.

Populate `gesture_rate_per_min`, `gesture_amplitude_mean`,
`hands_above_shoulder_pct`, `hands_near_face_pct`, omitting all four when no hand
sample was ever usable.

Episode kinds — add a `case` to `windowTrips` for each, all ratio-based so a thin
window cannot trip on one frame, all thresholds imported from
`body-thresholds.ts`:
- `excessive_gesturing`: window gesture rate above `GESTURE_RATE_EXCESSIVE_MIN`
- `minimal_gesturing`: window has enough hand samples to judge AND gesture rate
  below `GESTURE_RATE_STILL_MAX`. The hand-sample guard matters: "no hands
  detected" is not the same finding as "hands visible and still", and conflating
  them would report stillness for someone sitting outside frame.
- `hands_near_face`: near-face count over hand samples above `HANDS_NEAR_FACE_TRIP_PCT`
- `posture_drift`: window drift mean above `POSTURE_DRIFT_TRIP` and the window has
  posture samples at all

`extractEpisodes(windows, VISUAL_EPISODE_KINDS)` then picks them up with no change
— the existing MIN_EPISODE_SECONDS / gap-tolerance / severity machinery applies
unchanged, which is the whole point of the closed-vocabulary design.

Finally, in `lib/metrics/types.ts`, remove `"hand_gestures"` and `"body_posture"`
from `VISUAL_NOT_MEASURED` — their producers now ship, which is the only
condition under which an entry may leave that list — and in `stop()` replace the
unconditional `not_measured: [...VISUAL_NOT_MEASURED]` with
`resolveNotMeasured({ handSignals, postureSignals, fidget: false, phone: false })`
using real per-session usability booleans for hands and posture. Leave the
`fidget`/`phone` arguments false here; 12-07 supplies them when their producers
land. Add a comment at the `resolveNotMeasured` call stating that a session is
allowed to declare a capability unmeasured even though the pipeline supports it —
that is the honest outcome when the body was never in frame.

Add assertions in the existing `check` style:

1. `computePostureBaseline` — establishes shoulder_line only when hips are never
   visible; returns `signals: []` and null readings for an all-null input; ignores
   readings after the calibration window; respects the minimum sample count.
2. `computePostureDrift` — a reading identical to its baseline yields drift 0; a
   large shoulder tilt change yields a high drift; a signal with no baseline
   contributes nothing; a reading with no shared signal yields `null`, not 0.
   **The fairness assertion:** two sessions with very different absolute shoulder
   tilts but identical deltas from their own baselines produce the SAME drift.
   That single assertion is where "the score comes from the student's own opening
   posture" stops being a comment and becomes a test.
3. `computeGestureRates` — zero hand samples yields zeroes and is distinguishable
   from a stillness finding; the rate uses session minutes as denominator (assert
   that doubling hand-detected samples at a fixed event count does NOT change the
   rate); `handsNearFacePct` divides by face-and-hand samples.
4. `windowTrips` via `extractEpisodes` — synthetic window arrays produce exactly
   one `excessive_gesturing`, one `minimal_gesturing`, one `hands_near_face` and
   one `posture_drift` episode at the expected timecodes; a window array with zero
   hand samples produces NO `minimal_gesturing` episode (stillness is not the same
   finding as absence); episodes shorter than `MIN_EPISODE_SECONDS` are dropped.
5. `resolveNotMeasured` wiring — a metrics object from a session with no usable
   pose still lists `body_posture`; one with usable pose and hands lists neither.

absolute posture reading — each assembled into the separate observations
sub-object with its own episode extractor.

presentations, and a phone sitting on the desk in shot is not misconduct. "Your

deduction for it is not defensible if a student challenges it. The type seam from

it, which is also the moment to assert that a 90%-fidget payload moves no score.

timeline, and `VISUAL_NOT_MEASURED` reduced to what truly remains unobservable.
</objective>

  <action>
Add one pure exported derivation and the `stop()` assembly.

```ts
export interface ObservationCounts {
  handSamples: number;
  fidgetSamples: number;          // low-amplitude, high-direction-change samples
  phoneSamples: number;
  phoneVisibleSamples: number;
  phoneSampleHz: number;          // the object runner's effective rate, from SCHEDULE
  absoluteShoulderTiltDegMean: number | null;
  absoluteForwardHeadOffsetMean: number | null;
}
export function computeObservations(counts: ObservationCounts): {
  fidgetPct: number;
  phoneVisibleSeconds: number;
  postureShoulderTiltDeg: number | null;
  postureForwardHeadOffset: number | null;
}
```
Rules:
- `fidgetPct` divides fidget samples by HAND-detected samples — the signal is
  about hands that were visible, and this one is descriptive, so the
  absence-is-poor-performance denominator rule that governs the scored rates does
  not apply. Document the difference explicitly so it does not read as the
  camera-centred bug returning.
- Fidget samples come from the SEPARATE accumulator 12-05 established:
  displacement below `FIDGET_MAX_AMPLITUDE` with at least
  `FIDGET_MIN_DIRECTION_CHANGES_PER_S` reversals. It must not read the gesture
  accumulators. Add a comment naming the warning sign that this went wrong —
  fidget and gesture bands correlating 1:1 across sessions means both are
  measuring the same motion.
- `phoneVisibleSeconds` converts visible samples to seconds using the object
  runner's effective rate (ticks per second from the schedule), not the nominal
  6 Hz. Round to whole seconds and report 0 below `PHONE_MIN_VISIBLE_S` — a
  single false-positive frame must not become "a phone was visible".
- The absolute posture readings are session means of the SAME raw angles 12-06
  already collects for drift, kept at `null` when never measurable. These are the
  absolute reading REQ-51 requires to be produced and shown but never graded.

Then write a separate extractor for the descriptive episode kinds:
`export function extractDescriptiveEpisodes(windows: CaptureWindow[], kinds:
readonly VisualDescriptiveEpisodeKind[]): VisualDescriptiveEpisode[]` with its own
`descriptiveWindowTrips` covering `fidgeting` (window fidget count over hand
samples above a threshold) and `phone_visible` (window phone count over phone
samples above a threshold). It may share the run-collapsing logic with
`extractEpisodes` by extracting a generic inner helper, but the two PUBLIC
functions and the two kind vocabularies must stay distinct — that separation is
what makes a fidget episode unable to enter the scored array.

In `stop()`, assemble `observations: { fidget_pct, phone_visible_seconds,
posture_shoulder_tilt_deg, posture_forward_head_offset, episodes }` as its own
object literal, built after and separately from the scored fields, with a comment
stating that no scored field may be derived from anything inside it. Omit the
whole `observations` key when no descriptive signal was measurable at all.

Finally update the `resolveNotMeasured(...)` call to pass real `fidget` and
`phone` usability booleans, and remove `"fidgeting"` and `"phone_checking"` from
`VISUAL_NOT_MEASURED` in `lib/metrics/types.ts` — leaving only
`background_environment`, whose aesthetic half is permanently out of scope
(judging a background as unprofessional is largely a judgement about someone's
housing). Update that constant's doc comment to reflect the three-category
reality: never measured, measured and scored, measured and never scored — and to
keep the absence-is-not-evidence rule intact, since it is the reason the list
exists.

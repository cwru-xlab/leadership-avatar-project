<objective>
Land the type contract this whole phase hangs off: a third category of signal —
measured but never scored — that is structurally unreachable from scoring, plus
the scored body-language fields, the new episode vocabularies, and one file
holding every provisional threshold.

Purpose: REQ-53 says descriptive signals must never share a list with scored
rows, and the phase context says the two must never share a list *at all*. The
cheapest way to guarantee that is to make it a compile error rather than a
convention — exactly how `VisualCoverage` is already kept structurally separate
from the detection fields so scorability can never be derived from a detection
ratio. This plan ships no producer: every field it adds is populated by later
plans, so it is pure contract plus pure rendering, fully testable through
`scripts/verify-visual-metrics.ts`.
Output: the extended contract, server-side sanitisers, the three new pure
rendering functions, and the provisional-threshold module.
</objective>

  <name>Task 1: Extend the metric contract with scored body fields and a structurally separate observations block</name>
  <files>lib/metrics/types.ts, lib/metrics/body-thresholds.ts</files>
  <action>
In `lib/metrics/types.ts`, add the following. Every new field is OPTIONAL on
`VisualMetrics` (`?`), because legacy stored rows and Phase 10 rows genuinely
lack them and `bands.ts` already omits rather than defaults a missing row — do
not break that discipline.

1. `export const VISUAL_POSTURE_SIGNALS = ["shoulder_line", "forward_head",
   "torso_lean", "torso_openness"] as const;` + `VisualPostureSignal` type.
   Doc it as the landmark groups a posture reading can be built from, gated on
   MediaPipe's per-landmark `visibility`: shoulder_line needs pose landmarks
   11/12, forward_head needs 0 plus 7/8, torso_lean and torso_openness need
   23/24, which a head-and-shoulders webcam frame usually will not have.

2. Extend `VISUAL_EPISODE_KINDS` with the SCORED body kinds:
   `"excessive_gesturing"`, `"minimal_gesturing"`, `"hands_near_face"`,
   `"posture_drift"`. Comment that `minimal_gesturing` and
   `excessive_gesturing` are the two ends of one curve (both reportable — a
   still delivery is a finding the same way monotone volume is), and that
   `posture_drift` is baseline-relative, never an absolute-posture judgement.

3. `export const VISUAL_DESCRIPTIVE_EPISODE_KINDS = ["fidgeting",
   "phone_visible"] as const;` with its own `VisualDescriptiveEpisodeKind` and
   `VisualDescriptiveEpisode` interface (same shape as `VisualEpisode`: kind,
   start_s, end_s, severity). This is deliberately a SEPARATE type, not a
   widening of `VisualEpisodeKind`: a fidget episode must be unable to enter the
   scored `episodes` array at all. Document that `severity` here is a
   descriptive intensity only and that nothing downstream may multiply it into a
   score.

4. `export interface VisualDescriptiveObservations` with:
   - `fidget_pct: number` (0-100 of processed samples in the fidget band)
   - `phone_visible_seconds: number`
   - `posture_shoulder_tilt_deg: number | null` (absolute reading, null when
     never measurable)
   - `posture_forward_head_offset: number | null`
   - `episodes: VisualDescriptiveEpisode[]`
   Header comment must state plainly: nothing in this interface may be read by
   any band/scoring function, and the reason — fidgeting overlaps with stimming,
   ADHD and anxiety presentations, and a phone on the desk is not misconduct;
   describing either is defensible, deducting for it is not.

5. On `VisualMetrics`, add the SCORED body fields:
   `gesture_rate_per_min?`, `gesture_amplitude_mean?` (0-1),
   `hands_above_shoulder_pct?`, `hands_near_face_pct?`,
   `posture_drift_mean?` (0-1, baseline-relative), `posture_drift_max_s?`,
   `posture_signals_measured?: VisualPostureSignal[]`,
   and `observations?: VisualDescriptiveObservations`.

6. `export function resolveNotMeasured(measured: { handSignals: boolean;
   postureSignals: boolean; fidget: boolean; phone: boolean }):
   VisualNotMeasured[]` — pure, returns the entries from `VISUAL_NOT_MEASURED`
   that this session genuinely could not observe. `background_environment` is
   ALWAYS returned (its aesthetic half is permanently out of scope). Keep the
   `VISUAL_NOT_MEASURED` tuple itself intact in this plan — entries are removed
   from it only by the plans that ship each producer (12-06, 12-07), so the list
   never claims a capability before it exists. Document that this replaces the
   unconditional `[...VISUAL_NOT_MEASURED]` spread in `visual-capture.ts`, and
   why: a session where the body was never in frame must still declare
   `body_posture` unmeasured rather than report a silent zero.

Then create `lib/metrics/body-thresholds.ts` holding EVERY numeric cutoff this
phase introduces, with a file header stating in capitals that all values are
PROVISIONAL, were not derived from recorded sessions, and are retuned by plan
12-08 against real recordings — and that no other file in this phase may define
a body-signal threshold inline. Include at minimum, each with a one-line
rationale comment and a named constant:
- `LANDMARK_VISIBILITY_FLOOR = 0.5`
- posture calibration window: `POSTURE_BASELINE_WINDOW_S = 20`,
  `POSTURE_BASELINE_MIN_SAMPLES = 60`
- posture drift: `POSTURE_DRIFT_TRIP`, `POSTURE_DRIFT_SUSTAINED_S`
- gesture curve: `GESTURE_RATE_STILL_MAX`, `GESTURE_RATE_EXCESSIVE_MIN` (per
  minute), `GESTURE_AMPLITUDE_MIN` (the normalized wrist displacement that
  counts as a gesture at all)
- hands near face: `HANDS_NEAR_FACE_RADIUS`, `HANDS_NEAR_FACE_TRIP_PCT`
- fidget discrimination: `FIDGET_MAX_AMPLITUDE`, `FIDGET_MIN_DIRECTION_CHANGES_PER_S`
  — with a comment that fidgeting is defined as a DISTINCT low-amplitude
  high-frequency band, never "gesticulation above an extra threshold", so the
  two counters cannot correlate 1:1 by construction
- phone: `PHONE_SCORE_THRESHOLD = 0.5`, `PHONE_MIN_VISIBLE_S`

  <files>lib/metrics/ingest.ts, lib/metrics/bands.ts</files>
  <action>
`lib/metrics/ingest.ts` — extend `sanitizeVisualMetrics` following the existing
clamp/allowlist style exactly (never throw, never partially accept):
- clamp the six new numeric scored fields with sane bounds
  (`gesture_rate_per_min` 0-600, `gesture_amplitude_mean` 0-1, the two pct
  fields 0-100, `posture_drift_mean` 0-1, `posture_drift_max_s` 0-MAX_SAFE).
- `sanitizePostureSignals(value)` filtering against `VISUAL_POSTURE_SIGNALS`,
  mirroring `sanitizePostureFlags`.
- `sanitizeDescriptiveEpisodes(value)` — a near-copy of `sanitizeEpisodes` but
  allowlisting `VISUAL_DESCRIPTIVE_EPISODE_KINDS`, sharing the same backwards-
  interval drop and a cap of `MAX_DESCRIPTIVE_EPISODES = 40`. Do NOT generalise
  `sanitizeEpisodes` to take a kind list: keeping them as two functions is what
  makes the separation visible at the one place a tampered payload is examined.
- `sanitizeObservations(value): VisualDescriptiveObservations | null` returning
  `null` for a missing/garbage block, with the two posture readings narrowed to
  `number | null` (a non-number becomes `null`, never 0 — a fabricated zero
  degree tilt would be an invented finding).
- Fields are emitted only when present, so a Phase 10 payload still produces the
  identical object it does today. Raise `MAX_PAYLOAD_BYTES` only if the new
  arrays genuinely need it (they add ≤40 rows of 4 numbers; state the decision
  either way in a comment). `MEDIA_SHAPED_PATTERN` and `MAX_STRING_LENGTH` are
  NOT to be touched.

`lib/metrics/bands.ts` — add three exported pure functions, and document in the
file header that scored and descriptive rendering now go through separate
functions by design:
- `visualBodyLanguageBands(m: VisualMetrics): MetricBandRow[]` — the SCORED body
  rows, omitted individually when their field is absent. Rows:
  "Gesturing" (three-band from `gesture_rate_per_min` +
  `gesture_amplitude_mean`: `Very still` / `Well judged` / `A lot of movement`
  — wording must not imply an effect on the interviewer), "Hands near face",
  "Posture drift" (band on `posture_drift_mean` + `posture_drift_max_s`, labelled
  so it reads as change from the student's own opening posture), and — rendered
  UNCONDITIONALLY whenever `posture_signals_measured` is present, including the
  empty case — "Measured from", listing the available signals in plain words
  ("Shoulder line and head position", "Nothing — body not visible in frame").
  That row is REQ-51's "every posture comment states which signals were
  available", and unlike `isPoorVisualCoverage` it is not conditional on
  coverage being poor.
- `visualObservationRows(m: VisualMetrics): MetricBandRow[]` — reads ONLY
  `m.observations` and returns `[]` when absent. Rows describe, never judge:
  hand motion as a percentage band, phone visibility as seconds
  ("A phone was visible for about 40 seconds"), and the absolute posture
  readings when non-null. No row here may contain a word implying a grade.
- `timelineRows(m: VisualMetrics): Array<MetricBandRow & { group: "camera" |
  "body" | "observation" }>` — merges the scored `episodes` and
  `observations.episodes` into ONE chronological list (REQ-55's single timeline),
  tagging each by kind group via a `EPISODE_KIND_GROUP` lookup, offsetting both
  by `coverage.capture_offset_s` like `episodeBand` already does. Add labels for
  the six new kinds to `EPISODE_LABELS` (descriptive kinds get their own
  lookup). Add a comment that the merge is for DISPLAY only and that
  `visualBands`/`visualBodyLanguageBands` still never read `observations`.

Do not modify `visualBands` beyond leaving it untouched — the camera/environment
rows (Eye contact, Attention, Framing, On camera, Lighting, Steadiness, Others
in frame) stay exactly as they are. Steadiness is deliberately NOT retired in
this phase.

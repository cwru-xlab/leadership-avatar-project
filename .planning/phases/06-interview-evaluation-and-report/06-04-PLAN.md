<objective>
Wire evaluation into the request lifecycle: a finish endpoint that stores the final transcript,
flips the row to `PENDING`, returns `{reportId}` immediately, and schedules the evaluator via
`waitUntil`; plus a retry endpoint that re-runs a `FAILED` report from its stored transcript.

Purpose: This is the seam that makes a failed evaluation visible and recoverable without ever
risking the transcript.
Output: `lib/interview/evaluation-runner.ts`, the finish route, the retry route.
</objective>

  <name>Task 1: Shared background evaluation runner</name>
  <files>lib/interview/evaluation-runner.ts</files>
  <action>
Create `lib/interview/evaluation-runner.ts` exporting:

```ts
export async function runAndPersistEvaluation(userId: string, reportId: string): Promise<void>
```

Used by both the finish route and the retry route so failure semantics exist in exactly one place.

Flow:
1. Load the row: `prisma.interviewReport.findFirst({ where: { id: reportId, userId } })`.
   Null → log a warning and return (nothing to do).
2. Load the transcript: `await s3Storage.getInterviewTranscript(userId, reportId)`.
   Null → persist FAILED with reason `"Transcript could not be read from storage."` and return.
3. Resolve role context via `getInterviewType(report.typeSlug)`; fall back to
   `DEFAULT_INTERVIEW_TYPE` if the slug is no longer registered so an old report still evaluates.
   Build `roleContext = { roleTitle: type.defaultRoleTitle, industry: type.defaultIndustry, difficulty: type.difficulty }`.
4. Call `runInterviewEvaluation({ fullTranscript: formatTranscriptForEvaluator(transcript), resumeText: report.resumeText ?? "", roleContext })`.
5. On `ok: true` — update the row:
   ```ts
   { status: "READY", visualScore: null, vocalScore: null,
     contentScore: result.contentScore, behavioralScore: result.behavioralScore,
     reportMarkdown: result.reportMarkdown, failureReason: null,
     evalModel: model, completedAt: new Date() }
   ```
6. On `ok: false` — update the row:
   ```ts
   { status: "FAILED", failureReason: reason, evalModel: model, completedAt: new Date() }
   ```
   Do NOT clear `transcriptKey`, `resumeText`, or `turnCount`.
7. Wrap the whole body in try/catch. In the catch, make a best-effort FAILED write with the
   error message (truncated to 500 chars) and swallow any secondary error — a background job
   must never leave the row stuck in `PENDING` because of an unhandled throw.

Log start and outcome with `console.info` / `console.error` including `{ userId, reportId, status }`.
Never log transcript or resume content.

<task type="auto">
  <name>Task 2: POST /api/interview/session/finish</name>
  <files>app/api/interview/session/finish/route.ts</files>
  <action>
`export const runtime = "nodejs";` and `export const maxDuration = 60;` (the waitUntil job needs
the headroom — see `app/api/interaction/finish/route.ts`). Same auth + `no-store` helper.

Request body: `{ reportId: string; turns: unknown; progress: InterviewProgress }`.

Flow:
1. Auth → 401.
2. UUID-shape `reportId` → 400 if malformed.
3. `findFirst({ where: { id: reportId, userId: currentUser.id } })` → null gives **404**.
4. If `status !== "IN_PROGRESS"` → 409 `{ error: "This interview has already been submitted.", reportId, status }`.
   Make this idempotent-friendly: the client may double-submit; returning 409 with the current
   status lets it navigate to the report page rather than error out.
5. `normalizeTurns(body.turns)`. Empty → 400 `{ error: "There is no interview transcript to evaluate." }`.
   A short-but-nonempty transcript is ACCEPTED and evaluated — the evaluator prompt explicitly
   handles a too-short or disengaged transcript, and the client already warned the student in
   the confirm modal. Do not add a server-side minimum-length block.
6. Write the FINAL transcript to S3 via `s3Storage.saveInterviewTranscript(...)`, built the same
   way as the checkpoint route (DB `startedAt`, canonical `typeSlug`, stored interviewer fields).
   If this write throws → 502 `{ error: "We could not save your interview. Please try again." }`
   and leave the row `IN_PROGRESS`. Never flip to PENDING without a stored transcript.
7. `await prisma.interviewReport.update({ where: { id }, data: { status: "PENDING", transcriptKey, turnCount, failureReason: null } })`.
8. `waitUntil(runAndPersistEvaluation(currentUser.id, report.id));` — import `waitUntil` from
   `@vercel/functions`, matching the existing precedent. Do NOT await it.
9. Respond `202` with `{ reportId: report.id, status: "PENDING" }`.

The path from request to response must contain zero LLM calls; target ~200ms.
  </action>

Next.js App Router dynamic route. Same auth + `no-store` helper. `runtime = "nodejs"`,
`maxDuration = 60`.

Signature: `export async function POST(request: NextRequest, { params }: { params: Promise<{ reportId: string }> })`
— `params` is a Promise in this Next version; `await` it. Match the awaiting style used by other
dynamic routes in `app/api/` (check one before writing).

Flow:
1. Auth → 401. UUID-shape check → 400.
2. `findFirst({ where: { id: reportId, userId: currentUser.id }, select: { id: true, status: true, transcriptKey: true } })`
   → null gives **404**.
3. `status !== "FAILED"` → 409 `{ error: "Only a failed report can be re-run.", status }`.
   This is the guard that prevents regenerating a READY report. State the reason in a comment.
4. `transcriptKey === null` → 409 `{ error: "This interview has no stored transcript to re-run." }`.
5. Flip to `PENDING` and clear `failureReason`, then
   `waitUntil(runAndPersistEvaluation(currentUser.id, reportId));` (not awaited).
6. Respond `202` `{ reportId, status: "PENDING" }`.

The same `reportId` is reused — no new row is created.

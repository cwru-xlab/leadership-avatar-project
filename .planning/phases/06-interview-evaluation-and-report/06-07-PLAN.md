  <action>
`"use client"` client component using `useParams<{ type: string; reportId: string }>()` and
`useRouter()`, matching the style of `app/interview/[type]/page.tsx`.

State: `report: InterviewReportDTO | null`, `error: string | null`, `timedOut: boolean`,
`retrying: boolean`.

Fetching:
- `load()` → `fetch(\`/api/interview/report/\${reportId}\`, { cache: "no-store" })`.
  - 401 → `router.replace("/login")` (confirm the actual login path used elsewhere in the app
    before hardcoding it; if unclear, render an "Please sign in to view this report." card with a
    link rather than guessing a route).
  - 404 → set `error` to "We couldn't find that report." and STOP. Do not reveal whether it
    exists — the API already returns an identical 404 for another student's report.
  - 200 → `setReport(data.report)`.
- On mount: `void load()`.
- Polling: `useEffect` that sets a 2000ms `setInterval` ONLY while
  `report?.status === "PENDING" || report?.status === "IN_PROGRESS"` and `!timedOut`.
  Clear the interval on unmount and whenever the status leaves that set.
- Give-up: a `startedAt` ref captured on mount; when `Date.now() - startedAt > 120_000` while still
  polling, `setTimedOut(true)` and clear the interval. Define `const POLL_MS = 2000;` and
  `const POLL_GIVE_UP_MS = 120_000;` as named constants with a comment that typical evaluation
  lands in 15-40s.

Layout (one shell used by every state so nothing reflows) on `bg-[#f5f8fa] text-[#102331]`,
`mx-auto max-w-4xl px-5 py-10 sm:px-8`:
1. Header row: `Sparkles`-style eyebrow "CASEBRIDGE PRACTICE", `h1` "Your interview report",
   and a sub-line with the interviewer name and completion time when known.
2. `<ReportScoreCards scores={report?.scores ?? nullScores} pending={isPending} />`
3. A body card (`border border-[#d4e2e9] bg-white rounded-2xl shadow-[0_24px_60px_rgba(20,58,75,0.12)]`)
   containing, by state:
   - **PENDING / IN_PROGRESS (not timed out):** a status line with `<Spinner size="sm" />` and
     "Reviewing your interview…", then 4-5 `animate-pulse` placeholder blocks shaped like
     headings and paragraphs, in the same positions the real sections will occupy.
   - **PENDING + timedOut:** "This is taking longer than expected." with a `Check again` button
     that calls `load()` once and resets `timedOut`/the timer.
   - **READY:** `<ReportMarkdown markdown={report.reportMarkdown ?? ""} />`.
   - **FAILED:** a `CircleAlert` block — "We couldn't generate your report." plus
     `report.failureReason` in smaller muted text, then a `Try again` button that POSTs to
     `/api/interview/report/{reportId}/retry`, and on 202 sets `retrying`, clears `timedOut`,
     and resumes polling. Include the reassurance line: "Your interview transcript is saved —
     nothing was lost."
4. Footer actions: `Back to practice` (variant flat) → `router.push("/student-cases")` and
   `Practice again` (color primary) → `router.push(\`/interview/\${params.type}\`)`.

Canonical-URL handling: once `report` loads, if `report.typeSlug !== params.type`, call
`router.replace(\`/interview/\${report.typeSlug}/report/\${report.id}\`)`. **Redirect, do not 404** —
`reportId` is the only thing ownership depends on.

Never render `reportId`-adjacent internals: no S3 keys, no resume text, no resume link.

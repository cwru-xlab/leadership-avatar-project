<task type="auto">
  <name>Task 2: The visual capture engine</name>
  <files>lib/metrics/visual-capture.ts</files>
  <action>
Create `lib/metrics/visual-capture.ts`. Browser-only module (`"use client"` is
not needed for a non-component module, but every browser API access must sit
inside a function, never at module scope, so the file is import-safe on the
server).

Export `requestCameraStream(): Promise<{ ok: true; stream: MediaStream } | { ok: false; reason: "DENIED" | "NOT_FOUND" | "UNAVAILABLE" }>`:
- Calls `navigator.mediaDevices.getUserMedia({ video: { width: { ideal: 640 }, height: { ideal: 480 }, facingMode: "user" } })`.
  Request a MODEST resolution deliberately — 640x480 at 6 Hz is ample for
  presence/framing and materially cheaper than 1080p (REQ-49).
- Request VIDEO ONLY here. Audio stays on the existing, untouched
  `getUserMedia({ audio: true })` path at
  `components/interview/InterviewSessionShell.tsx:475` — do not merge the two
  constraint objects, because the audio stream's lifecycle is already managed by
  the push-to-talk code and must not change.
- Map `NotAllowedError`/`PermissionDeniedError` -> `"DENIED"`,
  `NotFoundError`/`DevicesNotFoundError`/`OverconstrainedError` -> `"NOT_FOUND"`,
  anything else (including `NotReadableError`, i.e. the camera seized by another
  app) -> `"UNAVAILABLE"`. Plans 10-09/10-10 turn these into the REQ-37 block
  screen; this function never renders UI and never throws.

Export `createVisualCapture(options: { stream: MediaStream; onFaceStateChange?: (faceDetected: boolean) => void }): VisualCaptureHandle` where
`VisualCaptureHandle = { start(): Promise<void>; stop(): VisualMetrics | null; }`.

`start()`:
- Creates a detached `<video>` element (`muted`, `playsInline`, `autoplay`),
  attaches the stream, awaits `loadeddata`. Do NOT reuse the self-view's DOM
  element — the engine owns its own so it cannot be broken by a UI remount.
- Dynamically imports `FaceLandmarker` and `FilesetResolver` from
  `@mediapipe/tasks-vision` INSIDE `start()` so the ~several-MB runtime is never
  in the initial bundle and never loads for a camera-off session.
- `FilesetResolver.forVisionTasks("/mediapipe/wasm")` (or the pinned CDN URL from
  Task 1's fallback), then
  `FaceLandmarker.createFromOptions(resolver, { baseOptions: { modelAssetPath: "/mediapipe/face_landmarker.task", delegate: "GPU" }, runningMode: "VIDEO", numFaces: 1, outputFacialTransformationMatrixes: true })`.
  Request the GPU delegate explicitly (research Pitfall 1). Wrap init in
  try/catch; on failure retry ONCE with `delegate: "CPU"`; if that also fails,
  set `analyzerError = true`, invoke `onFaceStateChange?.(true)` so no banner is
  left stuck on screen, and return without starting a loop. A failed engine must
  never look like a student facing away — that is exactly REQ-42.
- Runs a `setInterval` at `1000 / METRICS_SAMPLE_HZ` (imported from
  `lib/metrics/types.ts`, i.e. ~167ms). Use an interval, NOT
  `requestAnimationFrame`: rAF is display-rate-coupled and would do ~10x the
  needed work, and it is throttled to near-zero in a backgrounded tab, which
  would silently corrupt the liveness counters rather than register as starvation.
- Each tick: if the video track's `readyState !== "live"`, skip inference and do
  NOT increment `processedSamples`; add the elapsed tick to nothing. Otherwise
  add the tick duration to `trackLiveSeconds`, call
  `landmarker.detectForVideo(videoEl, performance.now())` inside try/catch, and
  increment `processedSamples` on any returned result — face found or not. A
  thrown detect error increments a consecutive-error counter; three consecutive
  errors sets `analyzerError = true` and stops the loop.

Per-sample aggregation — SCALARS ONLY. Never retain a frame, an ImageBitmap, a
landmark array, or a canvas beyond the current tick. Accumulate:
- `faceDetectedSamples` when `result.faceLandmarks.length > 0`.
- Forward-gaze: derive yaw and pitch from
  `result.facialTransformationMatrixes[0].data` (a column-major 4x4); compute
  `yaw = atan2(-m[8], m[0])` and `pitch = asin(clamp(m[9], -1, 1))` in radians,
  convert to degrees. Count the sample as forward-facing when
  `abs(yaw) <= 25 && abs(pitch) <= 20`. Document those cone limits as a Phase 10
  decision and document that this is a HEAD-POSE PROXY for eye contact, not
  pupil tracking — the honesty requirement from CONTEXT.md's metric contract.
  If `facialTransformationMatrixes` is empty for a detected face, count the
  sample as detected but not forward-facing, and increment a
  `poseUnavailableSamples` counter; if that counter exceeds half of
  `faceDetectedSamples` at stop time, set `analyzerError = true` rather than
  reporting a bogus 0% eye contact.
- Framing: compute the face bounding box from the min/max of
  `result.faceLandmarks[0]` normalized x/y. Count `centeredSamples` when the box
  centre lies within x in [0.25, 0.75] and y in [0.15, 0.75]. Count
  `outOfFrameSamples` when any of minX<0.02, maxX>0.98, minY<0.02, maxY>0.98.
- Head movement: accumulate the absolute delta of the box centre between
  consecutive detected samples into `movementSum` and `movementSamples`.
- Lighting: every 12th tick only (once every two seconds — a luma read is the
  single most expensive operation here), draw the video into a reused 64x64
  offscreen canvas, read the pixels, compute mean luma over the face box region
  (fall back to the whole frame if no face), and accumulate into `lumaSum`/
  `lumaSamples`. Reuse ONE canvas and ONE `getImageData` buffer for the whole
  session; clear nothing to storage. The canvas and its context are released in
  `stop()`.
- Call `onFaceStateChange(detected)` only on a TRANSITION, and only after a
  detected/undetected state has persisted for 3 consecutive samples (~0.5s), so
  the banner does not flicker on a single blink or a momentary miss.

`stop()`:
- Clears the interval, closes the landmarker (`landmarker.close()`), detaches
  and releases the detached video element and the canvas. Does NOT stop the
  MediaStream tracks — the caller owns the stream (the self-view is still
  attached to it).
- Returns a `VisualMetrics` object:
  - `eye_contact_pct = round(forwardFacingSamples / max(1, processedSamples) * 100)`.
    **Denominator is PROCESSED samples, not detected samples** — a student who
    is absent from frame must score down for it (REQ-41), and dividing by
    detected samples would silently normalise that away.
  - `camera_centered_pct = round(centeredSamples / max(1, faceDetectedSamples) * 100)`.
    Here the denominator IS detected samples: framing is only meaningful for a
    frame containing a face, and absence is already penalised through
    `eye_contact_pct`. Comment the asymmetry so it reads as deliberate.
  - `lighting_ok = lumaSamples > 0 && meanLuma >= 40 && meanLuma <= 225`.
  - `posture_flags`: push `"face_partially_out_of_frame"` when
    `outOfFrameSamples / max(1, faceDetectedSamples) > 0.15`; push
    `"high_head_movement"` when `movementSum / max(1, movementSamples) > 0.04`.
    Use only the two flags in `VISUAL_POSTURE_FLAGS` — nothing else is honestly
    measurable from face landmarks.
  - `coverage`: `session_seconds`, `track_live_seconds`,
    `expected_samples = floor(track_live_seconds * METRICS_SAMPLE_HZ)`,
    `processed_samples`, `face_detected_samples`, `sample_hz`, `analyzer_error`.
- Returns `null` only if `start()` was never called.

Never `console.log` a frame, a landmark array, or anything derived from pixel
data beyond the final scalars.

`SelfViewThumbnail({ stream, className }: { stream: MediaStream | null; className?: string })`:
- Renders a `<video muted playsInline autoPlay>` and attaches `stream` via a ref
  in an effect (`el.srcObject = stream`), clearing it on unmount. Must be
  `muted` — an unmuted self-view causes audio feedback with the live avatar.
- Fixed bottom-right placement by default (`fixed bottom-4 right-4 z-40`),
  ~176x132 (`w-44`), rounded and ring-bordered to match the report cards'
  palette (`border-[#d4e2e9]`, `rounded-2xl`). `pointer-events-none` so it can
  never intercept a click meant for the session controls. Mirror the video
  (`scale-x-[-1]`) — an unmirrored self-view reads as wrong to everyone.
- Returns `null` when `stream` is null, so a camera-off session renders nothing.
- Include a small always-visible "You" label so it is unambiguous which video is
  which next to the avatar's own stream.
- Add a `<span className="sr-only">` note that this preview is local only and is
  not recorded.

`FaceDetectionBanner({ visible }: { visible: boolean })`:
- Renders a single small pill, top-centre of the session area
  (`fixed left-1/2 top-4 -translate-x-1/2 z-40`), with `pointer-events-none`.
- FOLDS AWAY rather than unmounting: always render the element and animate
  between states with `transition-all duration-300` plus
  `opacity-0 -translate-y-2 max-h-0 overflow-hidden` when `!visible` and
  `opacity-100 translate-y-0 max-h-16` when visible. CONTEXT.md's verbatim word
  is "folds away" — an unmount is a disappear, not a fold, and would also lose
  the transition.
- Copy: a `CircleAlert` (or `VideoOff`) lucide icon plus
  "We can't see your face right now" and a second, smaller line
  "Move back into frame — this affects your Visual score." That second line is
  informational, not a metric, and states the consequence honestly since REQ-41
  makes it real.
- `role="status"` and `aria-live="polite"` so it announces without stealing
  focus; never `role="alert"`, which interrupts.
- Amber/warning palette consistent with the repo's existing HeroUI `warning`
  toasts, but as a plain styled div — do NOT use `addToast`, which is a
  dismissible interruption and cannot fold away.

  <name>Task 1: Define the shared metric contract</name>
  <files>lib/metrics/types.ts</files>
  <action>
Create `lib/metrics/types.ts`. No imports from `lib/interview/` or
`lib/scenario/` — this module is the dependency, not the dependent.

Export exactly these:

1. `export type CameraMode = "ON" | "OFF";`

2. `export interface VisualMetrics` — the measured payload. Fields, ALL required
   (the pipeline either produces the block or omits it entirely; it never
   produces a half-block):
   - `eye_contact_pct: number` — 0-100. Percentage of PROCESSED samples where a
     face was detected AND head yaw/pitch fell inside a forward cone. Document
     in a comment that this is a measured forward-gaze proxy from head pose, not
     literal pupil tracking, and that it is a measurement (not a transcript
     estimate) which is what `lib/interview/prompts.ts`'s missing-data rule cares
     about.
   - `camera_centered_pct: number` — 0-100. Percentage of face-detected samples
     whose face bounding-box centre sat inside the central region of the frame.
   - `lighting_ok: boolean` — mean luma of the face region across samples inside
     an acceptable range.
   - `posture_flags: string[]` — a CLOSED vocabulary, documented in the comment
     as deliberately restricted to what face-landmark data can defend:
     `"face_partially_out_of_frame"` and `"high_head_movement"` only. Add an
     explicit comment: slouching / fidgeting / phone-checking are NOT measurable
     from face landmarks and must never appear here — emitting them would violate
     `lib/interview/prompts.ts`'s "do not estimate" rule. Export the vocabulary as
     `export const VISUAL_POSTURE_FLAGS = ["face_partially_out_of_frame", "high_head_movement"] as const;`
   - `coverage: VisualCoverage` — see below.

3. `export interface VisualCoverage` — the LIVENESS block, tracked independently
   of detection outcome. This is REQ-42's mechanism and must be a separate
   sub-object so no future edit can accidentally derive it from the detection
   ratio:
   - `session_seconds: number` — wall clock from capture start to session end.
   - `track_live_seconds: number` — accumulated time the video track's
     `readyState` was `"live"`.
   - `expected_samples: number` — `floor(track_live_seconds * sample_hz)`.
   - `processed_samples: number` — samples the detector actually returned a
     result for (face found OR not found — both count as processed).
   - `face_detected_samples: number` — subset of processed where a face was found.
   - `sample_hz: number` — the configured throttle rate.
   - `analyzer_error: boolean` — set true if landmarker init threw or the detect
     loop threw a non-recoverable error.

4. `export interface VocalMetrics` — fields mirroring the already-declared
   contract at `lib/interview/prompts.ts:213-215`:
   `words_per_minute: number`, `filler_word_count: number`,
   `filler_word_list: string[]`, `pause_count: number`,
   `volume_consistency: number` (0-1, 1 = perfectly steady), plus
   `coverage: VocalCoverage`.

5. `export interface VocalCoverage`:
   - `spoken_turns: number` — turns delivered by voice.
   - `typed_turns: number` — turns delivered by typing.
   - `analyzed_turns: number` — spoken turns whose word-timing analysis actually
     returned (a spoken turn whose STT call failed counts as spoken but not
     analyzed — this is the vocal liveness signal).
   - `spoken_seconds: number` — total measured spoken audio duration.
   - `analyzer_error: boolean`.

6. `export const FILLER_WORD_LEXICON` — a frozen array of lowercase filler
   tokens/bigrams: `um`, `uh`, `er`, `ah`, `like`, `you know`, `i mean`,
   `sort of`, `kind of`, `basically`, `actually`, `literally`, `right`, `so`.
   Comment that matching is case-insensitive, whole-token, and that multi-word
   entries are matched as consecutive word sequences.

7. `export type VisualUnscoredReason = "CAMERA_OFF_OPTOUT" | "INSUFFICIENT_DATA";`
   and `export type VocalUnscoredReason = "TYPED_ONLY" | "INSUFFICIENT_DATA";`
   Document that `null` on a report row means either "scored" or the legacy
   "no pipeline existed" case, disambiguated by whether `cameraMode` is null.

8. `export interface SessionMetricsPayload` — exactly what the client POSTs to a
   finish route: `{ cameraMode: CameraMode; visual: VisualMetrics | null; vocal: VocalMetrics | null; }`.
   Comment loudly: this payload contains ONLY derived scalars. No frames, no
   audio, no data URLs, no blob references. REQ-38 is enforced by this type's
   shape being the only thing the client is allowed to send.

Also export `export const METRICS_SAMPLE_HZ = 6;` with a comment explaining 6 Hz
is far below display frame rate, plenty for a coverage aggregate, and chosen to
protect the live HeyGen stream (REQ-49) — this is not a coaching feature.

<task type="auto">
  <name>Task 3: The liveness-vs-performance discriminator</name>
  <files>lib/metrics/coverage.ts</files>
  <action>
Create `lib/metrics/coverage.ts`. This is REQ-42 and the phase's hardest
correctness concern — CONTEXT.md forbids any code path that collapses "the
student left frame" with "the analyzer died". The research proposed a single
processed-vs-expected ratio; that is NOT sufficient on its own (a camera track
seized 20 seconds into a 10-minute session produces a perfectly healthy ratio
against its own short live time). Implement THREE independent failure signatures
plus a scoring path.

`export function resolveVisualOutcome(cameraMode: CameraMode, visual: VisualMetrics | null): { scored: boolean; reason: VisualUnscoredReason | null }`

Order of checks, each with its own comment explaining which real-world failure
it catches:
1. `cameraMode === "OFF"` -> `{ scored: false, reason: "CAMERA_OFF_OPTOUT" }`.
   A deliberate opt-out. Must be checked FIRST so it can never be misreported as
   a technical failure.
2. `visual === null` while `cameraMode === "ON"` -> `INSUFFICIENT_DATA`. The
   client promised metrics and delivered none.
3. `visual.coverage.analyzer_error === true` -> `INSUFFICIENT_DATA`, regardless
   of every ratio. An explicit thrown error is the strongest signal available
   and must not be outvoted by healthy-looking counters.
4. Track-death check: `track_live_seconds / max(1, session_seconds) < 0.5` ->
   `INSUFFICIENT_DATA`. Catches a camera unplugged, revoked, or seized by
   another app partway through — the case a processed/expected ratio alone
   cannot see, because a dead track also stops generating expected samples.
5. Starvation check: `processed_samples / max(1, expected_samples) < 0.5` ->
   `INSUFFICIENT_DATA`. Catches an inference loop that initialised but was
   starved of frames (tab backgrounded, worker wedged).
6. Absolute floor: `processed_samples < 60` (ten seconds at
   `METRICS_SAMPLE_HZ`) -> `INSUFFICIENT_DATA`. Guards the degenerate
   tiny-session case where every ratio above is trivially satisfiable.
7. Otherwise -> `{ scored: true, reason: null }`. **Add a comment stating
   explicitly that `face_detected_samples` is deliberately NOT consulted in this
   function: a live pipeline that saw a face zero percent of the time is a
   scoreable low Visual score, per REQ-41, and introducing a detection threshold
   here would reintroduce exactly the coverage gate CONTEXT.md forbids.**
   A regression test in the verify step asserts this.

`export function resolveVocalOutcome(vocal: VocalMetrics | null): { scored: boolean; reason: VocalUnscoredReason | null }`

1. `vocal === null` -> `INSUFFICIENT_DATA`.
2. `coverage.spoken_turns === 0` -> `{ scored: false, reason: "TYPED_ONLY" }`.
   REQ-44: typing is a different modality, never a penalty. Note in a comment
   that this is deliberately NOT symmetric with the visual case.
3. `coverage.analyzer_error === true` -> `INSUFFICIENT_DATA`.
4. `coverage.spoken_turns > 0 && coverage.analyzed_turns === 0` ->
   `INSUFFICIENT_DATA`. The student spoke but nothing could be analysed.
5. `coverage.spoken_seconds < 30` -> `TYPED_ONLY`. Under half a minute of speech
   in a mostly-typed session is a modality outcome, not a technical failure, and
   not weak delivery — document the reasoning.
6. Otherwise scored. A mixed typed/spoken session is scored on its SPOKEN
   portion only; typed turns contribute nothing and subtract nothing.

`export function isPoorVisualCoverage(visual: VisualMetrics): boolean` — the
REQ-46 disclosure predicate, entirely separate from scoring. Returns true when
`face_detected_samples / max(1, processed_samples) < 0.6`. Comment that this
governs only whether coverage TEXT is shown to the student, never the score
itself, and that keeping disclosure and scoring as two functions is the
anti-pattern guard the research flagged.
  </action>

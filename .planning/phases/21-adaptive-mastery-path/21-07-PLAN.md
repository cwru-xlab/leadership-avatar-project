<objective>
Open a NAMED, SCOPED exception to the study-plan privacy boundary so knowledge
checks can be generated from the student's own session moments — and record it in
writing, with what it does not permit.

Purpose: this is the one place where Phase 21 genuinely conflicts with existing
architecture, and it must be decided deliberately rather than discovered in code
review. `lib/study-plan/generate.ts` carries a hard privacy filter: raw reports
never leave the server, and the model receives only anonymous report ordinals,
two score aggregates, and locally-extracted closed-vocabulary rubric
label/rating strings. Its own comment says narrative examples are discarded
"preventing names, employers, resume details, answers, or other personal
information from leaving this application."

21-CONTEXT.md locks the opposite for knowledge checks: content is generated from
the student's OWN session moments — real transcript moments and the gaps their
report identified, explicitly "not a generic authored bank." A verbatim quote of
the student is required by REQ-110. These cannot both be true on one path.

The resolution is two paths, not a loosened one. The existing plan generator
keeps its filter byte-for-byte. A second, narrower path sends the student's own
words only, with everything else enumerated and stripped.

Output: `lib/study-plan/moment-boundary.ts`, a boundary record, and a verifier
that proves the old path is unchanged.
</objective>

Export `MOMENT_BOUNDARY_POLICY` as a documented const object stating, as data
rather than prose, exactly what the exception permits and forbids:

```ts
export const MOMENT_BOUNDARY_POLICY = {
  permits: [
    "the student's own verbatim transcript turns, for the user whose checks are being generated",
    "the avatar's immediately preceding turn, as the setup the student was responding to",
    "the student's own report growth-area titles and the competency keys they map to",
  ],
  forbids: [
    "the student's name, email, employer, school, or any resume field",
    "any OTHER person's name or identity, including a third-party persona pasted for networking distillation",
    "report prose beyond growth-area titles",
    "any turn from a report the requesting user does not own",
    "the deck, its slides, or any uploaded artifact text",
  ],
  scope: "knowledge-check and coached-session generation only — NOT study-plan synthesis",
  unchanged_path: "lib/study-plan/generate.ts keeps its closed-vocabulary filter",
} as const;
```

Export `prepareMomentsForGeneration(args: { requestingUserId: string; moments:
SessionMoment[]; momentOwnerUserIds: string[] }): MomentGenerationPayload`.

Enforce, in this order, throwing on violation:

1. OWNERSHIP FIRST. Every entry in `momentOwnerUserIds` must equal
   `requestingUserId`. Throw before touching any text. This is the only check
   whose failure means a cross-user leak, so it runs before anything that could
   partially succeed. Caller supplies the owner ids alongside the moments rather
   than this module re-querying, so the check is on the data actually about to be
   sent, not on a second lookup that could disagree.
2. REDACTION. For each moment's `studentText` and `precedingAvatarText`, apply an
   enumerated redactor and record what it removed:
   - email addresses → `[email]`
   - URLs → `[link]`
   - phone-shaped digit runs → `[phone]`
   - any capitalized token matching the requesting user's own first or last name
     (passed in via a `selfNames: string[]` arg) → `[me]`
   Do NOT attempt general NER or model-based PII detection. A model-based
   redactor would be a judgement call in a privacy guarantee, which is the exact
   pattern 21-CONTEXT.md's deterministic-over-model constraint rules out. State
   that limitation explicitly in a comment, and state what it means: this
   redactor catches structured identifiers, not an arbitrary third-party name
   the student happened to say aloud. That residual risk is accepted and
   recorded in the boundary document, not papered over.
   CRITICAL: redaction must NOT alter a quotable span. Any moment whose
   `studentText` was modified by redaction is DROPPED from the payload entirely
   rather than sent in redacted form — because a redacted line can no longer
   satisfy REQ-110's verbatim guarantee, and a question quoting `[email]` would
   be a misquote. Count and report drops.
3. CAP. At most 12 moments and at most 8,000 characters total, whichever binds
   first, keeping the most recent. Export both numbers as named consts marked
   PROVISIONAL UNTIL CALIBRATED with their reasoning: 12 moments is enough to
   generate a 5-10 step path's checks with slack, and 8,000 characters keeps one
   generation inside a single request without truncation mid-quote.

`MomentGenerationPayload` carries `moments`, `droppedForRedaction: number`,
`droppedForCap: number`, and `totalCharacters`. The caller logs the drop counts —
a generation that silently had half its evidence removed should be visible.

Do NOT import from or edit `lib/study-plan/generate.ts`. That file's filter is
the thing this plan is proving unchanged.

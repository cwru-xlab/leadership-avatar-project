<objective>
Add the persistence Phase 21 needs: a mastery contribution ledger, the four-format
knowledge-check model with attempts and contests, and the study-plan-owned path
with its steps and coached sessions.

Purpose: every other plan in this phase reads or writes these tables. Modelling
them once, up front, keeps six later plans from each inventing their own shape.
The two structural decisions that matter are encoded here: the path is a CHILD of
StudyPlan (21-CONTEXT.md: "not a global queue"), and every mastery contribution
is ONE row in ONE ledger regardless of source (21-CONTEXT.md: both live sessions
and knowledge checks move mastery).

Output: seven new Prisma models and a hand-authored migration, unapplied.
</objective>

  <action>
Append a `// ADAPTIVE MASTERY PATH (Phase 21)` banner section after

`MasteryContribution` — the single ledger REQ-107 requires.
  `id`, `userId` (relation to User, onDelete: Cascade), `competencyKey String`,
  `source String` (`"LIVE_SESSION" | "COACHED_SESSION" | "CHECK_DETERMINISTIC" |
  "CHECK_MODEL_GRADED"` — enforced in code, not a Prisma enum, so a later source
  needs no migration; say so in the comment), `rawScore Float` (normalized 0..1),
  `weight Float` (the declared weight in force when the row was written —
  SNAPSHOTTED, not looked up at read time, so retuning weights never silently
  rewrites history), `sourceReportId String?` (relation-free soft pointer to
  InteractionReport for a live or coached session; null for a check),
  `sourceAttemptId String?` (KnowledgeCheckAttempt for a check; null otherwise),
  `reversedAt DateTime?` + `reversedReason String?` (REQ-112's contest reverses a
  contribution rather than deleting the row — the ledger is APPEND-ONLY apart
  from these two columns; state that in the comment), `occurredAt DateTime`
  (the session's or attempt's own time, NOT createdAt — the current-window
  figure in REQ-104 windows on this), `createdAt`.
  Indexes: `@@index([userId, competencyKey, occurredAt])` (the lifetime and
  window queries), `@@index([userId, occurredAt])`, `@@index([sourceAttemptId])`.

`KnowledgeCheck` — one generated question, any of the four formats.
  `id`, `userId`, `studyPlanId String` (relation to StudyPlan, onDelete: Cascade
  — a check belongs to the plan whose path generated it), `competencyKey String`,
  `format String` (`"MULTIPLE_CHOICE" | "FILL_IN_BLANK" | "PICK_BETTER_RESPONSE"
  | "REWRITE_WEAK_LINE"`), `prompt String @db.Text`,
  `payload Json` (format-specific body — options, blanks, the two candidate
  responses, the weak line; shape validated in TypeScript per format, documented
  as living in `lib/study-plan/checks/types.ts`),
  `answerKey Json?` (null for REWRITE_WEAK_LINE, which has no deterministic key —
  that nullability is what makes REQ-111's split visible in the schema),
  `sourceReportId String?`, `quotedTurnIndex Int?`, `quotedText String? @db.Text`
  (REQ-110: the verbatim quote and its originating turn, stored so the guarantee
  is re-checkable after the fact, not only at generation),
  `generationModel String`, `flaggedAt DateTime?` + `flagReason String?`
  (REQ-112 flags a bad generated question), `createdAt`.
  Indexes: `@@index([userId, studyPlanId])`, `@@index([userId, competencyKey])`,
  `@@index([flaggedAt])`.

`KnowledgeCheckAttempt` — one student answer.
  `id`, `knowledgeCheckId` (relation, onDelete: Cascade), `userId`,
  `response Json`, `correct Boolean?` (null while a model grading is pending),
  `score Float?` (0..1), `gradedBy String` (`"DETERMINISTIC" | "MODEL"`),
  `graderModel String?`, `graderRationale String? @db.Text`,
  `submittedAt DateTime @default(now())`, `gradedAt DateTime?`.
  Unique: `@@unique([knowledgeCheckId, userId])` — one attempt per check per
  student; a re-answer after a contest is handled by the contest row, not by a
  second attempt. Index `@@index([userId, submittedAt])`.

`GradingContest` — REQ-112.
  `id`, `attemptId String @unique` (relation, onDelete: Cascade — one contest per
  attempt), `userId`, `reason String @db.Text`,
  `status String @default("OPEN")` (`"OPEN" | "UPHELD" | "REJECTED"`),
  `raisedAt DateTime @default(now())`, `resolvedAt DateTime?`,
  `resolutionNote String? @db.Text`.
  Index `@@index([status, raisedAt])`.

`StudyPlanPath` — REQ-117's child-of-study-plan.
  `id`, `studyPlanId String @unique` (relation to StudyPlan, onDelete: Cascade —
  `@unique` is what makes it exactly one path per plan, and Cascade is what makes
  it a child rather than a peer), `userId`, `generatedAt DateTime @default(now())`,
  `selectionSnapshot Json` (the mastery figures the path was generated against,
  frozen — REQ-118's explanation must still make sense months later, after mastery
  has moved on), `createdAt`.
  Index `@@index([userId, generatedAt])`.
  Note in the comment: old paths are NOT deleted and NOT carried forward; they
  remain reachable via their StudyPlan. Nothing in this schema expires a path.

`StudyPlanPathStep` — 5 to 10 per path.
  `id`, `pathId` (relation, onDelete: Cascade), `position Int`,
  `kind String` (`"KNOWLEDGE_CHECK" | "COACHED_SESSION" | "UNAIDED_SESSION"`),
  `competencyKey String`,
  `selectionReason String @db.Text` (REQ-118: stored, not recomputed, so the
  student is shown the reason that actually drove selection),
  `knowledgeCheckId String?`, `coachedSessionId String?`,
  `status String @default("PENDING")` (`"PENDING" | "COMPLETE" | "SKIPPED"`),
  `completedAt DateTime?`.
  Unique `@@unique([pathId, position])`. The 5-10 bound is enforced in code
  (`lib/study-plan/path.ts`), NOT in SQL — note that explicitly so a reader does
  not assume the database guards it.

`CoachedSession` — REQ-113/114.
  `id`, `userId`, `pathStepId String @unique` (relation, onDelete: Cascade — a
  coached session exists ONLY as a path step, which is the schema-level half of
  REQ-113's "reachable only through a path"), `competencyKey String`,
  `replaySourceReportId String`, `replayTurnIndex Int`
  (the actual moment being reworked — replay-first is not optional, so these are
  non-null), `freshScenarioPrompt String @db.Text` (the then-fresh situation),
  `reportId String?` (the InteractionReport the session produced, once finished),
  `startedAt DateTime @default(now())`, `completedAt DateTime?`.
  Index `@@index([userId, startedAt])`.

Add the inverse relation fields on `User` and `StudyPlan`. Do NOT alter any
existing column, index, or relation on an existing model — additions only.

<objective>
Make the coached session something a student actually does: the REPLAY leg with
their own moment, technique reminders delivered during it, the transition, the
FRESH leg, and a finish that tells them their mastery moved.

Purpose: 21-23 made the coached runtime reachable over HTTP. Without this plan
there is still no screen, so "coaching that arrives DURING practice" is a claim
about an API. REQ-114 is worded as "a student can COMPLETE", and REQ-115's "every
tip actually rendered" has no rendering surface until this exists.

Two things 21-CONTEXT.md locks bind hardest here. First: normal practice sessions
are UNTOUCHED — this shell is its own component tree, and nothing under
`components/practice/` may learn about it. Second: tips name the technique and
never script the words, which in a UI means a tip is presented as a reminder in a
side rail, never as a suggested reply in or near the input the student speaks or
types into.

Output: the shell, the page a path step links to, and a surface verifier.
</objective>

  <action>
Create `components/study-plan/CoachedSessionShell.tsx`, a client component.

READ `components/practice/PracticeSessionShell.tsx` first — for its session
transport, audio/avatar wiring and finish handshake, which this shell reuses by
the same means the engine decision document authorizes. But **do not import it,
do not extend it, and do not modify it.** 21-12's isolation guard asserts nothing
under `components/practice/` knows about coached mode, and the cheapest way to
violate it is to "share" the shell. If transport logic genuinely needs to be
reused, lift the reusable piece into a NEW module under
`components/study-plan/coached/` or `lib/study-plan/coached/` and leave the
practice shell byte-identical. Record in the SUMMARY which route was taken and
confirm `git diff --name-only -- components/practice/` is empty.

Props: `{ planId: string; stepId: string }`. Everything else comes from the API.

STATE MACHINE — mirror the server's, never lead it. The shell holds
`leg: "REPLAY" | "FRESH" | "COMPLETE" | "LOADING"` taken from the server
response, and never advances it locally. 21-23's PATCH is the only thing that
moves the leg; on a 409 the response carries the current leg and the shell
resynchronizes to it. A client-side optimistic advance is how a student reaches
the fresh leg without the replay leg being recorded, which makes REQ-114 false in
the data while looking fine on screen.

1. MOUNT. `GET` the coached route. 404 → `POST` to enter. Render a brief
   "setting up your coached session" state while that resolves — entry does an S3
   read and one model call, so it is not instant. On a 409
   `ReplayMomentUnavailableError`, render the specific message and a link back to
   the study plan; do not retry in a loop.

2. REPLAY LEG. The one that must be unmistakably first.
   - A heading naming it as the replay: something like "First, let's rework what
     you actually said."
   - The student's own words from `replayMoment.text`, in a `<blockquote>` with
     `whitespace-pre-wrap`, labelled with the session it came from and a link to
     that report. Render it VERBATIM — no trim, no ellipsis, no re-casing, no
     whitespace collapsing. The verbatim guarantee survives 21-04's gate, 21-10's
     generation and 21-23's delivery; the last place it can be broken is a
     cosmetic class or a `.slice()` here. Comment that.
   - The live session area for reworking the moment, using the transport read off
     the practice shell.
   - A "Done with the replay — show me a fresh situation" control which PATCHes
     `{ action: "advance", replayReportId }`. It is the ONLY way forward.

3. TIP RAIL — this is where "coaching arrives DURING practice" becomes true.
   - Render `tips` from the server in a side rail (or a collapsible panel on
     mobile), each as its technique `name` plus its `reminder`.
   - Label the rail explicitly as technique reminders, with one line of standing
     copy stating these name a skill and are not words to say. The student should
     understand the contract, not just be subject to it.
   - Render ONLY what the server sent. The shell may NOT compose, template,
     interpolate, concatenate or fall back to a default tip string. 21-23 ran
     `assertTipSafe` over every tip; a tip assembled in the view has passed no
     gate at all. Comment it.
   - Position the rail visually SEPARATE from the student's own input/speaking
     area, and never inside it. A reminder rendered as placeholder text, a
     suggested reply, or a chip above the input reads as a line to say, which is
     the thing 21-CONTEXT.md forbids regardless of what the text says.

4. FRESH LEG. Heading naming it as the transfer test ("Now a new situation, same
   skill"), the `freshScenarioPrompt`, the same live session area, its own tips,
   and a "Finish" control PATCHing `{ action: "complete", reportId }`.
   The replay moment is NOT shown again here — the point is transfer, and showing
   it would invite repetition. A single line saying which competency is being
   exercised is enough.

5. COMPLETE. Show `contributionsWritten` as plain words: that the session has
   been scored, that it moved mastery for N competencies, and — stated once,
   honestly — that a coached session counts for less than an unaided one because
   the coach helped. That last line is REQ-116's student-visible half and it
   prevents the student over-reading the figure. Link to `/mastery` and back to
   `/reports`.

6. NOTHING ELSE. No streak, no counter of consecutive days, no lock on either
   leg beyond the server's ordering, no progress bar implying more legs exist.
   21-CONTEXT.md rules streaks and unlocking out and 21-17's guard scans this
   tree.

Accessibility: each leg a labelled `<section>` with a heading; the current leg
announced via `aria-live`; the tip rail an `<aside>` with an accessible name;
every control keyboard reachable.
  </action>
  <verify>`npm run build` succeeds. `npx tsc --noEmit` clean. `git diff --name-only -- components/practice/` is empty. `grep -ci 'streak\|consecutive\|locked\|unlock' components/study-plan/CoachedSessionShell.tsx` returns 0. `grep -c 'whitespace-pre-wrap' components/study-plan/CoachedSessionShell.tsx` returns at least 1. `grep -c 'blockquote' components/study-plan/CoachedSessionShell.tsx` returns at least 1. `grep -c 'aside' components/study-plan/CoachedSessionShell.tsx` returns at least 1.</verify>
  <done>The shell renders REPLAY first with the student's verbatim moment, a visually separate technique-reminder rail rendering only server-sent tips, a single forward control to FRESH, a FRESH leg that does not repeat the moment, and a completion state naming how many competencies moved and that coached counts for less — with the leg never advanced locally, the practice shell untouched, and no streak or lock copy anywhere.</done>

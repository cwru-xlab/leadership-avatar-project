<objective>
Generate the four knowledge-check formats from the student's own session moments,
with the verbatim-quote validator wired as a HARD GATE that discards rather than
repairs.

Purpose: this is where 21-CONTEXT.md's "content is generated from the student's
own session moments" and its first named guardrail meet. The guardrail is not
"instruct the model to quote accurately" — 21-CONTEXT.md says the quote is
"mechanically checkable against the stored transcript, and should be." 21-04 built
the check. This plan is what makes it unbypassable: generation proposes,
validation disposes, and nothing the model says about its own fidelity is
consulted.

The precedent to follow is 20-06, which proved its sanitizer with an evaluator
payload that DELIBERATELY DISOBEYED the prompt. The same technique applies here:
a stub model that paraphrases is the only honest test of a verbatim gate.

Output: `lib/study-plan/checks/generate.ts` and an adversarial battery.
</objective>

  <name>Task 1: Build the generator with a strict schema and an injectable model call</name>
  <files>lib/study-plan/checks/generate.ts</files>
  <action>
Create `lib/study-plan/checks/generate.ts`. Follow the shape of
`lib/study-plan/generate.ts`: a system prompt const, a strict JSON schema const,
an `ok: true | false` discriminated outcome, and the model name returned on both
branches. Do NOT edit `generate.ts`.

Export `CHECK_GENERATION_SCHEMA` — an OpenAI `json_schema` envelope with
`strict: true`. Follow the rules `lib/report/structured.ts` documents: every
property listed in `required`, `additionalProperties: false` everywhere, and
nullable spelled `type: ["string", "null"]`. The schema asks for an array of
candidates, each with:
- `format` (enum of the four `CHECK_FORMATS`)
- `prompt` (string)
- `payload` (one object per format — model them as a single object with all
  fields nullable and validate the format-specific subset in code, because
  `strict: true` has no discriminated-union support; say so in a comment)
- `answer_key` (object with all fields nullable)
- `quoted_text` (`["string", "null"]`) — the student's exact words, or null for a
  candidate that quotes nobody
- `source_report_id` (`["string", "null"]`)
- `quoted_turn_index` (`["integer", "null"]`)

The system prompt must: state that the quote must be reproduced character for
character from the supplied moments; state that a candidate whose quote cannot be
reproduced exactly should be omitted rather than approximated; and require that
`REWRITE_WEAK_LINE`'s `weakLine` and `PICK_BETTER_RESPONSE`'s first candidate BE
the student's verbatim line. Add a comment stating plainly that this prompt is
advisory only and the gate in Task 1 step 5 is the guarantee — so nobody later
reads a strong prompt and concludes the gate is redundant.

```ts
export async function generateChecksForCompetency(args: {
  userId: string;
  studyPlanId: string;
  competencyKey: CompetencyKey;
  selfNames: string[];
  moments: SessionMoment[];
  momentOwnerUserIds: string[];
  transcriptsByReportId: ReadonlyMap<string, InterviewTranscript>;
  desiredCount: number;
  /** Injected for testing. Defaults to the real OpenAI call. */
  callModel?: (payload: unknown) => Promise<unknown>;
}): Promise<GenerationOutcome>
```

`callModel` injectable is what lets the battery run a deliberately-disobedient
stub with no API key. Make it a parameter, not a module-level mock hook.

WHERE THESE INPUTS COME FROM: `moments`, `momentOwnerUserIds`,
`transcriptsByReportId` and `selfNames` are assembled by
`loadGenerationSources(userId, reportIds)` in `lib/study-plan/checks/sources.ts`
(21-25), which owns the report query, the S3 transcript fetch, the
`StructuredReport` load and the `selfNames` lookup with ownership in every WHERE
clause. This module does NONE of that — keep it a pure consumer of its arguments
so its adversarial battery stays credential-free and database-free. Do not add a
convenience overload that fetches its own sources; that overload is how the
ownership scoping gets bypassed. 21-25's battery includes a compile-time check
pinning its output to this signature, so a rename here must be made in both
places deliberately.

Pipeline, in this order:

1. `prepareMomentsForGeneration({ requestingUserId: userId, moments,
   momentOwnerUserIds, selfNames })`. This is the ONLY way transcript text may
   reach the model (REQ-109 / 21-07). Do not assemble a prompt from
   `args.moments` directly — add a comment saying so, since the raw array is
   right there and bypassing the boundary would be a one-line mistake.
2. Build the request with the prepared payload plus the competency's label and
   description from `COMPETENCIES`, and the linked growth-area titles the moments
   carry. Nothing else.
3. Call `callModel`. On throw or malformed JSON, return `{ ok: false, reason }` —
   never a partial list.
4. Validate each candidate's `payload` and `answer_key` through
   `validateCheckPayload` / `validateAnswerKey` (21-06). A candidate that throws
   is DISCARDED with its reason recorded, not repaired.
5. THE GATE. For every candidate with a non-null `quoted_text`:
   - require `source_report_id` to be a key of `transcriptsByReportId`; discard
     otherwise (the model naming a report it was not given is fabrication);
   - call `validateVerbatimQuote(quoted_text, transcript, { expectedTurnIndex:
     quoted_turn_index ?? undefined })`;
   - on `ok: false`, DISCARD the candidate and record the reject reason. Do NOT
     re-prompt, do not trim, do not fall back to a fuzzy match, do not substitute
     the nearest real turn. Each of those is a plausible "fix" that converts the
     guarantee into a lie; name all four in a comment as forbidden.
   - Additionally, for `REWRITE_WEAK_LINE` require `payload.weakLine ===
     quoted_text`, and for `PICK_BETTER_RESPONSE` require
     `payload.candidates[0] === quoted_text`. The quote must be the thing the
     student is working on, not decoration elsewhere in the question.
   - A candidate whose format is `REWRITE_WEAK_LINE` or `PICK_BETTER_RESPONSE`
     and whose `quoted_text` is NULL is discarded: both formats are defined by
     reworking the student's own line, so an unquoted one is a generic question
     from the authored bank the Deferred list rejects.
6. Persist survivors with `prisma.knowledgeCheck.createMany`, writing
   `quotedText`, `quotedTurnIndex`, `sourceReportId`, `competencyKey`,
   `studyPlanId`, `generationModel`.
7. Return `{ ok: true, created: n, discarded: DiscardRecord[], model }` where
   `DiscardRecord` carries the candidate index, the stage it died at, and the
   reason. If `created === 0`, return `{ ok: false, reason: "no candidate
   survived validation", discarded }` — a zero-survivor run must be a failure the
   caller sees, because 21-14 will otherwise build a path step pointing at
   nothing.

  <files>scripts/verify-check-generation.ts</files>
  <action>
Create `scripts/verify-check-generation.ts` in the house `check()` style. Follow
20-06's technique: the stub model DELIBERATELY DISOBEYS the prompt. A battery
whose stub behaves well proves only that the happy path compiles.

Build a fixture `InterviewTranscript` with several user turns, including one
distinctive line, plus a matching `StructuredReport` with growth areas whose
timecodes line up. Derive moments via `extractSessionMoments` (21-04) so the
battery exercises the real extraction rather than hand-built moments.

Run `generateChecksForCompetency` with `callModel` stubs, asserting the outcome
each time:

1. OBEDIENT STUB — returns four candidates, one per format, each quoting a real
   turn exactly, with correct `source_report_id` and `quoted_turn_index`. Assert
   `ok: true`, `created: 4`, `discarded: []`, and that each persisted row's
   `quotedText` re-validates against the transcript.
2. PARAPHRASE STUB — quotes the distinctive line with one comma removed. Assert
   that candidate is discarded with `NOT_FOUND_IN_ANY_TURN`, and — critically —
   that the persisted row count does not include it and that NO row was written
   with the paraphrase. This is the central assertion of the whole plan.
3. TIDIED-GRAMMAR STUB — "I would" for the stored "I'd". Discarded.
4. ASSISTANT-QUOTE STUB — quotes the avatar's turn and attributes it to the
   student. Discarded with `FOUND_ONLY_IN_ASSISTANT_TURN`.
5. SPLICE STUB — concatenates the end of one user turn and the start of another.
   Discarded with `SPANS_MULTIPLE_TURNS`.
6. WRONG-REPORT STUB — supplies a `source_report_id` not present in
   `transcriptsByReportId`. Discarded before any transcript lookup.
7. TURN-INDEX-LIE STUB — exact quote, wrong `quoted_turn_index`. Discarded with
   `TURN_INDEX_MISMATCH`. A question that points the student at the wrong moment
   is still a misquote of their session.
8. DECORATION STUB — `REWRITE_WEAK_LINE` whose `quoted_text` is a real turn but
   whose `payload.weakLine` is a different, invented sentence. Discarded. This is
   the subtle one: the quote validates, and the question still misrepresents.
9. UNQUOTED-REWRITE STUB — `REWRITE_WEAK_LINE` with `quoted_text: null`.
   Discarded.
10. MALFORMED-PAYLOAD STUB — `MULTIPLE_CHOICE` with three options. Discarded at
    the payload stage, with `discarded[0].stage` naming the payload stage rather
    than the quote stage, so the two gates are distinguishable in diagnostics.
11. ALL-BAD STUB — every candidate fails. Assert `ok: false`, zero rows written,
    and that `discarded` has one record per candidate.
12. THROWING STUB and INVALID-JSON STUB — assert `ok: false` with no partial
    write in either case.
13. BOUNDARY STUB — a stub that echoes back whatever it was SENT. Assert the sent
    payload contains no email, URL, phone number, or the student's own name, by
    seeding one of the fixture turns with each. This closes the loop on 21-07
    from the caller's side: the boundary is not just available, it is on the path.

Persistence: run with a live local `DATABASE_URL` if available; otherwise inject a
capturing fake for the `createMany` call so every assertion about what WAS and
WAS NOT written still holds. Print an explicit SKIP line for any assertion that
genuinely requires the database. Never let an unavailable database turn a
write-assertion into a silent pass.

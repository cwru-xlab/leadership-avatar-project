<objective>
Make a normal practice session move mastery, and put the report-to-competency
mapping in one place so live and coached ingestion cannot diverge.

Purpose: 21-CONTEXT.md locks it outright — "Both live sessions and knowledge
checks move mastery. Mastery is not live-session-only." 21-05 declares
`LIVE_SESSION: 1.00` as the anchor the entire weight table is calibrated against.
But without this plan NOTHING ever writes a `LIVE_SESSION` row: 21-16 writes
`COACHED_SESSION`, 21-11 writes check rows, and no plan touches the path a
finished session takes. The result would be `/mastery` reading "Not yet measured"
for a student who has done ten sessions — the single most visible possible
failure of the phase, and the one that makes REQ-107 false while every verifier
passes.

Second purpose: 21-16 originally restated the map-up arithmetic. Two copies of
`competencyForDimension` + `(score-1)/4` + null-skip will drift, and the moment
they do, coached and live contributions stop being comparable — which is exactly
what the locked weight ORDERING depends on. REQ-124 makes one copy a requirement.
This plan owns that module; 21-16 imports it.

Output: `lib/mastery/from-report.ts`, one additive call site in
`lib/engine/evaluation-runner.ts`, and a battery.
</objective>

```ts
export interface ReportMappingResult {
  inputs: ContributionInput[];
  /** Dimensions skipped because the score was null. Reported, never zeroed. */
  nullDimensions: string[];
  /** Dimension keys with no competency in the catalog. Non-empty = a data bug. */
  unmappedDimensions: string[];
}

export async function contributionsFromReport(args: {
  userId: string;
  reportId: string;
  source: ContributionSource;
  occurredAt: Date;
}): Promise<ReportMappingResult>
```

Steps:
1. Load the `InteractionReport` scoped by BOTH `id` and `userId` in the WHERE
   clause. Throw if absent. Read `scores` through `asScoreMap` from
   `lib/report/snapshot.ts` — the existing accessor, not a fresh JSON cast; the
   accessor is where the shape is already known to be handled.
2. For each scored dimension key, resolve its competency via
   `competencyForDimension` (21-02). A key with no competency goes into
   `unmappedDimensions` and is SKIPPED — never defaulted into a competency,
   because a wrong attribution is worse than a missing one and 21-09 already
   surfaces `unmappedRowCount` so the disagreement is visible.
3. SKIP null scores rather than treating them as 0, and record the key in
   `nullDimensions`. A `visual` score of null means camera off or insufficient
   data (Phase 10's `visualUnscoredReason`), not a visual failure. Zeroing it
   would punish a student for not having a camera. This is the same
   null-is-not-zero rule 21-09 enforces on the read side, applied on the write
   side.
4. Group by competency. `rawScore` = the mean of that competency's dimensions'
   normalized scores. A competency whose every mapped dimension is null yields NO
   input at all — not a zero-score input. Say so in a comment; the difference
   between "no evidence" and "evidence of failure" is the whole point of REQ-105's
   thinness flag.
5. `occurredAt` comes from the ARGUMENT, not from the clock and not from
   `createdAt`. 21-05's `readContributions` windows on `occurredAt`, so a session
   evaluated late must still land in the window it actually happened in. The live
   caller passes the report's `startedAt`; the coached caller passes
   `completedAt`.
6. Set `sourceReportId: reportId` and `sourceAttemptId: null`.

Then export the live writer:

  `reportId`, return `{ written: 0, skipped: "coached-session" }` immediately:

```ts

// mastery, weighted below unaided practice" (21-05's
// WEIGHT_ORDERING_CONSTRAINTS: LIVE_SESSION 1.00 > COACHED_SESSION 0.40).
//
// A coached session's report goes through evaluation-runner's READY+scores
// update exactly like an unaided one, so this hook WILL fire on it. 21-16
// already writes that report's COACHED_SESSION row at 0.40. Without this skip
// the same session contributes 1.00 + 0.40 = 1.40 and OUTWEIGHS an unaided
// session's 1.00 — inverting the locked ordering in /mastery, the phase's
// headline output.
//
// The "already-ingested" guard below does NOT cover this: it keys on
// sourceReportId AND source "LIVE_SESSION", so a pre-existing COACHED_SESSION
// row for the same report does not suppress it. This is a separate, earlier,
// UNCONDITIONAL check, not a fallback.
const coached = await prisma.coachedSession.findFirst({
  where: { reportId },
  select: { id: true },
});
if (coached) {
  console.info("Mastery live ingestion skipped: coached session", {
    reportId,
    coachedSessionId: coached.id,
  });
  return { written: 0, skipped: "coached-session" };
}
```

- Does NOT swallow its own errors. The CALLER decides what a failure means; see

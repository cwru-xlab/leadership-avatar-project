```ts
export interface CompetencyMastery {
  competencyKey: CompetencyKey;
  /** 0..100, rounded to one decimal. null when no contribution exists. */
  lifetimePercent: number | null;
  currentPercent: number | null;
  lifetimeEvidenceCount: number;
  currentEvidenceCount: number;
  /** Weighted-evidence totals, carried so 21-13 can judge thinness without recomputing. */
  lifetimeWeightSum: number;
  currentWeightSum: number;
  /** Most recent contributing occurredAt, or null. */
  lastContributionAt: Date | null;
}

export interface MasteryResult {
  competencies: CompetencyMastery[];
  overallLifetimePercent: number | null;
  overallCurrentPercent: number | null;
  /** The window boundary actually used, echoed so a caller can label it. */
  windowStart: Date;
  windowDays: number;
  /**
   * Rows whose competencyKey is not in COMPETENCIES. Counted, never silently
   * dropped — a non-zero value means the catalog and the ledger disagree, which
   * is a data bug a reader must be able to see. 21-13's MasteryDTO and 21-18's
   * surface both consume this field, so it is part of the contract, not debug
   * output.
   */
  unmappedRowCount: number;
}

export function computeMastery(
  contributions: ReadonlyArray<MasteryContributionRow>,
  now: Date,
  opts?: { windowDays?: number },
): MasteryResult
```

`now` is a REQUIRED parameter, not read from the clock inside. That is what makes
the function testable and deterministic; a `new Date()` inside would make every
test time-dependent and every figure unreproducible. State that in a comment.

Rules:

- Figure per competency = weighted mean of `rawScore` using each row's SNAPSHOTTED
  `weight`: `sum(rawScore * weight) / sum(weight)`, scaled to 0..100 and rounded
  to one decimal. Use the row's stored `weight`, NEVER `weightForSource` — 21-05
  snapshots it precisely so a retune does not rewrite history.
- A row maps to a competency via `competencyForDimension` on whatever dimension
  produced it. Contributions arrive already carrying `competencyKey` (21-05's
  ledger writes it), so this function does NOT re-map; it groups by
  `competencyKey` and ignores a key not in `COMPETENCIES`, counting the ignored
  rows and exposing the count as `unmappedRowCount` on the result. Silently
  dropping them would make a figure quietly wrong after a catalog replacement.
- Lifetime = all supplied rows. Current = rows with
  `occurredAt >= windowStart`, where `windowStart = now - (opts?.windowDays ??
  MASTERY_WINDOW_DAYS) days`. Inclusive on the boundary — state the choice,
  because the edge case is otherwise decided by accident.
- Reversed rows are NOT filtered here. The ledger's `readContributions` already
  excludes them by default (21-05), and filtering in two places means a future
  change to one leaves the other wrong. Add an assertion-style comment and, if
  any supplied row has a non-null `reversedAt`, THROW — a reversed row reaching
  this function is a caller bug, and a thrown error is better than a figure that
  includes a mark the student successfully contested.
- Empty competency → `lifetimePercent: null`, counts 0, `lastContributionAt: null`.
  NOT 0. Zero is a measured failure; null is "we have not measured this." The
  whole thinness story in REQ-105 depends on the distinction surviving.
- `overallLifetimePercent` = the mean of the NON-NULL `lifetimePercent` values,
  each competency counting ONCE regardless of how much evidence it has. State the
  rule and why: a mean over raw contributions would let a student who did twelve
  deck pitches have their overall figure dominated by deck competencies, which
  is the per-type silo view 21-CONTEXT.md rejects. One figure per competency
  keeps it a cross-type view. Null when every competency is null.
- `overallCurrentPercent` the same, over `currentPercent`.

Cases to write as RED tests:
- Empty array → every competency null, both overalls null, `windowStart` =
  `now - 30 days`.
- One contribution to one competency → that competency's lifetime equals its
  rawScore×100; every other competency null; overall equals that one figure (mean
  of one).
- Two contributions, same competency, `rawScore` 0.4 weight 1.0 and `rawScore`
  0.8 weight 0.2 → lifetime = (0.4 + 0.16)/1.2 = 0.4667 → 46.7. This asserts the
  weight actually biases the mean and is not averaged flat.
- Row exactly on `windowStart` → included in current. Row one millisecond before
  → excluded, and lifetime still includes it. This is the pair that proves the
  two figures genuinely differ.
- A competency with only old rows → non-null lifetime, NULL current. The student
  has evidence but no recent form; collapsing this to 0 would tell them they got
  worse when they simply stopped practising.
- Determinism: call twice with the same inputs and a shuffled copy of the array
  → deep-equal results. Array order must not matter.
- Overall independence from volume: competency A with 10 rows at 0.3 and
  competency B with 1 row at 0.9 → overall is 60.0, not pulled toward 0.3.
- A row with `competencyKey: "__gone__"` → counted in `unmappedRowCount`, not
  included in any figure.
- A row with non-null `reversedAt` → throws.

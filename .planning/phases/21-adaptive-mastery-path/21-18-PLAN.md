<objective>
Surface mastery: one overall percentage, a per-competency breakdown, and both
figures per competency with labels that make the distinction unmistakable.

Purpose: 21-CONTEXT.md locks the presentation shape — "an overall figure and a
per-competency figure, the shape fizzylemon uses" — and flags the specific risk
for the dual figures: "Two figures for the same competency — labelling must make
the distinction obvious or it will confuse." It also locks that thinness is SHOWN
rather than withheld. 21-13 computed all of that and attached the disclosure copy
to each tier; this plan's job is to render it without dropping any of it.

The one thing this plan must not do is compute. Every number, tier, label,
disclosure, level and goal figure comes from the DTO. A component that computes a
tier is a second source of truth and will disagree.

Output: a GET route, a panel component, a page, and a surface verifier.
</objective>

Create `app/api/mastery/route.ts`, following `app/api/study-plans/route.ts`
exactly for auth and response conventions: `export const runtime = "nodejs"`, a
local `response()` helper setting `Cache-Control: no-store`, `getCurrentUser` from
the `siteConfig.auth.cookie.name` cookie, 401 on no user.

`GET`:
1. `readContributions(currentUser.id)` — default `includeReversed: false`, so a
   contested mark is already excluded without this route deciding anything.
2. `computeMastery(contributions, new Date())`. The clock read happens HERE, at
   the edge, which is why 21-09 made `now` a parameter.
3. `toMasteryDTO(result)`. This is the ONLY serialization. Add a comment citing
   21-13's single-exit rule and 20-06's finding that a guarantee applied after
   serialization has already shipped the unsafe value.
4. Attach the derived extras the DTO does not own:
   - per-competency `level` via `levelFor({ percent: c.current.percent, tier:
     c.current.tier })` AND a separate `lifetimeLevel` from the lifetime figure.
     Level the CURRENT figure as the primary — a level is a claim about where the
     student is now. Say so in a comment, since levelling the lifetime figure
     would be the easier-looking choice and would show a student a level they no
     longer hold.
   - `goals: goalProgress({ contributions, now, timeZone })`, with `timeZone` read
     from the `x-timezone` request header if present, falling back to
     `"America/New_York"` (Weatherhead's zone) and echoing the zone used in the
     response so the client can show it. Do NOT fall back to UTC: a UTC day
     boundary is wrong for every student in this cohort, and silently wrong is
     worse than a declared default.
5. Return 200 with `{ mastery, goals, timeZone }`.
6. 500 with a generic body and a `console.error` of the real error. Never return
   a Prisma or stack body.

Do NOT add POST, PUT or DELETE. Mastery is derived; there is nothing to write
here. Note it.

<task type="auto">
  <name>Task 2: Build the mastery panel and page</name>
  <files>components/mastery/MasteryPanel.tsx, app/mastery/page.tsx</files>
  <action>
Create `components/mastery/MasteryPanel.tsx`. Match the Tailwind conventions and
card/panel idiom already used in `app/reports/page.tsx` — read it and follow it
rather than introducing a new visual language.

Layout:

1. HEADER — the overall figure. Show `overall.currentPercent` large, labelled
   `"Recent form (last {window.days} days)"`, with `overall.lifetimePercent`
   beside it at smaller weight labelled `"All time"`. Both labelled; neither
   rendered as a bare number. When both are null, show `"No mastery measured
   yet"` and a one-line explanation that completing a session or a knowledge
   check will start it — never `0%`.

2. GOALS — a compact row: `"Today: {daily.completed} of {daily.target}"` and
   `"This week: {weekly.completed} of {weekly.target}"`, with a met indicator.
   No streak element, no chain, no "don't lose your progress" copy. 21-17's guard
   scans this file, so any such copy will fail the build-adjacent verifier.

3. BREAKDOWN — one row per competency, in `order`, EVERY competency including
   unmeasured ones. Per row:
   - competency `label` and, on a second line or a tooltip, its `description`
   - TWO figures, each with its own visible text label — `"All time"` and
     `"Recent"`. Do NOT distinguish them by position, colour, size or icon alone.
     21-CONTEXT.md names the confusion risk specifically; a label is the only
     thing that survives a screenshot, a colourblind reader and a narrow viewport.
   - the level `name` for the current figure, with a `"provisional"` marker when
     `levelFor` returned `provisional: true`, and `"Next level at {n}%"` when
     `nextLevelAtPercent` is non-null
   - the tier `disclosure` text rendered INLINE next to the figure it qualifies,
     not in a footnote, whenever it is non-null. Render BOTH the lifetime and the
     current disclosure when both are non-null and they differ; show one when they
     are identical.
   - for a null percent: the words from `TIER_DISCLOSURE.NONE` — `"Not yet
     measured"` — and NOT `0%`, not `—`, not an empty cell. A dash is read as
     zero by someone scanning a column.

4. UNMAPPED — when `unmappedRowCount > 0`, a small note that some recorded
   evidence does not map to the current competency set. Do not hide it; it means
   the catalog and the ledger disagree, and a student seeing a figure that does
   not reconcile deserves the note.

Accessibility: each competency row is a `<li>` in a `<ul>`; the two figures use
`<dl>`/`<dt>`/`<dd>` so the label-value pairing is programmatic and not purely
visual. The overall figure has an `aria-label` spelling out both numbers and
their window.

The component takes the API payload as a prop and performs NO computation — no
threshold comparison, no percentage arithmetic, no tier derivation. Add a comment
saying so and naming 21-13's single-exit rule.

NAVIGATION (REQ-106's reachability half — do NOT skip this). Add ONE entry to
`siteConfig.studentNavItems` in `config/site.ts`:
`{ label: "Mastery", href: "/mastery", icon: "ChartColumnBig" }`, placed between
the existing `My Reports` and `Settings` entries. `ChartColumnBig` is already in
`components/auth-navbar.tsx`'s `iconMap`, so no navbar change is needed — verify
that before choosing a different icon, because an icon name missing from the map

`navItems` (the admin list), and do not reorder or relabel an existing entry.
Without this, a student cannot find the page at all and REQ-106's reachability
condition fails even though the page renders perfectly.

Create `app/mastery/page.tsx`: authenticated page following the pattern of
`app/reports/page.tsx` (same auth guard and shell), fetching `/api/mastery` and
rendering `MasteryPanel`. Handle three states explicitly — loading, error (with a
retry affordance), and loaded-but-empty. The empty state is the common case for a
new student and must read as a starting point, not a failure.
  </action>

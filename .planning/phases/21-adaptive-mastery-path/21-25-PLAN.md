<objective>
Build the one thing that turns a user and a set of report ids into
`generateChecksForCompetency`'s inputs — ownership-scoped, injectable, and
testable without a route.

Purpose: `generateChecksForCompetency` (21-10) requires `moments`,
`momentOwnerUserIds`, `transcriptsByReportId` and `selfNames`. 21-04 deliberately
keeps S3 out of `extractSessionMoments` so its adversarial battery runs
credential-free. 21-07 deliberately takes `momentOwnerUserIds` as an ARGUMENT so
the privacy boundary is checkable. Both choices are right, and both mean
something else must do the report query, the S3 transcript fetch, the
`StructuredReport` load and the `selfNames` lookup.

have usable moments" with no mechanism, no file and no verification step — which
left the single integration point of the entire check-generation chain to be
improvised inside a route with a 60s `maxDuration`, including the S3 fan-out and
the ownership scoping that 21-07's whole privacy contract rests on. REQ-123 now
makes one named assembler a requirement.

Output: `lib/study-plan/checks/sources.ts` and a battery that needs no
credentials.
</objective>

Open with a block comment stating what this module is for: it is the ONLY place
the four inputs `generateChecksForCompetency` needs are assembled, and the reason
it exists as its own module rather than inside a route is REQ-123 — ownership
scoping and S3 fan-out improvised per-caller is how a privacy boundary fails
quietly. Name 21-07's `prepareMomentsForGeneration` as the consumer of
`momentOwnerUserIds` whose contract this module satisfies BY CONSTRUCTION.

Note the import direction: this file is under `lib/study-plan/checks/`, where
21-06's engine-import guard is ABSOLUTE with no carve-out. Import nothing from
`lib/engine/`. The S3 transcript accessor and `StructuredReport` loader live
outside `lib/engine/` — find and use the existing ones (read how
`lib/report/handlers.ts` and `lib/report/structured.ts` do it) rather than
writing new ones. If the only available accessor IS under `lib/engine/`, stop and
record the conflict in the SUMMARY rather than adding a second carve-out to
21-06's guard; the right resolution is lifting the accessor, not weakening the

```ts
export const SOURCE_LIMITS = {
  /** Reports read per assembly. PROVISIONAL UNTIL CALIBRATED. */
  maxReports: 8,
  /** Moments kept per competency. PROVISIONAL UNTIL CALIBRATED. */
  maxMomentsPerCompetency: 12,
} as const;

export interface GenerationSources {
  /** Exactly 21-10's `moments` input. */
  moments: SessionMoment[];
  /** Exactly 21-10's `momentOwnerUserIds`, index-aligned with `moments`. */
  momentOwnerUserIds: string[];
  /** Exactly 21-10's `transcriptsByReportId`. */
  transcriptsByReportId: ReadonlyMap<string, InterviewTranscript>;
  /** Exactly 21-10's `selfNames`. */
  selfNames: string[];
  /**
   * The pre-check index 21-19's POST uses INSTEAD of generating and discarding.
   * A competency absent from this map has no usable moment.
   */
  momentsByCompetency: ReadonlyMap<CompetencyKey, SessionMoment[]>;
  /** Reports dropped, with the reason. Reported, never silent. */
  degradedReports: Array<{ reportId: string; reason: string }>;
}

export async function loadGenerationSources(
  requestingUserId: string,
  reportIds: string[],
  opts?: {
    /** Injected for testing. Defaults to the real transcript accessor. */
    readTranscript?: (userId: string, reportId: string, key: string) => Promise<InterviewTranscript>;
  },
): Promise<GenerationSources>
```

Implementation, in this order:

1. OWNERSHIP IN THE WHERE CLAUSE, not after.
   `prisma.interactionReport.findMany({ where: { id: { in: reportIds },
   userId: requestingUserId, status: "READY" } })`, capped at
   `SOURCE_LIMITS.maxReports`, most recent first. Both halves matter: `userId`
   in the WHERE is what makes it IMPOSSIBLE for a foreign report to reach the
   result, and `status: "READY"` is what keeps an unscored or failed report from
   contributing moments with no growth areas behind them.
   Then, as a belt-and-braces assertion rather than a filter, assert every
   returned row's `userId === requestingUserId` and THROW if not. A post-filter
   would hide a query bug; an assertion surfaces it. Comment the distinction.
   Ids in `reportIds` that do not come back are silently absent — that is
   correct: a student passing someone else's report id must get nothing, not an
   error that confirms the id exists.

2. `selfNames`. `prisma.user.findUnique({ where: { id: requestingUserId } })` and
   build the array from the name fields the schema actually has (read the User
   model; do not guess at field names). Include every distinct non-empty variant:
   full name, first name, any preferred/display name. Deduplicate
   case-insensitively and drop entries shorter than 2 characters — a one-letter
   "name" would redact every occurrence of that letter and destroy the
   transcript. Return `[]` when the user has no name set; 21-07's redaction must
   handle an empty list, and asserting that is cheaper than special-casing it
   here.

3. TRANSCRIPTS. For each report with a `transcriptKey`, call
   `opts?.readTranscript ?? <the real accessor>`. Do them with a bounded
   concurrency (4) rather than a serial loop or an unbounded `Promise.all` — this
   runs inside a route with a 60s budget, and eight serial S3 round trips is the
   difference between a fast request and a timeout, while unbounded fan-out is
   how a larger `maxReports` later takes down the request.
   A report whose transcript is missing, unreadable, or whose read throws goes
   into `degradedReports` with the reason and is EXCLUDED from `moments` and from
   `transcriptsByReportId`. Do NOT fail the whole assembly: one unreadable
   transcript out of eight should cost one report's worth of moments, not the
   student's entire path. Comment that.
   A report with no `transcriptKey` at all is degraded with reason
   `"no-transcript-key"` — it is a pre-transcript-era or scenario-shaped report
   and has no turns to quote.

4. STRUCTURED REPORTS. Load each surviving report's `StructuredReport` through
   the existing loader. A report whose structured form is absent or invalid is
   degraded with its reason, same as above — `extractSessionMoments` needs the
   growth areas, and inventing them would be exactly the generic content
   21-CONTEXT.md rejects.

5. MOMENTS. Call `extractSessionMoments(transcript, structuredReport, reportId)`
   (21-04) per surviving report and concatenate. Build `momentOwnerUserIds` in
   the SAME loop, pushing `requestingUserId` per moment so the two arrays are
   index-aligned by construction — do not build it afterwards with a `.map()`
   over a possibly-reordered array. Assert
   `moments.length === momentOwnerUserIds.length` before returning and throw
   otherwise. 21-07 compares these index-wise and a misalignment would make its
   ownership check pass while attributing the wrong owner.

6. `momentsByCompetency`. Group moments by the competency their report's growth
   areas implicate, using the same `competencyForDimension` catalog (21-02) — go
   through the report's scored dimensions and growth areas, not through a fresh
   judgement about the text. Cap each competency's list at
   `SOURCE_LIMITS.maxMomentsPerCompetency`, keeping the most recent. A competency
   with zero moments is ABSENT from the map rather than present with an empty
   array: 21-19's pre-check reads absence as "unavailable", and an empty array
   present in the map would read as available and send it to the generator
   anyway.

7. Return. This module does NOT call `prepareMomentsForGeneration` and does NOT
   call the model. 21-10 owns both. Keeping the boundary means this module is
   fully testable with no API key, and 21-07's boundary remains the single
   redaction point rather than being applied twice with different arguments.
   State both absences as deliberate.

  `SOURCE_LIMITS.maxMomentsPerCompetency` retained, and assert the retained set

  keeps the oldest moments would quietly generate checks about behaviour the
  student has already changed.
- `selfNames`: a user with a one-character name contributes nothing; duplicate
  casings collapse to one entry; a user with no name yields `[]` and the
  assembler still returns.

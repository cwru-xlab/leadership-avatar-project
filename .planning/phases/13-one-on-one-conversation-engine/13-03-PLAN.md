<task type="auto">
  <name>Task 1: terminationPolicy — avatar-initiated end with a recorded reason</name>
  <files>lib/engine/termination.ts</files>
  <action>
Read `lib/interview/turn-control.ts` first. It already defines the mechanism to
extend: the model emits a trailing `<interview-turn kind="..." />` marker that
`parseInterviewTurn` strips and interprets. Build termination on the SAME
marker-and-tail-block machinery rather than a second mechanism.

Create `lib/engine/termination.ts`:
- `parseTerminationMarker(assistantText)` → `{ cleanedText, termination: { reason: string } | null }`.
  Parse a trailing engine marker carrying a termination intent plus a `reason`
  attribute (pick one concrete marker syntax, document it in the file header, and
  state that the type's live system prompt is what instructs the model to emit it
  — the marker's instruction text itself is session-constant, so it does not
  threaten the prefix cache). Strip the marker from the text the student sees,
  exactly as `parseInterviewTurn` strips today's marker.
- `resolveTermination({ policy, source, reason })` → a discriminated result:
  - `source: "student"` is accepted iff `policy.studentMayEnd`.
  - `source: "avatar"` is accepted iff `policy.avatarMayEnd` AND the reason is one
    of `policy.avatarEndReasons` (an unrecognized reason is REJECTED, not stored —
    the model must not be able to invent a reason vocabulary).
  - A rejected avatar termination returns `{ ok: false }` and the session
    continues. This is what keeps today's interview and case-study behavior
    unchanged: both types ship with `avatarMayEnd: false`, so the marker can never
    end a session in this phase even if a model emits one.
- Return a `recordedReason: string | null` suitable for writing straight into
  `InteractionReport.terminationReason`.
Pure functions only — no I/O, no Prisma, no fetch.
  </action>
  <verify>`npx tsc --noEmit` clean; the assertions added in Task 3 cover this module.</verify>
  <done>An avatar-initiated end is expressible, policy-gated, and produces a reason string; with `avatarMayEnd: false` (both of today's types) it is structurally impossible for a model marker to end a session.</done>
</task>

<task type="auto">
  <name>Task 2: visible-context slice, outcome record, and time budget</name>
  <files>lib/engine/visible-context.ts, lib/engine/outcome.ts, lib/engine/time-budget.ts</files>
  <action>
`lib/engine/visible-context.ts` — `applyVisibleContext(config, sessionState, turn)`
returning only the portion of session state the type permits the avatar to see on
this turn. Model session state as an opaque keyed record of context channels
(e.g. `{ transcriptWindow, instanceBackground, studentArtifacts }`) and let
`VisibleContextConfig` express per-channel admission, including a "progressively
revealed" mode where a channel's entries are admitted only up to a cursor the
session reports. Default for both of today's types: admit everything, so behavior
is unchanged. Zero slide/deck vocabulary in this file. Document that Phase 14's
"the avatar must not reference slide 10 while the student is on slide 4" is this
primitive with a cursor, not a new feature.

`lib/engine/outcome.ts` — `validateOutcome(config, produced)` returning
`{ ok: true; outcome: Record<string, unknown> } | { ok: false; errors: string[] }`.
Validate the produced record against the type's `OutcomeRecordConfig` field
declarations: unknown keys rejected, declared-kind mismatches rejected, missing
optional fields allowed. A type that declares no outcome fields accepts only an
empty record. The output is what gets written to `InteractionReport.outcome`.

`lib/engine/time-budget.ts` —
- `computeTimeBudgetState({ config, startedAt, now })` → `{ elapsedSeconds, remainingSeconds: number | null, warn: boolean, expired: boolean }`.
  `remainingSeconds` is `null` when the type declares no total (today's
  `case-study`), and nothing may fabricate one.
- `buildTimeBudgetFragment(state)` → the short natural-language fragment that gets
  APPENDED TO THE LATEST USER MESSAGE's tail block, in the same style as
  `buildProgressBlock`. Add a header comment stating plainly: this string must
  never be concatenated into a system prompt, with the REQ-73 reason.
- Take `now` as an argument rather than calling `Date.now()` internally, so the
  function is pure and testable.
  </action>
  <verify>`npx tsc --noEmit` clean. `grep -in "slide\|deck" lib/engine/visible-context.ts` returns nothing.</verify>
  <done>All three modules exist as pure functions; the time-budget fragment is tail-block-only by construction and documentation; the visible-context slice contains no deck-specific vocabulary.</done>
</task>

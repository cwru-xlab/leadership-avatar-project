    scenario report page therefore offers a "check again" instead of a retry. Gate

    engine list route must support a type filter and the caller must keep requesting
    exactly today's set, so the page renders identically. CONTEXT.md leaves
    cross-type presentation to discretion; the discretion is being exercised as
    "preserve today's behavior in Phase 13," because REQ-69 is the stronger
    constraint and surfacing scenario reports for the first time is a visible
    product change that belongs to a phase that owns it.
  - **404/401 semantics differ per surface.** Interview's report page distinguishes
    401-needs-login from 404; scenario's does not. That difference lives in the
    PAGES (plan 13-12), but this route must keep returning the status codes each
    page's current logic depends on: the same 401 for unauthenticated and the same
    404 for not-found/not-owned that both current routes return. Do not introduce
    403.
  - The list route still EXCLUDES `IN_PROGRESS`, as `app/api/interview/reports/route.ts`
    does today.

  (Phase 6 criterion, still binding). Use an ownership-scoped `findFirst({id, userId})`.
- Reads come from `InteractionReport` only. Do NOT add a fallback read of the legacy
  tables — that is exactly the "legacy read path forever" option CONTEXT.md
  rejected. Backfilled rows are why it is not needed.
- Do not touch the report PAGES in this plan (`app/interview/[type]/report/...`,
  `app/case-play/[caseId]/report/...`). Plan 13-12 owns them.

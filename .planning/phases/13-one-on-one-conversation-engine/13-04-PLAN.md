<non_negotiables>
- **The shared Lightsail DB is off limits (REQ-67).** `.env` is a symlink to
  `.env.local`; `DATABASE_URL` there is the SHARED database. Every command in this
  plan passes the local URL inline:
  `DATABASE_URL="postgresql://ajabreu79@localhost:5432/leadership_avatar_dev" npx tsx scripts/...`
  Never run `npm run setup`. Never run `prisma migrate deploy`. If any command in
  this plan would touch the shared DB, stop and report instead.
- The backfill is a TypeScript script, NOT inline `INSERT ... SELECT` SQL in a
  Prisma migration. Prisma migrations are forward-only SQL with no room for the
  conditional null-preservation logic below, and REQ-67 requires a human to read
  the SQL — a short additive `CREATE TABLE` is reviewable, a data-rewriting SQL
  blob is not.
- **Preserve `cameraMode === null` exactly.** A row with null `cameraMode` is a
  pre-Phase-10 row; REQ-48 guarantees legacy reports never change. A backfill that
  defaults null to `"OFF"` "to be safe" silently alters how 06-08/10-era rows
  render their unscored-reason text. Same for both `*UnscoredReason` columns.
- Carry `id` forward unchanged. Old deep links resolve by report id; a regenerated
  id breaks every REQ-66 URL.
- `ScenarioReport` rows get `typeSlug = "case-study"` — the slug locked in 13-01.
  This value becomes permanent history; it must match the engine registry exactly.
- `caseId` goes into `inputSnapshot` as a bare string. No foreign key (HANDOFF.md §3).
</non_negotiables>

<task type="auto">
  <name>Task 2: Write the idempotent backfill, run it locally, and verify row for row</name>
  <files>scripts/backfill-interaction-reports.ts, scripts/verify-interaction-report-backfill.ts</files>
  <action>
`scripts/backfill-interaction-reports.ts`, following the `scripts/sync-s3-to-db.ts`
precedent (plain `tsx`, explicit logging, a `--dry-run` flag that reports what it
WOULD write and changes nothing):

- Read every `InterviewReport` row. For each, upsert an `InteractionReport` keyed on
  the SAME `id`: `typeSlug` from the row's own `typeSlug`; `userId`, `status`,
  `turnCount`, `transcriptKey`, `cameraMode`, `visualMetrics`, `vocalMetrics`,
  `visualUnscoredReason`, `vocalUnscoredReason`, `metricsConsentAt`,
  `reportStructured`, `reportMarkdown`, `failureReason`, `evalModel`, `startedAt`,
  `completedAt`, `createdAt`, `updatedAt` copied verbatim (nulls stay null);
  `scores` built as `{visual, vocal, content, behavioral}` preserving nulls as
  JSON nulls (a null score must remain distinguishable from 0);
  `inputSnapshot` built as the locked `{kind:"interview", ...}` shape from the ten
  typed snapshot columns, using the `InputSnapshot` type from `lib/report/snapshot.ts`;
  `interactionLogId`/`studentEmail`/`terminationReason`/`outcome` null.
- Read every `ScenarioReport` row. Same, with `typeSlug: "case-study"`,
  `transcriptKey: null`, `interactionLogId` and `studentEmail` copied verbatim, and
  `inputSnapshot` as `{kind:"scenario", caseId, caseName, background:
  backgroundSnapshot, avatars: avatarsSnapshot, criteria: criteriaSnapshot}`.
- Idempotency: `upsert` on `id`, so a second run updates in place and never
  duplicates. Log created-vs-updated counts separately.
- Do not skip `IN_PROGRESS` rows — they are real rows and the engine's report-GET
  must keep finding them. Log how many were seen.
- Never write to the legacy tables. Never delete anything.

`scripts/verify-interaction-report-backfill.ts` — the proof, not a vibe check:
- Count assertion: `interactionReport.count() >= interviewReport.count() + scenarioReport.count()`,
  and every legacy id has a matching `InteractionReport` id (set difference printed,
  must be empty).
- Per-row field assertions for every row: status, turnCount, all six Phase 10
  metric columns, reportStructured/reportMarkdown/failureReason/evalModel and all
  four timestamps are deeply equal to the source row.
- Score-map assertion: each of the four keys equals the source column, with null
  preserved as null (assert explicitly that a null score did not become 0).
- NULL-PRESERVATION assertion, called out as its own numbered section: for every
  source row with `cameraMode === null`, the backfilled row has `cameraMode === null`
  AND `visualUnscoredReason === null` AND `vocalUnscoredReason === null`.
- Snapshot assertion: interview rows round-trip all ten typed columns through
  `inputSnapshot`; scenario rows round-trip caseId/caseName/background/avatars/
  criteria, and `caseId` is a plain string inside the JSON.
- Idempotency assertion: run the backfill a second time from inside the verifier (or
  instruct it as a two-step) and assert the row count and a sampled row's
  `updatedAt`-independent content are unchanged.

Run both against the LOCAL DB.

Expose the deck pipeline as three authenticated routes: upload (which does the whole
validate-convert-rasterize-persist job synchronously and returns an opaque id), the
owner's manifest, and the private slide-image byte server.

private binary object back to its authenticated owner. Today's private objects
(resume PDFs) never leave the server; today's images (avatars, case covers) are
public-read. Slide images are the first private, owner-only binary asset.
Output: three routes plus a verification script.
</objective>

<non_negotiables>
- **PDF and PPTX only.** No Drive, no OAuth, no `googleapis`. The `unknown-format`
  rejection copy may mention exporting a Slides deck to PDF; nothing else.
- **No S3 URL in any response**, signed or unsigned. The upload route returns an
  opaque `deckId` and derived metadata only — the exact posture
  `app/api/interview/upload-resume/route.ts` already documents in its header
  comment. Copy that posture and that comment style.
- **Ownership comes from the cookie, never the request.** Every route resolves
  `currentUser` via `getCurrentUser(token)` and passes `currentUser.id` into the
  store. A cross-owner request is a **404**, not a 403 — matching the report GET
  route's established behavior ("a student requesting another student's report still
  gets a 404, not a 403 and not someone else's data").
- **Rejection responses carry both halves.** The body shape is
  `{ error: reason, fix, code }`. A response with `error` and no `fix` is a defect;
  the verification script asserts it for every code.
- **No escape hatch.** There is no `?skipDeck=1`, no empty-deck success path, and no
  warning tier. CONTEXT.md: "No 'start without a deck' escape hatch and no soft
  per-slide warning tier."
- **Rasterization is synchronous in the request.** No `waitUntil`. Set
  `maxDuration = 120` and `runtime = "nodejs"` on the upload route (the resume route
  uses 60; conversion plus rasterization of a large deck needs more headroom, and
  14-01 measured conversion at under 45s).
- Do not add a Prisma model for decks. 14-06 decided the manifest in S3 is the
  record.
</non_negotiables>

<task type="auto">
  <name>Task 1: The deck upload route</name>
  <files>app/api/practice/deck/upload/route.ts</files>
  <action>
Port the structure of `app/api/interview/upload-resume/route.ts` — same auth read,
same `response()` helper with `Cache-Control: no-store`, same header comment style
stating the private-storage posture.

`export const runtime = "nodejs"; export const maxDuration = 120;`

POST flow:
1. Read the session cookie, `getCurrentUser`; no user → 401 `{ error: "Unauthorized" }`.
2. `formData()`, get `file`. Missing or a string → 400 with the `empty` rejection copy
   from `DECK_REJECTIONS`.
3. **Do NOT gate on `file.type`.** The resume route gates on the PDF MIME type first;
   here the format is decided by magic bytes alone, because a `.pptx` arrives with
   several different browser-reported MIME types and `lib/deck/intake.ts` already
   treats client MIME as forgeable. Note the deliberate divergence in a comment.
4. `const buffer = Buffer.from(await file.arrayBuffer())`, then
   `validateAndExtractDeck(buffer, file.name)`. On `ok: false` → 400 with
   `{ error: result.reason, fix: result.fix, code: result.code }`.
5. If `format === "pptx"`: `convertPptxToPdf(buffer)`. On failure map the driver's
   code to a student-facing reason+fix pair and return 502 (not 400 — the student's
   file was fine, the service was not):
   - `backend-unconfigured` → reason "PowerPoint decks can't be processed right now."
     / fix "Export your deck as a PDF and upload that instead — PDF decks work."
   - `backend-timeout` → reason "That deck took too long to process." / fix "Try
     again, or export it as a PDF and upload that instead."
   - `backend-error` → reason "That .pptx couldn't be converted." / fix "Re-save it
     as .pptx from PowerPoint or Keynote, or export it as a PDF, then try again."
   Put these in a small exported map in this file so they are greppable and so the
   wizard's error UI (plan 14-12) can be tested against them.
6. `rasterizePdf(pdfBuffer)` — the original buffer for a PDF upload, the converted
   buffer for a PPTX.
7. `persistDeck({ userId: currentUser.id, extraction, rasterized, originalBuffer: buffer, originalFormat: format })`.
8. 201 with
   `{ deckId, format, slideCount, slides: [{ index, widthPx, heightPx, textLength }] }`.
   **Do not return the slide text** — the wizard does not need it, the live session
   gets it server-side, and sending it bloats the response for a 60-slide deck. Do
   not return any URL. `textLength` is there so the wizard can show a "this slide is
   text-heavy" affordance later if wanted without a second round trip.
9. Wrap everything in try/catch returning a 500 with a reason+fix pair; never let a
   raw stack reach the student.
  </action>

  <name>Task 2: The manifest route and the private slide-image byte server</name>
  <files>app/api/practice/deck/[deckId]/route.ts, app/api/practice/deck/[deckId]/slide/[index]/route.ts</files>
  <action>
**`app/api/practice/deck/[deckId]/route.ts`** — `GET`:
- `runtime = "nodejs"`. Auth → 401. `loadDeckManifest(currentUser.id, deckId)` →
  null means 404 (this covers both "no such deck" and "not your deck" with one code,
  which is exactly the 404-not-403 posture required).
- Return `{ deckId, format, slideCount, slides: [{ index, text, widthPx, heightPx }] }`.
  The per-slide TEXT is included here because the wizard's session-length proposal
  and the report both legitimately need it, and the caller is already proven to be
  the owner. `Cache-Control: private, no-store`.

**`app/api/practice/deck/[deckId]/slide/[index]/route.ts`** — `GET`:
- `runtime = "nodejs"`. Auth → 401.
- Parse `index` with `Number.parseInt` + `Number.isInteger` guard; a non-numeric or
  negative index → 404 (not 400 — do not leak whether the deck exists).
- `variant` from `?v=thumb`, defaulting to `"slide"`; any other value → treat as
  `"slide"` rather than erroring.
- `loadDeckSlideImage(currentUser.id, deckId, index, variant)` → null → 404.
- Return the bytes with `Content-Type: image/png`, `Content-Length`, and
  `Cache-Control: private, max-age=3600, immutable`. **`private` is required** — a
  shared CDN cache must never hold another student's slide. Add a comment saying so.
- No `Access-Control-Allow-Origin`. No redirect to S3. Stream or buffer the body
  directly; 14-RESEARCH.md Pattern 1 recommended this over presigned URLs
  specifically to preserve the codebase's "never expose a raw bucket URL" posture.
- Header comment: "This is the first route in this codebase that serves a PRIVATE
  binary object back to its authenticated owner. Resume PDFs are stored privately but
  only their extracted text ever leaves the server; avatar/profile/case-cover images
  are public-read. If you are adding a second such route, follow this one's
  ownership-check shape."
  </action>

<objective>
Wire the server-authoritative high-water mark into the live turn: ratchet the client's
reveal claim, persist it, slice the slides channel with Phase 13's visible-context
cursor, and deliver the admitted slide text through the per-turn TAIL BLOCK.

Purpose: Success Criterion 3 in full — "the avatar's context contains only slides the
student has actually shown, never content from a slide not yet reached, and navigating
backward does not un-show what the avatar already saw." This is also the plan where
14-RESEARCH.md's two highest-confidence pitfalls both live: a client-trusted cursor is
a context-leak vector (Pitfall 2) and putting growing slide text in the system prompt
kills the prefix cache (Pitfall 1).
Output: one new `lib/pitch/slide-reveal.ts`, an additive edit to `buildTailBlock`, a
narrow edit to the chat route, and a verification script.
</objective>

<non_negotiables>
**Pitfall 1 — the prefix cache (REQ-73, inherited).**
- Slide text goes in the **tail block**, appended to the latest user message. It must
  NEVER be concatenated into the system prompt, nor reach `assembleSystemPrompt`
  through any argument. 13-06 ships a dev-mode guard that throws if a per-turn-looking
  value reaches the system prompt; if this plan can make it throw, this plan is wrong.
- Some cache-hit loss on the TAIL is expected and acceptable. The goal is a stable
  SYSTEM PROMPT prefix, not a byte-identical request.

**Pitfall 2 — the client is not trusted.**
- The request's slide index is an INPUT to a ratchet, never a stored or used value.
  The only value that reaches `applyVisibleContext` is the server-persisted
  high-water mark after ratcheting.
- Monotonic non-decreasing, bounds-checked against the deck's real slide count from
  the manifest (not from the request). Backward navigation never lowers it — CONTEXT.md:
  "the investor already saw them." Forward thumbnail jumps DO advance it.
- A non-finite, negative, non-integer or over-range value is ignored or clamped, never
  an error. A malformed client must not be able to break a live session.

**Phase 13 must not move.**
- An interview turn and a case-study turn must produce byte-identical requests to what
  Phase 13 sent. The reveal logic is reachable only when the resolved instance is a
  `pitch-deck` instance.
- Do not restructure `buildTailBlock`'s existing fragments or their order. Append.
</non_negotiables>

Create `lib/pitch/slide-reveal.ts`. Three exports, the first two pure.

**`ratchetHighWaterMark({ stored, requested, slideCount }): { mark: number | null; advanced: boolean }`**
- `stored` is `number | null` (null = nothing revealed yet, per 14-05's convention).
- Returns `mark = Math.max(stored ?? -1, clamp(trunc(requested), 0, slideCount - 1))`,
  and `mark = stored` unchanged when `requested` is not a finite number, is negative,
  or `slideCount <= 0`. `advanced` is true only when `mark > (stored ?? -1)`.
- `mark` of `-1` is normalized back to `null`? No — once a session has started the
  student is on slide 0, so a successful ratchet always yields `>= 0`. Return the
  incoming `stored` (possibly null) when nothing valid was requested, so a type with
  no deck never gains a mark.
- Header comment: quote CONTEXT.md's high-water-mark rule and name 14-RESEARCH.md
  Pitfall 2. State in one line: **this function is the only place in the repo where a
  client-supplied slide index is read.** Any other reader is a bug.
- This duplicates the arithmetic 14-05 put inside `checkpointSession`. **Refactor
  14-05's copy to call this function** so there is exactly one ratchet in the repo,
  and record the refactor in the SUMMARY. Two ratchets that can drift is precisely the
  failure this phase is trying to avoid.

**`resolveRevealedSlides({ config, mark }): { index: number; text: string }[]`**
- Build the channel with `buildSlidesChannel(config.instance.slideTexts)`, then call
  `applyVisibleContext(config, { [SLIDES_CHANNEL_KEY]: channel, ...otherChannels }, { cursor: mark })`
  using 13-03's real argument shape, and return the admitted slides entry.
- **Do not filter locally.** No `.slice(0, mark + 1)` in this file. The point is that
  Phase 13's primitive does the admission; a local filter would be the parallel
  mechanism the hard constraint forbids. Assert this in Task 3.
- `mark === null` → return `[]`. Nothing has been shown.

**`buildSlidesTailFragment(revealed, { slideCount }): string`**
- Returns `""` when `revealed` is empty.
- Otherwise a compact block in the same voice as `buildTimeBudgetFragment`:
  a one-line header stating how many of how many slides the founder has shown
  ("The founder has shown you slides 1-5 of 18 so far."), then each revealed slide's
  text under a `Slide N:` label (1-based for the model, matching 14-09's labelling
  decision), then a one-line reminder: "You have not seen any later slide. Do not
  reference or ask about content you have not been shown."
- Truncate an individual slide's text to a sane length (e.g. 1200 characters) with an
  ellipsis note, so one pathological slide cannot dominate the tail. Export the limit
  as a named constant.
- Header comment: "**Tail-block content only.** This string grows as the session
  progresses and must never be concatenated into a system prompt — REQ-73, and
  14-RESEARCH.md Pitfall 1. `lib/engine/time-budget.ts` carries the same warning for
  the same reason."

  <name>Task 3: Prove the gating, the leak cases and the prefix-cache stability</name>
  <files>scripts/verify-slide-gating.ts</files>
  <action>
Create `scripts/verify-slide-gating.ts` (plain `tsx`, numbered sections, prints each
assertion, non-zero exit on failure). Build a synthetic 10-slide pitch-deck config
whose slide texts are distinctive sentinels (`"SENTINEL-SLIDE-00"` ... `"SENTINEL-SLIDE-09"`)
so leakage is detectable by string search.

1. **Ratchet monotonicity.** `stored: 3, requested: 1` → `mark: 3, advanced: false`.
   `stored: 3, requested: 7` → `mark: 7, advanced: true`.
2. **Bounds.** `stored: 3, requested: 99, slideCount: 10` → `mark: 9`. `requested: -5`
   → `mark: 3`. `requested: NaN` / `Infinity` / `3.7` → `mark: 3` or 3 respectively
   (assert the truncation case explicitly).
3. **Null start.** `stored: null, requested: 0` → `mark: 0, advanced: true`.
   `stored: null, requested: -1` → `mark: null`.
4. **No deck, no mark.** `slideCount: 0` → `mark` equals `stored` for any request.
5. **The slice admits exactly the shown slides.** `resolveRevealedSlides` with
   `mark: 4` returns 5 entries, indices 0-4. The joined text CONTAINS
   `SENTINEL-SLIDE-04` and does NOT contain `SENTINEL-SLIDE-05` .. `-09`.
6. **Backward navigation does not un-show.** Ratchet to 7, then ratchet with
   `requested: 2`, then slice. Assert `SENTINEL-SLIDE-07` is still present. This is
   CONTEXT.md's locked rule and the single most important assertion in the script.
7. **Forward jump reveals the skipped slides.** Ratchet from 2 straight to 6 and
   assert the slice contains sentinels 3, 4 and 5 — the skipped ones — because a
   forward jump advances the mark past them.
8. **Unshown slides never enter the tail.** `buildSlidesTailFragment` for `mark: 4`
   must not contain any sentinel above 04. Also assert the fragment contains the
   "do not reference content you have not been shown" reminder.
9. **PREFIX CACHE.** Call `assembleSystemPrompt(config)` for the deck config, then
   again after notionally revealing slides 0 through 9, and assert the two strings are
   **byte-identical**. Then assert `assembleSystemPrompt`'s output contains NONE of
   the ten sentinels. This is the Pitfall-1 guard.
10. **Tail block is unchanged for other types.** Call `buildTailBlock` with an
    interview config and the same turn state minus the slide fields, and assert the
    output is byte-identical to calling it without the new fields at all.
11. **One ratchet, one filter.** Read `lib/pitch/`, `lib/engine/` and
    `app/api/interaction/chat/route.ts` as text and assert: `Math.max(` combined with
    `slideHighWaterMark` appears in exactly one file (`lib/pitch/slide-reveal.ts`);
    and no file outside `lib/engine/visible-context.ts` filters the slides channel.
12. **No slide value can reach the system prompt.** Assert
    `buildDeckSystemPrompt.length` (the function's arity) is 1 and that its only
    parameter is the config — i.e. there is no second parameter a caller could pass a
    cursor through.

<objective>
Turn a validated deck into server-rendered slide images and store everything
privately: one PNG per slide at viewer resolution, one thumbnail per slide, the
original file, and a manifest carrying the per-slide text and slide count.

Purpose: the second half of Success Criterion 2 and the precondition for CONTEXT.md's
locked "slide images are server-rendered and privately stored, and are an evaluator
input as well as a student-facing asset". PPTX and PDF converge onto ONE rendering
path — PPTX is converted to PDF first, then both rasterize identically.
Output: `lib/deck/{pptx-convert,pdf-rasterize,store}.ts`, additive deck helpers in
`lib/s3-client.ts`, and a verification script.
</objective>

<non_negotiables>
- **No public ACL, ever.** `lib/s3-client.ts` already has `ACL: 'public-read'` upload
  methods for avatar/profile/case-cover images. Deck objects must NOT use them and
  must not copy their shape. 14-RESEARCH.md Pattern 1 confirms there is no existing
  private-binary-serving precedent in this codebase; this plan creates the storage
  half of it and plan 14-07 creates the serving half.
- **Keys are server-derived.** Build every key from the authenticated `userId` and a
  server-generated `deckId` (`randomUUID()`), sanitized the same way
  `saveInterviewResume` sanitizes them. A client-supplied string must never reach a
  key. No function in this plan may return an S3 URL.
- **Rasterization is synchronous.** Do NOT wrap it in `waitUntil`. 14-RESEARCH.md
  Pitfall 4: the student cannot start the live navigation session without the images,
  so a backgrounded rasterization leaves the wizard with nothing to show.
- **No slide-count rejection.** CONTEXT.md forbids it. Rasterize every page the deck
  has. If a very large deck is slow, that is a latency finding for 14-15, not a
  licence to reject it.
- **PDF and PPTX take the same rendering path** (CONTEXT.md: "same path for PDF and
  PPTX"). Do not write a second renderer for PPTX.
- No Google Slides, no Drive, no `googleapis`.
</non_negotiables>

  <name>Task 1: The PPTX-to-PDF conversion driver and the PDF-to-PNG rasterizer</name>
  <files>lib/deck/pptx-convert.ts, lib/deck/pdf-rasterize.ts</files>
  <action>
**`lib/deck/pptx-convert.ts`** — `convertPptxToPdf(buffer): Promise<{ ok: true; pdf: Buffer } | { ok: false; code: "backend-unconfigured" | "backend-error" | "backend-timeout"; detail: string }>`:
- Read `DECK_CONVERT_BACKEND`, `DECK_CONVERT_URL`, `DECK_CONVERT_TOKEN` from
  `process.env`. If the backend or URL is unset → `backend-unconfigured`. Never throw.
- Implement the contract from `14-DECK-RENDER-DECISION.md`. For the recommended
  `gotenberg` backend that is a multipart POST with a bearer token returning
  `application/pdf`; for `cloudconvert` it is the vendor's job/upload/export dance;
  for `vercel-libreoffice` it is an in-process `soffice --headless --convert-to pdf`
  through a temp directory. Write ONE driver per selected backend — do not stub the
  other two. Put a `switch` on `DECK_CONVERT_BACKEND` with the unselected branches
  throwing a clear "not implemented — see 14-DECK-RENDER-DECISION.md fallback order"
  error, so a later fallback is a small, obvious edit.
- `AbortController` timeout of 45 seconds (the disqualifier threshold 14-01 set).
  One retry on a network-level failure only (not on a 4xx). Export the timeout as a
  named constant.
- Assert the response body begins `%PDF-` before returning it; a backend returning
  an HTML error page with a 200 must map to `backend-error`, not be handed onward as
  a "PDF".
- Header comment: name the selected backend, cite the decision doc, and state the
  fallback order, so a future reader does not re-litigate it.

**`lib/deck/pdf-rasterize.ts`** — `rasterizePdf(buffer): Promise<RasterizedSlide[]>`
where `RasterizedSlide = { index: number; png: Buffer; thumbPng: Buffer; widthPx: number; heightPx: number }`:
- Import the legacy Node build of `pdfjs-dist` and the canvas package 14-01 proved
  (`@napi-rs/canvas` unless 14-01 recorded a fallback). Match 14-01's spike code
  exactly — it is the proof that this works on Vercel.
- For each page: viewport scaled so the LONG edge is 1600px for the slide image and
  240px wide for the thumbnail (two renders, or render once and downscale — whichever
  the spike proved). Record both pixel dimensions on the result so the viewer can lay
  out portrait and landscape decks correctly **without rejecting either**.
- `index` is zero-based, matching `lib/deck/types.ts`'s locked convention.
- Disable pdfjs worker usage and font fetching from the network
  (`isEvalSupported: false`, no `standardFontDataUrl` pointing at a CDN — bundle or
  accept pdfjs's built-ins). A rasterizer that silently reaches the internet for
  fonts will render differently on Vercel than locally, which 14-01's disqualifier
  list explicitly cares about.
- Never throw: wrap per-page failures so one bad page yields a blank-but-sized PNG
  with a flag rather than failing the whole deck, and return the flag so the caller
  can record it. A deck must not be rejected because page 17 has an exotic
  transparency group.
  </action>

`npx tsc --noEmit` clean; `npx eslint lib/deck` clean.

`grep -n "waitUntil" lib/deck/` returns nothing.
`grep -n "public-read" lib/deck/` returns nothing.
  </verify>
  <done>PPTX converts to PDF through the decided backend with a timeout and typed failures; a PDF rasterizes to two-resolution PNGs with recorded pixel dimensions; neither module can throw or reach for a public ACL.</done>

<task type="auto">
  <name>Task 2: Private deck storage and the manifest</name>
  <files>lib/s3-client.ts, lib/deck/store.ts</files>
  <action>
**`lib/s3-client.ts`** (additive — do not modify any existing method):
- `const DECKS_PREFIX = "decks/";` next to the existing prefix constants.
- `async saveDeckObject(userId, deckId, relativeKey, body, contentType)` — PUT to
  `${DECKS_PREFIX}${safeUserId}/${safeDeckId}/${relativeKey}` with **no ACL**
  (private by default, matching `saveInterviewResume`, NOT the avatar-image methods).
  Sanitize `userId`/`deckId` exactly as `saveInterviewResume` does and reject a
  `relativeKey` containing `..` or a leading `/`.
- `async getDeckObject(userId, deckId, relativeKey)` → `{ body: Buffer; contentType: string } | null`,
  returning null on `NoSuchKey` rather than throwing.
- Header comments on both: "Deck objects are PRIVATE. There is deliberately no
  presigned-URL or public-ACL variant here — slide images reach the browser only
  through the authenticated, ownership-checked byte-serving route
  (app/api/practice/deck/[deckId]/slide/[index]/route.ts). Do not add a URL-returning
  helper."

**`lib/deck/store.ts`**:
- `export type DeckManifest = { deckId: string; format: DeckFormat; slideCount: number; createdAt: string; slides: { index: number; text: string; widthPx: number; heightPx: number; renderFailed?: boolean }[] };`
  Comment: the manifest is the deck's only metadata record. There is deliberately NO
  Prisma table — a deck is an engine INSTANCE and this codebase already stores
  student-authored instances (`CaseStudy`) in S3, so adding a table would be a
  second pattern for the same thing and a second migration.
- `persistDeck({ userId, extraction, rasterized, originalBuffer, originalFormat })`
  → `{ deckId, manifest }`: generate `deckId = randomUUID()`; write
  `original.{pdf|pptx}`, `slides/{nnn}.png`, `thumbs/{nnn}.png` (three-digit
  zero-padded index) and `manifest.json`. Write the manifest LAST so a partially
  written deck is never readable as a complete one. Zip the extraction's per-slide
  text with the rasterized dimensions by `index`; if the counts disagree (a
  conversion that produced a different page count than the PPTX had slides), use the
  RASTERIZED count as authoritative for slide identity and record the mismatch on
  the manifest — the images are what the student navigates and what the avatar is
  gated against, so they define the deck.
- `loadDeckManifest(userId, deckId)` → `DeckManifest | null`.
- `loadDeckSlideImage(userId, deckId, index, variant: "slide" | "thumb")` →
  `{ body, contentType } | null`, bounds-checking `index` against the manifest's
  `slideCount` and returning null (not an error) when out of range.
- No function in this module returns a URL.
  </action>

  <done>Deck originals, slide images, thumbnails and a manifest are stored privately under server-derived keys; the manifest is the deck's only metadata record; nothing in the storage layer can produce a URL.</done>

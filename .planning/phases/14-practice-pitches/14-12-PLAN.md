<objective>
Build the investor pitch deck's three setup steps on Phase 13's generic wizard: the
deck upload (the heaviest step anything in this codebase has had), the student's
declared ask, and the student-adjustable session length.

Purpose: the student-facing half of Success Criterion 2, the "ask" half of Criterion
4, and Criterion 5's adjustable proposal. 14-RESEARCH.md Pitfall 4 is specifically
about this step: the wizard's generic step contract assumes fast, mostly client-side
steps (pick an interviewer, paste a persona). A deck upload is slow and can fail in
ways that need specific messaging, so it gets its own component with its own loading
and error states rather than being forced through `ResumeStep.tsx`'s near-instant
round-trip pattern.
Output: three components plus the registration edit. No route (14-07 built them).
</objective>

<non_negotiables>
**From CONTEXT.md — locked:**
1. **PDF and PPTX only.** The file input's `accept` attribute lists
   `.pdf,.pptx,application/pdf` and the copy says "PDF or PowerPoint (.pptx)". **No
   Google Slides button, no "import from Drive", no OAuth.** The helper copy may say
   "Using Google Slides? File → Download → PDF" as plain text — that is the one
   permitted mention, and it is a how-to, not an integration.
2. **Rejection shows reason AND fix.** Render both halves from the response body
   (`error` and `fix`). Never substitute a generic "Upload failed". If the response
   somehow lacks `fix`, render the reason plus a generic next action AND log a
   console warning naming the missing field — a silent degradation here is how the
   locked decision rots.
3. **No escape hatch.** There is NO "continue without a deck" button, no skip link,
   and the step is NOT optional in the `setupSteps` declaration. Contrast this with
   `ResumeStep` which IS optional — note the deliberate difference in a comment,
   because a contributor copying `ResumeStep` will carry its `optional` flag across.
4. **No warning tier.** Do not add "this slide looks text-heavy" warnings, do not
   warn about portrait orientation, do not warn about slide count. The server
   accepted the deck; the UI's job is to show it, not to second-guess it.
5. **Session length is a PROPOSAL, adjustable.** Pre-fill from
   `proposeDeckSeconds(slideCount)`; let the student move it anywhere in 20-30
   minutes. Do not present it as fixed and do not let the UI offer a value outside
   the envelope (the server clamps anyway — belt and braces).
6. **The ask is a plain form field.** Price and equity percentage, typed by the
   student. **No LLM extraction, no parsing of free text.** 14-RESEARCH.md Open
   Question 3's recommendation, adopted: capturing it structurally up front is what
   lets it enter the session-constant prompt safely from turn one.
7. **No S3 URLs in the DOM.** Thumbnails point at
   `/api/practice/deck/{deckId}/slide/{index}?v=thumb`.
</non_negotiables>

  <name>Task 1: The deck upload step</name>
  <files>components/practice/steps/DeckUploadStep.tsx</files>
  <action>
Read `components/practice/steps/ResumeStep.tsx` for the props shape and the visual
vocabulary, then build this as its own component — explicitly NOT a parameterization
of `ResumeStep`, which assumes a near-instant round trip.

State machine, as an explicit union (`idle | uploading | processing | ready | rejected | failed`):
- **idle** — heading "Upload your pitch deck", one line of copy ("PDF or PowerPoint
  (.pptx), up to 25MB"), the Google-Slides-to-PDF how-to line, a file input / drop
  zone. **No skip control.**
- **uploading** — a determinate progress bar from `XMLHttpRequest`'s `upload.onprogress`
  (fetch cannot report upload progress). Label it "Uploading your deck…".
- **processing** — once the upload bytes are sent, the server is still converting and
  rasterizing, which can take tens of seconds. Switch to an indeterminate indicator
  with honest copy: "Rendering your slides… this takes a few seconds for a large
  deck." Pitfall 4 names the absence of this indicator as the specific failure to
  avoid. Do not fake a percentage.
- **rejected** (HTTP 400) — render the `error` as the headline and the `fix` as the
  action line beneath it, visually distinct. Then a "Choose a different file" control
  that returns to `idle` **preserving nothing** of the bad file. The student must be
  able to retry without leaving the step or restarting the wizard.
- **failed** (HTTP 502 conversion failure, or 500) — same two-part rendering using
  14-07's conversion-failure copy map, which already pairs each backend failure with
  a fix (and whose PPTX fixes include "export it as a PDF instead", which is a real
  escape from a service outage without being an escape from needing a deck).
- **ready** — show `slideCount` ("18 slides") and a horizontal strip of thumbnails
  from `/api/practice/deck/{deckId}/slide/{i}?v=thumb` with `loading="lazy"` and an
  `alt` of "Slide {i+1}". **Lay out each thumbnail from the returned `widthPx`/`heightPx`
  so a portrait deck renders upright and uncropped** — a portrait deck is a valid
  deck and must not look broken. Then a "Replace deck" control returning to `idle`.
- Report `{ deckId, slideCount, slides: [{index,widthPx,heightPx}] }` into wizard
  state under the declared key. The wizard's forward control must be disabled unless
  the state is `ready`.
- Reversibility: coming BACK to this step from a later step must show the `ready`
  state with the already-uploaded deck, not reset to `idle`. Read the value out of
  wizard state on mount.
- `aria-live="polite"` on the status region so the state transitions are announced.
- File-header comment: cite 14-RESEARCH.md Pitfall 4; state that this step is
  deliberately NOT optional and deliberately not built on `ResumeStep`.
  </action>

     way the text must not sit in client state for the whole wizard.
   - `fairValueBand`: the scenario's hidden band. **The student never chooses it and
     never sees it.**
     **It MUST be independent of the student's declared ask.** Carry it as
     per-instance configuration resolved server-side at `startSession` — a per-type
     constant, or a small fixed set of bands keyed off deck/scenario metadata
     (e.g. slide count or a scenario label). Implement it in `lib/pitch/`.
     **Deriving it as a function of `askPriceUsd`/`askEquityPct` is DISALLOWED** —
     including "a band centred near a discount to the ask". A band that moves with
     whatever the student types makes the report's `settled vs. fair` comparison
     circular and destroys its ability to say whether the ask itself was reasonable.
     The band is what CONTEXT.md calls the *configured scenario's* band
     (`14-CONTEXT.md`, "Negotiation target — both"), and 14-RESEARCH.md Pattern 4
     fixes it as instance config known before the session and never model-controlled.
     **Do not send it from the client** under any circumstances; a client-supplied
     fair band would let a student negotiate against a band they chose. If this
     forces a small addition to `startSession`, make it and record it as a 13-07
     extension in the SUMMARY. State the chosen values explicitly in the SUMMARY.
     The *numbers* inside a band are a tuning knob 14-15 may calibrate; the rule that
     the band is ask-independent is a correctness constraint and is NOT tunable.
3. Keep the unknown-slug handled-not-found behavior and every existing branch exactly
   as they are. No `if (typeSlug === "pitch-deck")` logic beyond this page's

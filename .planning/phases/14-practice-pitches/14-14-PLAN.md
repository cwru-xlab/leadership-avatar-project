Make the one report page tell the truth about a pitch: the named early-end outcome
with its reasons and timecode, the ask-versus-settled-versus-fair triple, the slide
reveal timeline, the overrun — all contributed by the type rather than branched into
the page.

presentation as **both** a named outcome banner with reasons and timecode **and**
every dimension still scored, explicitly "no zeroing, no rendering the report as an
error or crash". It locks the negotiation display as the three-value ask/settled/fair
and the overrun as a noted fact.
Output: a DTO extension, a chrome extras slot, and three report panels. The one
report page itself should need **no** edit if 13-12's dimension-driven rendering
works as designed — if it does, say so in the SUMMARY; if it needs one, keep it to
the extras slot.
</objective>

<non_negotiables>
**From CONTEXT.md — locked:**
1. **An early end is a recorded failure with reasons — never a crash and never a
   neutral finish.** The banner names the outcome ("The listener disengaged and ended
   the conversation"), gives the specific reasons, and gives the timecode where
   interest dropped. It must use the report's normal visual language for a notable
   outcome, **not** the error/failure styling the page uses for a FAILED evaluation.
   A student must not think their session broke.
2. **Every dimension still scored.** The banner sits ALONGSIDE the full score cards.
   Do not hide, grey out, or omit any dimension because the session ended early. The
   discovery/tailoring ceiling was already applied in code (14-04); the report just
   renders the number. **Do not render a "capped" badge that implies a penalty beyond
   the score** — if you show anything, show a short factual note that the early end
   limited what could be evidenced on that dimension.
3. **Ask vs settled vs fair — three distinct sources.** Ask comes from the pitch
   `inputSnapshot` (the student's wizard entry). Settled comes from the validated
   `outcome` (the evaluator's structured output). Fair comes from the
   `inputSnapshot`'s `fairValueBand` (instance config). Never compute one from
   another, never fall back from one to another, and label each so the student knows
   which is which. The fair band is revealed **on the report** — it was hidden only
   during the session.
4. **No deal reached is a legitimate outcome.** When `dealReached` is false or the
   settled values are null, render "No deal" explicitly, not an empty cell and not a
   zero.
5. **Overrun is a noted fact, not a score.** State it ("Scheduled 25:00 — ran 31:40,
   6:40 over"). There is no overrun rubric dimension and you must not invent one.
6. **No engagement meter, retrospective or otherwise.** Do not add an engagement
   graph "now that the session is over". The decision against a gauge was about the
   mechanic, not just the live UI.
7. **The one report page must not branch on a type slug.** Extras are declared in
   `ReportChrome`'s per-type map, which is exactly what 13-12 built that module for.
</non_negotiables>

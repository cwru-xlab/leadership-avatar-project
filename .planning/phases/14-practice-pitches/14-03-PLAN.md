<objective>
Build the deck intake floor: format detection by magic bytes, the size limit, and
per-slide/per-page TEXT extraction for both PDF and PPTX — with every rejection
carrying a specific reason and a specific fix.

Purpose: the first half of Success Criterion 2. CONTEXT.md locks validation as
"minimum only" and rejection messages as "specific reason plus the fix", and
explicitly forbids rejecting on page shape or slide count. This plan is where that
discipline is encoded, as pure functions with no route and no storage, so it can be
proven against real fixture files without a running app.
Output: `lib/deck/{types,intake,pdf-extract,pptx-extract}.ts` and a verification
script driven by committed fixtures.
</objective>

<non_negotiables>
**From CONTEXT.md — a plan that breaks one of these is wrong:**
1. **PDF and PPTX only.** No Google Slides, no Drive, no OAuth, no `googleapis`
   import, not even a commented-out branch. A student with a Slides deck exports
   to PDF.
2. **Validation is MINIMUM ONLY.** Accept iff: the bytes are a genuine PDF or a
   genuine ZIP-container PPTX, the file is within the size limit, and pages/slides
   extract. **Do NOT reject on page shape** — a portrait document that parses is
   accepted. **Do NOT reject on slide count** — one slide is accepted and sixty
   slides are accepted. Do not add an aspect-ratio check "for the student's
   benefit"; the user explicitly rejected it.
3. **Every rejection names the reason AND the fix.** No generic failure string. The
   `DeckRejection` type must make the fix structurally mandatory (a required field),
   so a future contributor cannot add a reason-only rejection.
4. **No escape hatch, no warning tier.** There is no "start without a deck" path and
   no soft per-slide warning between accept and reject. The result type is a binary
   union by design — do not add a `warnings` field.
5. Do NOT edit `lib/rag/document-processor.ts`. It is shared by the RAG pipeline and
   has its own callers; `extractPerPageText` is a NEW function in a NEW module that
   borrows its loop shape (14-RESEARCH.md Pattern 2).
</non_negotiables>

`lib/deck/types.ts`:
- `export const MAX_DECK_SIZE_BYTES = 25 * 1024 * 1024;` — 25MB. Comment: chosen
  larger than the 10MB resume cap because decks carry images; it is the ONLY
  size-shaped rejection and there is deliberately no slide-count or page-shape one.
- `export type DeckFormat = "pdf" | "pptx";`
- `export type DeckSlide = { index: number; text: string };` — `index` is
  **zero-based** and is the single index convention used everywhere in Phase 14
  (storage keys, the viewer, the high-water mark). State that in a doc comment so
  no off-by-one creeps in between plans.
- `export type DeckExtraction = { ok: true; format: DeckFormat; slides: DeckSlide[] };`
- `export type DeckRejectionCode = "empty" | "too-large" | "unknown-format" | "corrupt-pdf" | "corrupt-pptx" | "no-extractable-pages" | "password-protected";`
- `export type DeckRejection = { ok: false; code: DeckRejectionCode; reason: string; fix: string };`
  Doc comment: "`reason` and `fix` are BOTH required fields. CONTEXT.md forbids a
  generic failure: every rejection must name what failed and the next action. Do
  not add an optional-fix variant."
- A frozen `DECK_REJECTIONS: Record<DeckRejectionCode, { reason: string; fix: string }>`
  map so the copy lives once and can be grepped by a reviewer. Write real copy, in
  the voice of the existing resume-upload errors:
  - `empty` — reason "That file is empty." / fix "Pick the deck file again — it looks like the upload was interrupted."
  - `too-large` — reason "That deck is larger than the 25MB limit." / fix "Re-export it with compressed images, or split it, and upload again."
  - `unknown-format` — reason "That file is not a PDF or a PowerPoint (.pptx) deck." / fix "Export your deck as PDF or .pptx and upload that file. Google Slides decks work once you use File → Download → PDF."
  - `corrupt-pdf` — reason "That file claims to be a PDF but could not be read." / fix "Re-export the deck as a PDF from your slide app and try again."
  - `corrupt-pptx` — reason "That .pptx file could not be opened — it may be damaged or may be an older .ppt saved with the wrong extension." / fix "Open it in PowerPoint or Keynote and re-save it as .pptx, then upload again."
  - `no-extractable-pages` — reason "No slides could be read out of that deck." / fix "If the deck is a scan or an image export, re-export it from the original slide file so the text is selectable, then try again."
  - `password-protected` — reason "That deck is password-protected." / fix "Remove the password or export an unprotected copy, then upload again."

`lib/deck/intake.ts`:
- `detectDeckFormat(buffer): DeckFormat | null` — `%PDF-` in the first 5 bytes
  (copy the exact idiom from `app/api/interview/upload-resume/route.ts`) → `"pdf"`;
  first 4 bytes `50 4b 03 04` (ZIP local file header) → `"pptx"`; otherwise `null`.
  Header comment: client-supplied MIME types are forgeable and this codebase already
  treats byte-signature checking as settled for PDF.
- `validateAndExtractDeck(buffer, filename?): Promise<DeckExtraction | DeckRejection>`
  in this order: size 0 → `empty`; size > `MAX_DECK_SIZE_BYTES` → `too-large`;
  `detectDeckFormat` null → `unknown-format`; dispatch to the extractor; a thrown
  extractor error → `corrupt-pdf`/`corrupt-pptx` (detect the
  password/encryption case from the thrown message or the PDF `/Encrypt` marker and
  map it to `password-protected`); an empty slide array → `no-extractable-pages`.
  A slide whose text is empty but whose sibling slides have text is **fine** — an
  image-only slide is a legitimate slide and must not reject the deck. Only ZERO
  extractable pages rejects.
- Never throw. Every path returns one of the two union members.
- A file whose only problem is being a ZIP that is not a PPTX (no `ppt/slides/`
  parts) → `corrupt-pptx`, since a `.docx`/`.xlsx`/`.zip` hits the same magic bytes.
  </action>

`grep -n "warnings" lib/deck/types.ts` returns nothing.
  </verify>

<task type="auto">
  <name>Task 2: Per-page PDF text and per-slide PPTX text extraction</name>
  <files>lib/deck/pdf-extract.ts, lib/deck/pptx-extract.ts</files>
  <action>
**`lib/deck/pdf-extract.ts`** — `extractPerPageText(buffer): Promise<string[]>`.
Read `lib/rag/document-processor.ts`'s `extractTextFromPDF` first: it already walks
`pdfData.Pages.forEach(page => page.Texts.forEach(t => t.R.forEach(run => ...)))`
and then JOINS everything into one string. Write the same loop here but push each
page's accumulated, `decodeURIComponent`-decoded text into an array and resolve the
array. Preserve the existing error/`pdfParser_dataError` handling shape so a corrupt
PDF rejects (plan Task 1 maps the rejection). Keep whitespace normalization minimal:
collapse runs of whitespace, trim, nothing more — the text is going to an LLM and to
a text-density score, so stripping meaningful line breaks would distort both.
File header: state explicitly that this is a restructuring of an existing loop
(14-RESEARCH.md Pattern 2) and that `lib/rag/document-processor.ts` is deliberately
NOT edited because it is shared by the RAG pipeline.

**`lib/deck/pptx-extract.ts`** — `extractPerSlideText(buffer): Promise<string[]>`.
- `jszip.loadAsync(buffer)`.
- List entries matching `^ppt/slides/slide(\d+)\.xml$` and sort by the captured
  integer NUMERICALLY (string sort puts slide10 before slide2 — this is the classic
  bug here; add an inline comment).
- For each, parse with `fast-xml-parser` and collect every `a:t` text node's value
  in document order, joining with a space within a paragraph and a newline between
  `a:p` paragraphs. Do not attempt layout, shapes, theme inheritance, speaker notes
  or SmartArt — text only. File header: cite 14-RESEARCH.md's Don't-Hand-Roll row
  stating that text-only extraction is the one place a lightweight pure-JS approach
  is correct, and that FIDELITY RENDERING is explicitly NOT this module's job (that
  is 14-06's conversion + rasterization).
- If there are zero matching slide parts, throw a distinguishable error so
  `intake.ts` maps it to `corrupt-pptx` (a `.docx` has the same magic bytes).
- Normalize whitespace the same way `pdf-extract.ts` does, via a tiny shared helper
  colocated in one of the two files and imported by the other — do not duplicate it.
  </action>
  <verify>
`npx tsc --noEmit` clean; `npx eslint lib/deck` no errors.
`grep -n "sort" lib/deck/pptx-extract.ts` shows a numeric comparator, not a default sort.
`git diff --stat lib/rag/document-processor.ts` is empty.
  </verify>
  <done>Both extractors return one text entry per page/slide, in correct numeric order, with the shared RAG module untouched.</done>
</task>

<non_negotiables>
**From CONTEXT.md — locked:**
1. **High-water mark, client-side too.** The viewer tracks the student's CURRENT slide
   for display and, separately, the FURTHEST slide reached. Only the furthest value is
   ever reported to the server. Going back changes the display and **not** the reported
   value. Forward jumps through the thumbnail strip set the furthest value to the
   jumped-to index, which is how "jumping forward reveals the skipped slides" happens.
2. **Both control sets.** Next/back buttons **and** a thumbnail strip for jumping.
   Not one or the other. Keyboard arrows too (free, and this is a live spoken session
   where a student's hands are busy).
3. **Backward jumps are free.** No confirmation dialog, no warning, no "this will not
   un-show it" nag. The student should be able to flip back to slide 3 without
   friction.
4. **The server is authoritative.** The viewer REPORTS; it never decides what the
   avatar sees. The ratchet is 14-11's, in `lib/pitch/slide-reveal.ts`. Do not add any
   client-side filtering of slide text — the client never holds slide text at all.
5. **Soft envelope.** When remaining time reaches zero: the timer changes appearance
   and counts up as an overrun. It must **not** auto-finish the session, must not
   disable the finish control differently, must not disable push-to-talk, and must not
   prompt the student to wrap up. The avatar cannot end it either
   (`avatarMayEnd: false`, 14-09).
6. **Timer hideable mid-session**, visible by default, collapse state does not pause
   it. Same contract as `PitchTimerPanel`.
7. **No engagement indicator** of any kind, here or anywhere.
8. **High-water mark indication in the viewer is optional** (CONTEXT.md Claude's
   Discretion). Decision: indicate it subtly — thumbnails at or below the furthest
   slide get a faint "seen by the investor" treatment. It makes the core mechanic
   legible and costs nothing. Keep it subtle enough that it is not a scoreboard.
</non_negotiables>

State: `current: number` and `furthest: number`, both starting at 0. Call

Layout:
- **Main stage**: an `<img>` at `/api/practice/deck/{deckId}/slide/{current}` sized
  from the slide's `widthPx`/`heightPx` so **portrait and landscape decks both render
  upright and uncropped** — use `object-fit: contain` inside a flexible box rather
  than a fixed aspect ratio. Preload the next and previous slide images (hidden
  `<img>` or `<link rel="preload">`) so advancing is instant; a stutter here breaks
  the flow of a live spoken pitch.
- **Next / Back** buttons flanking the stage, plus `ArrowRight`/`ArrowLeft` and
  `PageDown`/`PageUp` key handlers scoped so they do not fire while the student is
  typing in the shell's text input. Disable Next on the last slide and Back on the
  first (bounds, not policy).
- **Thumbnail strip** along the bottom: horizontally scrollable, one lazy-loaded
  `?v=thumb` image per slide with `alt="Slide {i+1}"`, clicking jumps. The current
  slide gets a clear active outline. Thumbnails with `index <= furthest` get the
  subtle seen treatment (a small filled dot or a slightly brighter border) with an
  accessible title of "Shown to the investor"; thumbnails above `furthest` get the
  unseen treatment with "Not yet shown". Auto-scroll the strip to keep the current
  thumbnail in view.
- **Slide counter** "7 / 18" near the stage.

Navigation logic, in one `goTo(index)` function so there is a single path:
- Clamp `index` to `[0, slides.length - 1]`.
- `setCurrent(index)`.
- `if (index > furthest) { setFurthest(index); onFurthestChange(index); }` — and only
  then. Going back never calls `onFurthestChange`. Put a comment on that `if` quoting
  CONTEXT.md: "navigating back to slide 3 after reaching slide 7 does not un-show
  4-7 — the investor already saw them."
- Next, Back, keyboard and thumbnail click ALL route through `goTo`. Do not write a
  second increment path.

File-header comment: "The client tracks `furthest` only to report it. The authority
is `InteractionReport.slideHighWaterMark`, ratcheted server-side in
`lib/pitch/slide-reveal.ts`. This component never holds slide TEXT and never decides
what the avatar can see (14-RESEARCH.md Pitfall 2)."

Accessibility: the stage image's `alt` is "Slide {current+1} of {n}"; announce slide
changes with a single `aria-live="polite"` region saying "Slide 7 of 18" — not the
slide content.

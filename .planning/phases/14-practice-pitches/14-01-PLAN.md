<decision_criteria_written_in_advance>
These criteria are fixed NOW so the spike's outcome selects a backend rather than
the implementer rationalizing whichever one was tried first.

**Stage 1 — PDF page -> PNG (mandatory, no alternative).** `pdfjs-dist` legacy
Node build + `@napi-rs/canvas`. This path also serves the PDF-native upload path,
so it is not optional. Accept if: a page renders to a non-blank PNG locally AND
on a Vercel preview deployment. If `@napi-rs/canvas` fails to load on Vercel's
Node runtime, fall back to `canvas` (node-canvas) and record why.

**Stage 2 — PPTX -> rendered image.** Candidates in priority order:

| Rank | Backend (`DECK_CONVERT_BACKEND`) | Select it if |
|------|----------------------------------|--------------|
| 1 | `gotenberg` — self-hosted Gotenberg (LibreOffice wrapper) on the team's existing AWS Lightsail host | The container runs and converts a real .pptx to a PDF whose rasterized pages show correct fonts and layout. **This is the recommendation to try first** (14-RESEARCH.md Alternatives table; the team already operates this host per HANDOFF.md §3). |
| 2 | `vercel-libreoffice` — LibreOffice bundled into a Vercel Large Function | Rank 1 is refused by the human (does not want a second deployable) AND a bundled `soffice --headless --convert-to pdf` actually runs inside a Vercel preview function within its duration limit with correct fonts. |
| 3 | `cloudconvert` — third-party conversion API | Ranks 1 and 2 both fail, OR the human explicitly accepts sending a student's private deck to an external vendor. This is the documented last resort because the deck is private student work. |

**Disqualifiers (reject the candidate, move down the list):**
- Rendered slide fonts are substituted/missing — this directly defeats "judge
  slide appearance," which is a locked CONTEXT.md scoring requirement.
- Conversion of a 20-slide deck does not complete inside 45 seconds (the deck
  upload request must return images synchronously; 14-RESEARCH.md Pitfall 4
  forbids deferring rasterization to `waitUntil`).
- The backend requires the deck to be publicly readable at any point.

**Explicitly out of scope:** any pure-JS PPTX renderer. 14-RESEARCH.md's
Don't-Hand-Roll table rejects these as toys for an appearance-grading use case.
</decision_criteria_written_in_advance>

1. Generate or locate a multi-page test PDF. Prefer generating one so the spike has

   `promise`, encode PNG, write it to `/tmp/spike-slide-001.png`.

   is tiny). Also write a 240px-wide thumbnail to `/tmp/spike-thumb-001.png` to
   prove the two-resolution scheme works.

   be compared against the local one.

`DECK_CONVERT_BACKEND=`, `DECK_CONVERT_URL=`, `DECK_CONVERT_TOKEN=`.

Then prove it on Vercel: add a temporary route `app/api/_spike/deck-render/route.ts`
(`runtime = "nodejs"`, `maxDuration = 60`) that performs step 2 against a PDF
generated in-process and returns `{ ok, pngBytes, canvasBinary }`. Deploy a preview
with `npx vercel --yes` (preview, NOT production) and curl it. Record the response.
**Delete the temporary route and redeploy/discard the preview before finishing the
task** — it must not be left in the repo.

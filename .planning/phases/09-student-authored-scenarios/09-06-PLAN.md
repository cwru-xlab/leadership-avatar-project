<task type="auto">
  <name>Task 1: Scenario card with provenance and owner actions</name>
  <files>components/scenario/ScenarioCard.tsx</files>
  <action>
Create `components/scenario/ScenarioCard.tsx`, a client component. Match the visual
treatment of the existing `components/case-card.tsx` (read it first — same card shell,
cover-image handling and grid sizing) so the two sections on `/case-play` read as one
page, not two designs.

Props:
```ts
{
  scenario: CaseStudy;
  owned: boolean;
  onPlay: (id: string) => void;
  onChanged: () => void;   // parent re-fetches after publish/delete
}
```

Always render: cover image (or the same fallback `case-card.tsx` uses), the name, a
truncated background excerpt, and a character count ("3 characters"). The whole card body
is the Play affordance, calling `onPlay(scenario.id)` — this is REQ-28's "launchable
without further setup".

Provenance badge, always present so REQ-31's obviousness survives even out of context:
- `owned` → a `Chip` reading "Yours" plus, when `scenario.published`, a second
  "Published" chip; when not published, a muted "Private" chip.
- `!owned` → a `Chip` reading "Shared by a classmate". Never render another student's
  id; use `createdBy` (the display string) only if it is non-empty.

Owner actions (rendered ONLY when `owned`, and never on a shared card):
- **Edit** → `router.push(`/case-play/${scenario.id}/edit`)`.
- **Publish / Unpublish** toggle → `POST /api/scenario/publish` with
  `{ id, published: !scenario.published }`, `credentials: "include"`. On success
  `addToast` (publish: "Every student can now find this scenario"; unpublish: "This
  scenario is private again") then `onChanged()`.
- **Delete** → a confirm modal first ("Delete this scenario? Your past reports for it are
  kept."). Then `POST /api/scenario/delete` with `{id}`. On **409**, do NOT show a generic
  failure: surface the server's message and tell the student to unpublish first —
  this is REQ-34's two-step guard and it must be explained, not just enforced.
  On success `addToast` and `onChanged()`.
Guard every action button with an in-flight disabled state and stop click propagation so
an action never also triggers Play.
  </action>

<objective>
Wire the scenario run lifecycle: a cohort-free start that snapshots the scenario onto a
`ScenarioReport` row, a finish that guarantees a terminal evaluation status, and an
owner-scoped report GET.

Purpose: REQ-33 requires the snapshot to be taken AT RUN TIME (Phase 8's
snapshot-on-start precedent), REQ-34 requires the report to outlive its scenario, and
REQ-32 requires the new rubric evaluator to actually run. The legacy
`/api/interaction/start` hard-requires a `cohortId` a student scenario will never have —
this plan routes around it without touching that route.
Output: three routes plus the background runner.
</objective>

`getCurrentUser` → 401). Body: `{ caseId: string, language?: string }`.

1. `const scenario = await s3Storage.getCase(caseId)`.
2. Playability check — the caller may run it only if it is a scenario they may see:
   `scenario.ownerId === currentUser.id` (their own, published or not) OR
   (`scenario.ownerId` present AND `scenario.published === true`) — another student's
   published scenario. A case with NO `ownerId` (admin-authored) is NOT playable through
   this route: return 404. Admin cases keep using the legacy `/api/interaction/*` path
   unchanged. Any miss → 404 `{error:"Scenario not found"}`, never 403.
3. Create the `ScenarioReport` row with the REQ-33 snapshot, taken from `scenario` right
   now — this is the Phase 8 snapshot-on-start precedent
   (`app/api/interview/session/start/route.ts:93-110`), which keeps the row truthful even
   if the author edits mid-run:
   - `userId: currentUser.id`, `caseId`, `status: "IN_PROGRESS"`
   - `caseName: scenario.name`
   - `backgroundSnapshot: scenario.backgroundInfo`
   - `avatarsSnapshot: scenario.avatars` (the `CaseAvatar[]` as-is, into the `Json` column)
   - `criteriaSnapshot: scenario.evaluationPrompt ?? null`
4. Create the S3 `InteractionLog` for the transcript, reproducing what
   `app/api/interaction/start/route.ts` builds — same `InteractionLog` shape, same
   `logId` generation (`${Date.now()}_${random}`), `mode: "assessed"`,
   `attemptNumber` from `s3Storage.getNextAttemptNumber(email, caseId)`,
   `language` resolved through `resolveAttemptLanguage` as that route does, and
   **`cohortId: ""`** — a scenario has no cohort and none is invented. Include the
   `start_session` event the legacy route creates. Persist with
   `s3Storage.saveInteractionLog(log)`.
   Do NOT call `/api/interaction/start` over HTTP and do NOT relax its `cohortId` check.
5. Store the pointer back on the row: `interactionLogId: log.id`,
   `studentEmail: currentUser.email.toLowerCase()`.
6. Return 201 `{ success: true, reportId, log }` — the client needs the full `log` so its
   existing `/api/interaction/save` checkpointing keeps working unchanged.

If the `ScenarioReport` create succeeds but the S3 log write throws, delete the row
before returning 500 so no orphan `IN_PROGRESS` report is left behind (the Phase 6
no-orphan-row discipline recorded in STATE.md).

<objective>
Make the ONE existing deck pipeline carry five modes instead of one, with a
single deliberate, mode-AGNOSTIC widening of the shared plumbing — and no
mode-specific logic anywhere in it.

Purpose: this is the plan that makes REQ-93 achievable. Every new deck mode
reuses `InstanceConfig`'s `kind: "pitch-deck"` member, so the chat route's
`isInstanceConfig` allow-list, its slide-hydration branch, `session.ts`'s
snapshot/ratchet path and the evaluation runner's reconstruction keep working
untouched for all five modes. Three places today hard-require investor
negotiation data and would reject every other mode; they must stop requiring it
WITHOUT learning any mode's name.

Read before writing: `lib/engine/types.ts` (the `pitch-deck` union member,
~line 414), `lib/report/snapshot.ts` (`PitchInputSnapshot` and
`PITCH_INPUT_KEYS`, the `hasAllKeys` narrowing), `lib/engine/session.ts`
(`pitchSnapshotFromInstance` ~line 128 and the `authoredInWizard` band
injection ~line 512), `lib/engine/evaluation-runner.ts`
(`instanceFromPitchSnapshot` ~line 215).

Output: optional negotiation fields, one optional `modeInputs` field, mode-aware
band resolution, a reconstruction path that works without an ask, and a verify
script proving absence and back-compatibility.
</objective>

  <files>lib/engine/types.ts, lib/report/snapshot.ts</files>
  <action>
`lib/engine/types.ts`, the `InstanceConfig` member `kind: "pitch-deck"`:
  - Make `askPriceUsd`, `askEquityPct` and `fairValueBand` OPTIONAL
    (`askPriceUsd?: number`, etc.). REQ-89 / P19-SC2 require these to be ABSENT
    on a mode with no terms — do NOT default them to 0, do NOT add a
    `negotiationEnabled` flag, and do NOT widen their types to `number | null`.
    Absence is the enforcement; a zeroed field is a latent bug.
  - Add ONE optional field `modeInputs?: DeckModeInputs`, importing the type from
    `@/lib/pitch/deck-modes`. This mirrors the precedent already in this file,
    where the union references the feature-layer type
    `DifficultConversationInstance` rather than inlining it — so a sixth deck
    mode adds a `DeckModeInputs` member under `lib/pitch/` and never returns here.
  - Update the member's doc comment: name all five deck modes as sharing this one
    member deliberately (REQ-88, REQ-93); state that `askPriceUsd` /
    `askEquityPct` / `fairValueBand` are present ONLY for the negotiating mode and
    that a reader must never assume they exist; state that `modeInputs` is the one
    extension point for per-mode wizard data.
  - DO NOT add a new union member for any new mode. A new `kind` would force edits
    to `app/api/interaction/chat/route.ts`'s `isInstanceConfig` allow-list and its
    slide-hydration branch, to `session.ts`'s snapshot and ratchet paths, and to the
    evaluation runner — exactly the surfaces REQ-93 forbids touching.

`lib/report/snapshot.ts`, `PitchInputSnapshot`:
  - Add `deckModeInputs?: DeckModeInputs | null`.
  - **Do NOT add `"deckModeInputs"` to `PITCH_INPUT_KEYS`.** That array drives
    `hasAllKeys` in `asInputSnapshot`; adding the key there would make every
    pre-Phase-19 pitch report fail to narrow and render as not-found. Leave the
    required-key list exactly as it is and add a comment saying why the new field
    is deliberately excluded from it.
  - `pitchKind` stays `"elevator" | "deck"` — all five deck modes are
    `pitchKind: "deck"`, and WHICH mode a report was is already recoverable from
    `InteractionReport.typeSlug`. Do not add a second mode discriminant here.
  - In the `v.kind === "pitch"` branch of `asInputSnapshot`, validate
    `deckModeInputs` defensively only: accept absent/`null`, accept a plain object
    whose `mode` is a known deck-mode slug (use `isDeckModeSlug`), and coerce
    anything else to `null` rather than rejecting the whole snapshot. A malformed
    mode-input blob must degrade to absent, never lose a student's report — the
    same posture `asConversationOutcome` already takes in `lib/report/dto.ts`.
  </action>
  <verify>`npx tsc --noEmit` passes. `grep -n 'deckModeInputs' lib/report/snapshot.ts` shows the field on the interface but NOT inside `PITCH_INPUT_KEYS`.</verify>
  <done>The negotiation fields are optional, one `modeInputs` field exists, no new `InstanceConfig` kind was added, and `PITCH_INPUT_KEYS` is unchanged.</done>

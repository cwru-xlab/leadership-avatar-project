<objective>
Create the ONE data home for the deck-led pitch family: a mode table that names
all five modes (investor, funding request, product pitch, deck-led talk, general
deck pitch) and everything that differs between them, plus the four shared deck
rubric dimensions extracted so no mode re-declares them.

Purpose: every later plan in this phase — the four TYPE records, the picker, the
wizard, the report verdicts, the surface guard — reads from this table. That is
what makes adding a sixth mode a data edit rather than a code edit (REQ-93), and
what keeps the investor deck's capability shared rather than copied (REQ-88).

Output: `lib/pitch/deck-modes.ts`, `lib/pitch/deck-rubric.ts`, a generalized
`proposeDeckSeconds`, and a verify script proving the table is complete.
</objective>

<task type="auto">
  <name>Task 2: Build the five-mode deck table</name>
  <files>lib/pitch/deck-modes.ts</files>
  <action>
Create `lib/pitch/deck-modes.ts` — the single source of truth for what differs
between deck modes. Slugs are PERMANENT (they land in
`InteractionReport.typeSlug`) and keep the existing `pitch-` prefix so the Phase
14 reports filter and surface-guard regexes keep matching:
`pitch-deck`, `pitch-funding`, `pitch-product`, `pitch-talk`, `pitch-general`.

Export:

1. `export type DeckModeSlug = "pitch-deck" | "pitch-funding" | "pitch-product" | "pitch-talk" | "pitch-general";`

2. `export type DeckModeInputs` — a discriminated union on `mode`, carrying ONLY
   the per-mode wizard inputs. These are the fields that will ride on the shared
   `pitch-deck` instance and input snapshot (plan 19-02):
   - `{ mode: "pitch-funding"; requestedAmountUsd: number; useOfFunds: string }`
   - `{ mode: "pitch-product"; buyerProfile: string }`
   - `{ mode: "pitch-talk"; talkAudience: string; talkTakeaway: string }`
   There is deliberately NO member for `pitch-deck` (its ask/equity stay where
   Phase 14 put them, on the instance itself) and NO member for `pitch-general`
   (19-CONTEXT.md: zero setup, no audience field — do not invent one).

3. `export interface DeckMode` with these fields and nothing speculative:
   - `slug: DeckModeSlug`
   - `cardTitle: string`, `cardBlurb: string`
   - `listenerLine: string` — who you're pitching to (the picker's primary differentiator)
   - `scoredLine: string` — the short "what gets scored" line
   - `envelopeSeconds: readonly [number, number]` — this mode's own session-length range
   - `negotiates: boolean` — true for `pitch-deck` only
   - `negotiationMarker: string` — the explicit picker marker, e.g. "Ends in terms" / "No terms negotiated"
   - `modeInputStepId: string | null` and `modeInputStepComponent: string | null` — the one wizard step this mode adds, or null for `pitch-general`
   - `distinctiveDimensionKeys: readonly string[]` — rubric keys beyond the shared four
   - `outcomeFieldKeys: readonly string[]` — the mode's outcome record keys (empty for `pitch-general`)
   - `hasOutcomePanel: boolean` — false for `pitch-general` only
   - `listenerDisplayName: string` — the name shown as the live avatar's label
   - `wizardHeadline: string`, `wizardStudioStat: string` — copy the wizard reads instead of branching on a slug

4. `export const DECK_MODES: Record<DeckModeSlug, DeckMode>` populated as:

   | slug | listenerLine | scoredLine | envelope | negotiates | mode input step | distinctive dims | outcome keys |
   |---|---|---|---|---|---|---|---|
   | pitch-deck | An investor | Negotiation | 20-30 min | true | negotiation-ask / NegotiationAskStep | negotiation | dealReached, settledPriceUsd, settledEquityPct, negotiationNotes |
   | pitch-funding | A budget or grant reviewer | Use of funds and whether the amount is feasible | 15-25 min | false | funding-ask / FundingAskStep | use_of_funds_credibility, ask_feasibility | fundedAmountUsd, fundingPosition, fundingRationale |
   | pitch-product | A prospective customer | Objection handling | 10-20 min | false | buyer-profile / BuyerProfileStep | objection_handling | buyerPosition, blockingObjection |
   | pitch-talk | A conference audience | Audience takeaway and holding the room | 10-20 min | false | talk-audience / TalkAudienceStep | audience_takeaway_clarity, holding_the_room | takeawayHeard, matchedDeclaredTakeaway |
   | pitch-general | An attentive listener | Your deck and your delivery | 10-20 min | false | null / null | (none) | (none) |

   `pitch-deck`'s row must reproduce what ships today — envelope
   `DECK_ENVELOPE_SECONDS`, title "Investor pitch deck", and the existing
   `negotiation-ask` step id — so adding the table changes nothing about the
   investor mode. Write real, student-facing copy for every card line (exact
   wording is Claude's discretion per 19-CONTEXT.md); each new mode's blurb must
   make its purpose distinguishable before a student commits.

5. Lookups, mirroring `getEngineType`'s shape so a later store swap touches one
   function: `getDeckMode(slug): DeckMode | null` (trim + lowercase, null on
   unknown), `isDeckModeSlug(slug): slug is DeckModeSlug`,
   `listDeckModes(): DeckMode[]` in picker order (deck, funding, product, talk,
   general), and `deckModeNegotiates(slug): boolean` (false for a non-mode slug).

Header comment must state: this table is the ONLY place a deck mode's identity
lives; a sixth mode is a row here plus one TYPE record under `lib/pitch/`; if you
are about to write `slug === "pitch-..."` anywhere else, call `getDeckMode()`
instead. Pure data + pure lookups — no I/O, no React, no Prisma.
  </action>

<objective>
Build the storage and validation layer for difficult-conversation records as a NEW S3
object type, ported structurally from Phase 9's scenario machinery rather than
retrofitted onto `CaseStudy`.

Purpose: Success Criteria 2 and 3 both rest on ownership and privacy. Phase 9 already
solved owner-scoped CRUD, the 404-never-403 rule, and the `published`-is-discovery-only
semantic — this plan ports those patterns onto a record whose field set
(`hiddenPosition` / `sharedBackstory` / `studentObjective` / `stakes`) `CaseStudy`
cannot express. Research Section B is explicit: a dedicated type gets a
compiler-enforced privacy boundary where `CaseStudy` has only a stripping convention.
Output: the record type, the one validator, the S3 layer, and a verification script.

**This plan imports nothing from `lib/engine/` and is safe to run before Phase 13
lands.**
</objective>

   new prefix, new validator. Copy the *pattern*, not the record.
2. **404 never 403.** `loadOwnedDifficultConversation(id, userId)` returns `null`
   uniformly for "does not exist", "has no owner", and "owned by someone else". This is
   the project-wide rule. Read `lib/scenario/validation.ts`'s `loadOwnedScenario` and
   reproduce its behavior and its doc comment's reasoning.
3. **`published` gates DISCOVERY ONLY, not access.** Carry Phase 9's exact semantic and
   reproduce its doc comment from `app/api/scenario/publish/route.ts`. A direct read by
   id must NOT check `published`. This is literally how P15-SC3 ("playable by any user")
   is satisfied with zero new design.
4. **No `cohortIds`.** That field is dead Phase-11-era weight. Do not carry it forward.
5. **`ownerId` comes from the authenticated session, never from a request body.**
6. **One avatar per conversation, `avatarId` and `voiceId` always set together.** Never
   cross-paired — `CaseAvatar`'s discipline in `types/index.ts`.

**`lib/difficult-conversation/types.ts`:**
- `export const DIFFICULTY_BANDS = ["receptive", "guarded", "hostile"] as const;` with a
  doc comment: three bands is a Claude's-Discretion choice recorded here — it gives a
  real spread without pretending to a precision a prompt cannot deliver. `receptive` =
  defensive but reachable; `guarded` = deflects, needs to be pinned down; `hostile` =
  counter-attacks and has a bottom line they will state late. The band is chosen in the
  wizard and is **hidden entirely during the session**.
- `export interface DifficultConversationRecord` with:
  `id`, `title`, `avatarRole`, `studentRole`, `situation`, `sharedBackstory`,
  `hiddenPosition`, `studentObjective`, `stakes`, `difficulty` (one of the bands, the
  record's DEFAULT band — the student may pick another at setup),
  `avatarId`, `voiceId`, `ownerId: string | null`, `published: boolean`,
  `createdAt: string`, `updatedAt: string`,
  and `lastCheck: { status: "passed" | "rejected"; checkedAt: string; reason?: string; fix?: string } | null`
  — the pre-publish check's last verdict (plan 15-03 writes it, plan 15-05 stores it,
  plan 15-07 renders it).
- Doc comment on `hiddenPosition`: *"Never sent to a client except to the record's own
  owner in the authoring UI. It is omitted from the student-facing briefing and from the
  report snapshot (15-01). Any new read path must be checked against that rule."*
- Doc comment on `published`: reproduce Phase 9's semantic verbatim — discovery only,
  not access control.
- `export const DC_LIMITS` — min/max lengths for every text field. Pick limits that
  make a scenario gradeable without being an essay: title 4-80; avatarRole and
  studentRole 2-80; situation 40-1200; sharedBackstory 40-2000; hiddenPosition 40-2000;
  studentObjective 10-400; stakes 10-600. Record the reasoning in a comment.

**`lib/difficult-conversation/validation.ts`:**
- `validateDifficultConversationInput(input: unknown): DifficultConversationFieldError[]`
  — returns `[]` when valid; otherwise one entry per failing field, **all of them**,
  never short-circuiting on the first. Check: every required text field present and
  within its `DC_LIMITS` bounds; `difficulty` is one of `DIFFICULTY_BANDS`; `avatarId`
  and `voiceId` are both present or both absent (never one of the two); no unknown keys.
- Every message must name the problem AND the fix, in the project's rejection standard
  ("Shared backstory is too short (18 characters). Give both sides at least a couple of
  concrete facts — performance history, prior conversations, dates — up to 2000
  characters."). This same standard is what plan 15-03's rejection copy follows.
- Export nothing that reads from S3 or from a session — this file must be importable by
  a client component.

**`lib/s3-client.ts`** — add `DIFFICULT_CONVERSATIONS_PREFIX = "difficult-conversations/"`

**`lib/difficult-conversation/store.ts`:**
- `loadOwnedDifficultConversation(id: string, userId: string): Promise<DifficultConversationRecord | null>`
  — returns `null` for not-found, for `ownerId === null`, and for
  `ownerId !== userId`. Reproduce `loadOwnedScenario`'s doc comment reasoning: callers
  turn `null` into a 404, never a 403, so a probe cannot distinguish "exists but not
  yours" from "does not exist".
- `loadDifficultConversationForPlay(id: string): Promise<DifficultConversationRecord | null>`
  — **no ownership check and no `published` check**, by design. This is the read path a
  session uses, and it is what makes a published scenario playable by any user
  (P15-SC3). Doc comment must say so explicitly and cite Phase 9's
  `/api/case/get`-stays-untouched precedent. Callers must strip `hiddenPosition` before
  anything reaches a client — add that instruction in the comment and in Task 3's
  assertion.
- `saveDifficultConversation(record, userId)` — stamps `ownerId` from `userId`,
  stamps `updatedAt`, preserves `createdAt` and `published` on update, writes the object
  and updates the index. Never accepts `ownerId` or `published` from the caller's payload.
- `listDifficultConversations({ ownerId?, publishedOnly? })` — reads the index. Returns
  lightweight summaries (id, title, avatarRole, difficulty, published, ownerId,
  updatedAt) and **never** `hiddenPosition`. This feeds plan 15-07's three sections.
- `deleteDifficultConversation(id, userId)` — owner-scoped, removes object and index
  entry. Returns `false` when the loader returns `null`.

<task type="auto">
  <name>Task 3: Prove validation, ownership and the privacy boundary</name>
  <files>scripts/verify-dc-store.ts</files>
  <action>
Create `scripts/verify-dc-store.ts` (plain `tsx`, numbered sections, prints each
assertion, non-zero exit on failure). Use a real S3 round-trip against the configured
dev bucket with ids prefixed `verify-dc-` and delete them at the end; if S3 is
unavailable, fail loudly rather than skipping.

1. A fully valid input validates to `[]`.
2. **Every failure path, individually and together.** For each required field: missing,
   too short, too long. Then one input failing five fields at once returns five entries.
   Assert every message is non-empty and contains both a problem phrase and a fix phrase
   (assert each message is over 40 characters and contains at least one of
   "Give", "Add", "Shorten", "Choose", "Use").
3. `difficulty` outside `DIFFICULTY_BANDS` fails; each of the three bands passes.
4. `avatarId` without `voiceId` fails, and vice versa; both present passes; both absent
   passes.
5. Unknown key rejected.
6. **Round-trip.** Save a record as user A, load it as user A — identical. Confirm the
   index lists it.
7. **404-never-403.** Load it as user B → `null`. Load a nonexistent id as user A →
   `null`. Hand-write an ownerless record and load it as user A → `null`. All three are
   indistinguishable.
8. **Play path.** `loadDifficultConversationForPlay(id)` returns the record for a user
   who is not the owner, AND returns it while `published === false`. Add an assertion
   comment that this is deliberate: `published` is discovery, not access.
9. **Privacy boundary.** `listDifficultConversations` summaries do not contain the key
   `hiddenPosition` for any entry.
10. **Server-side ownership.** Call `saveDifficultConversation` with a payload that
    tries to set `ownerId: "someone-else"` and `published: true`, and assert the stored
    record kept the authenticated `userId` and the previous `published` value.
11. Delete as user B → `false` and the record still exists; delete as user A → `true`
    and both the object and the index entry are gone.

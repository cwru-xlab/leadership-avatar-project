write path that can make content visible to another student.

write paths; this plan wires all of them.
Output: five routes, each a thin wrapper, and a verification script that proves the gate
cannot be walked around.

<non_negotiables>
**From CONTEXT.md — locked:**
1. **Every transition to `published: true` runs the check.** Three paths, enumerated by
   research Section G: the publish route's `false`→`true`; an edit to a record that is
   already `published: true`; and a re-publish after an unpublish even when the text is
   unchanged. Re-screen on all three — re-running on an unchanged republish is cheap and
   removes a "was this exact text last validated" bookkeeping question.
2. **Unpublish is NEVER gated.** `published: true`→`false` runs no check and can never
   fail. An author must always be able to pull their own content down instantly.
3. **A rejection leaves the scenario saved and privately playable.** The record is
   written; only visibility is withheld. The response says so explicitly.
4. **`rejected` and `unavailable` must not be collapsed.** A blocked publish because the
   check could not run says "could not be checked right now — try again in a minute". It
   does NOT tell an author their scenario is abusive.
5. **No appeal path, no reviewer, no staff role, no moderation queue.** Phase 11 removed
   staff roles. The remedy is editing. Do not add a flag, a report button, a review
   status beyond `lastCheck`, or any admin surface.
6. **`published` gates discovery only, not access.** Reproduce the doc comment from
   `app/api/scenario/publish/route.ts` verbatim. `loadDifficultConversationForPlay`
   stays ungated — that is P15-SC3.
7. **404 never 403**, everywhere.
8. **No seeded record is writable.** Seeded ids have `ownerId: null`, so the owner-scoped
   loader returns `null` and every write route 404s. Assert it rather than special-casing.
</non_negotiables>

<task type="auto">
  <name>Task 2: publish and edit — the gate on every publish-visible write</name>
  <files>app/api/difficult-conversation/publish/route.ts, app/api/difficult-conversation/edit/route.ts</files>
  <action>
**`publish/route.ts` (POST `{ id, published: boolean }`)** — authenticate;
`loadOwnedDifficultConversation(id, userId)`, `null` → 404.

Reproduce Phase 9's doc comment at the top of the file verbatim in intent: *"This
deliberately reuses the Phase 7 `published` flag, which gates DISCOVERY only and is not
access control — that semantic is unchanged: reading a conversation by id stays
untouched."* Then add: *"What is NEW in Phase 15 is an automated pre-publish check on
every transition TO published. Unpublishing is never gated."*

- `published: false` → write it, no check, 200. Always succeeds.
- `published: true` → `await runPrePublishCheck(record)`.
  - `passed` → write `published: true`, store `lastCheck`, 200
    `{ published: true }`.
  - `rejected` → do NOT write `published: true`. Store `lastCheck` with the reason and
    fix. Return **422** with
    `{ published: false, blocked: "rejected", category, reason, fix, stillPlayable: true }`
    and a human-readable message stating the scenario is still saved and still
    privately playable.
  - `unavailable` → do NOT write. Store `lastCheck`. Return **503** with
    `{ published: false, blocked: "unavailable", reason, fix }` whose copy says the check
    could not run and to try again — **not** that the scenario was rejected.
  Three distinct statuses (200 / 422 / 503) so the UI never has to parse prose.

**`edit/route.ts` (POST)** — authenticate; owner-scoped load, `null` → 404; validate →
400 with all field errors.

Then branch on the record's CURRENT `published`:
- Currently `false` → save the edit, 200. No check. A private scenario is not
  publish-visible.
- Currently `true` → **re-screen the EDITED text before it becomes visible.** This is
  CONTEXT.md's "closes the publish-clean-then-edit hole". Order matters:
  1. `await runPrePublishCheck(editedRecord)`.
  2. `passed` → save the edit with `published: true` preserved, store `lastCheck`, 200.
  3. `rejected` → save the edit with `published: false` and store `lastCheck`, then
     return **422** with `{ published: false, demoted: true, category, reason, fix, stillPlayable: true }`.
     The edit IS saved (CONTEXT.md: the scenario stays saved and privately playable) and
     the scenario IS unpublished, and the response states both plainly: *"Your changes
     were saved, but this scenario has been unpublished until the problem below is
     fixed."* Never leave the OLD published text live while storing new rejected text —
     that would publish content the author no longer has in front of them.
  4. `unavailable` → identical handling with 503 and the try-again copy. Also demote,
     and say so. Failing closed means the unchecked edit does not stay visible.
- Record a comment at the branch stating that these four outcomes are the complete set
  and that a fifth path (save-but-keep-published-without-a-check) must never be added.
  </action>

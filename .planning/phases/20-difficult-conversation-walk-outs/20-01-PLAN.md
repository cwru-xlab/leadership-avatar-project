against the register the seven seeded confrontation scenarios actually require
BEFORE it is wired into anything.

Purpose: REQ-97 is the detector's core test, not an afterthought. These
scenarios are *about* confrontation — firing someone, confronting a low
performer, declining a senior's request. A detector tuned for a general chat
product fires on the seeded "firing someone" conversation's intended register
and is therefore broken, not strict. The corpus is written first so the
implementation is shaped by the false-positive boundary rather than patched
against it afterwards.

Output: `lib/engine/hostility.ts` (pure, no model, no I/O) plus
`scripts/verify-hostility-detector.ts`, a standalone battery in the house style
of `scripts/verify-disengagement.ts`.

  <action>
Create `lib/engine/hostility.ts`. Pure module: no import from `./types` is
needed, no I/O, no model, no clock, no randomness. Mirror
`lib/engine/disengagement.ts`'s file-top doc-comment discipline — state in the
header that this module decides nothing about termination; it only classifies
text, and the avatar's own cue can never reach it.

Export:
```ts
export const HOSTILITY_TIERS = ["none", "hostile", "severe"] as const;
export type HostilityTier = (typeof HOSTILITY_TIERS)[number];
export interface HostilityVerdict {
  tier: HostilityTier;
  severe: boolean;          // true iff tier === "severe"
  /** Which rules fired, for the report's effect text. Never the matched span. */
  matched: string[];
}
export function detectHostility(text: string): HostilityVerdict;
```

Implementation shape — the TARGETING rule is the whole design:

1. Normalize: lowercase a working copy, but compute the ALL-CAPS shouting
   signal from the ORIGINAL (ratio of upper-case letters over letters, with a
   minimum length of ~15 characters and at least ~4 words, so "HR" and "OK"
   never qualify). Collapse character padding and separator evasion
   (`i d i o t`, `i-d-i-o-t`, `f*ck`) by stripping non-alphanumerics between
   single letters and mapping common leet substitutions (`0→o`, `1→i`, `3→e`,
   `@→a`, `$→s`) on the working copy only.

2. SEVERE lexicon — a short, explicitly enumerated list of identity-slur and
   sexual-harassment patterns, each with an inline comment naming the category
   it covers. Keep the real-word list minimal and deliberately incomplete:
   this phase proves the TIER exists and is separate, and the lexicon is
   editable in one place. Include the placeholder token(s) the verifier uses.
   Severe fires regardless of targeting — a slur does not need a "you".

3. HOSTILE requires BOTH an attack term AND person-targeting. Person-targeting
   = a second-person reference in the same clause as the attack term: `you`,
   `your`, `you're`, `yourself`, or a vocative at the start/end. Attack terms
   are grouped and each group is its own `matched` string:
     - `insult` — demeaning nouns/adjectives applied to a person
     - `profanity_at_person` — profanity whose object is the second person
     - `contempt` — "anyone competent would", "are you stupid", sneering
       comparatives aimed at the person
     - `threat_to_person` — harm/consequence aimed at the PERSON's standing
       ("you'll regret", "I'll end your career", "make sure you never")
     - `shouting` — the ALL-CAPS signal, which counts as hostile only when it
       co-occurs with second-person targeting
   The exclusions are as important as the inclusions and must each carry a
   comment with the corpus row that motivates it:
     - a consequence stated about a PROCESS is not a threat: HR, a formal
       process, a performance plan, escalation, termination, a grade appeal,
       a deadline, a contract. Build an explicit `PROCESS_CONSEQUENCE` pattern
       and let it veto `threat_to_person` for that clause.
     - judgement of WORK, PERFORMANCE, a DECISION, a POSITION, a SITUATION or
       a RESULT is never hostile, even when harsh ("unacceptable", "not good
       enough", "final warning", "this is a mess"). Build an explicit
       `POSITION_OBJECT` pattern; when the attack term's object is one of
       these, the clause is firm, not hostile.
     - un-targeted profanity is not hostile.
   Split on clause boundaries (`.`, `!`, `?`, `;`, `,`, ` and `, ` but `) so
   "your performance has been unacceptable" cannot be joined to a distant
   pronoun.

4. Return `{ tier: "severe" }` if any severe rule fires; else
   `{ tier: "hostile" }` if any hostile rule fires; else `{ tier: "none" }`.
   `matched` is the sorted, de-duplicated list of rule-group names — never the
   matched text itself, so no caller can accidentally quote a slur back out of
   this module.

Iterate on the rules until section 1 of the verifier is fully green. If a
corpus row genuinely cannot be separated by rules, do NOT delete the row: keep
it, record the conflict in the SUMMARY as an open calibration item, and prefer
the FALSE-NEGATIVE (classify as `none`). For this phase, missing a hostile
turn costs one turn of accumulation; firing on a seeded firing conversation
breaks the product.

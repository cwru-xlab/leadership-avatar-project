<objective>
Add the hostility, severe-content and unacknowledged-position signals to the
engine's observable cause vocabulary, make ordinary hostility accumulate and
ratchet one-way, and give a type the ability to declare its own weight profile
so the difficult-conversation type's dead `budget_pressure` weight is
redistributed deliberately rather than inherited silently.

Purpose: Phase 18's five causes are all boredom/stall signals, and because the
difficult-conversation type sets `timeBudget.totalSeconds: null` the
joint-largest of them (`budgetPressure`, 0.25) contributes nothing here. If the
new hostility weight were simply added to the shared default profile, the
pitch-elevator's live threshold behaviour would change — which
`18-VALIDATION.md`'s calibration policy forbids without explicit human
approval. A per-type weight profile keeps every existing type numerically
identical while making this type's arithmetic explicit and reviewable.

Output: three new causes, one new optional type-level field pair, a
`deriveAcknowledgementAbsent` twin of `deriveCommonGroundAbsent`, and the
regression sections that prove the ratchet holds under hostility.
</objective>

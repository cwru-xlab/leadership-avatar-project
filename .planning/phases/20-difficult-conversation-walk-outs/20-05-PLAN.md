<objective>
Wire the new signals, the type weight profile, the severe carve-out and the
derived reason code into the two real server callers, and fix the
forced-farewell directive so an avatar-initiated difficult-conversation end is
actually accepted.

Purpose: this is where Phase 18's failed UAT says the risk lives. Its ratchet
was proven in the unit by passing `priorValue` into the primitive directly, and
was unenforced at the integration seam, so a real session reached 0.6 and then
fell to 0.4. Every contract this phase adds must therefore be asserted at the
real caller. There is also a live defect this plan must close:
`buildWalkOutFragment` hardcodes `<engine-end reason="lost_interest" />`, which
is NOT in `difficult-conversation`'s `avatarEndReasons`, so a forced farewell
here would be rejected by gate (2) of `resolveTermination` and the session would
never end.

Output: both callers compute with the type's weights, both see `severe`, the
forced-farewell directive cites a declared reason, and
`scripts/verify-disengagement-walkout-shell.ts` gains the caller-level and
in-character guards.

**No session-shell changes.** `components/practice/PracticeSessionShell.tsx` is
deliberately NOT in `files_modified`. REQ-101 locks one ending path and no
break-frame branch, and Phase 18's lock, `waitForSpeechEnd()` auto-finish and
proof plumbing already work type-agnostically; the difficult-conversation
launcher at `app/practice/[type]/[instanceId]/page.tsx` already passes
`autoFinishOnAvatarEnd` and a `reportId`. If execution finds a genuine gap,
stop and raise it as a deviation rather than adding a branch.
</objective>

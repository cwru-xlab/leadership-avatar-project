Give `InterviewReport` somewhere to record what customization actually produced a
session, and surface it on the client-facing DTO.

Purpose: REQ-24. `typeSlug` alone stops identifying a session the moment presets become
customizable — two students picking `general` can end up in very different interviews.
This is also the prerequisite for fixing the evaluator blind spot in
`lib/interview/evaluation-runner.ts` (plan 08-04), which today grades every session
against the preset's defaults.

Output: a migration applied to the LOCAL dev database only, plus an extended
`InterviewReportDTO`.
</objective>

Map each field explicitly inside `toInterviewReportDTO` from the corresponding `row.*`
column. Honor the file's existing discipline verbatim: never spread the Prisma row —

student-owned data safe to return to its owner (the route is already owner-scoped with
a 404-never-403 contract) — and in particular that `interviewerPersona` is the
distilled summary, never the raw pasted profile text, which is never stored.

Every new DTO field must tolerate null: pre-Phase-8 rows have all six columns null and
must still produce a valid DTO with no fallback guessing from `typeSlug` here (the

<objective>
Replace `getInterviewType` with the validating resolver at the two prompt-assembly call
sites, persist the resolved customization on the report row, and fix the evaluator so a
customized session is graded against what the student actually experienced.

Purpose: this is the REQ-23 crux. The client resends an identical customization payload
every turn — exactly how `resumeText` already travels — and the server re-derives the
same object deterministically while validating every field. It is also the fix for the
confirmed bug at `lib/interview/evaluation-runner.ts:70`, which today builds the
evaluator's `role_context` from `getInterviewType(report.typeSlug)` and would silently
grade every customized session against the preset's defaults.

Output: three modified server files. No UI in this plan.
</objective>

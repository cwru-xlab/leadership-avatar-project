<objective>
Build the data layer for interview customization: the expanded preset catalog, the
curated option lists, and the single validating resolver that every server call site
will use in place of `getInterviewType`.

Purpose: REQ-23 requires the assembled system prompt to stay session-constant while
the student tunes it. The answer is a pure, deterministic resolver — the client
resends an identical customization payload each turn (exactly as `resumeText`
already travels), and the server re-derives the same `InterviewType` object,
validating every field against fixed lists so no unsanitized student input reaches
the prompt.

Output: `lib/interview/customization-options.ts`, `lib/interview/customization.ts`,
and three new preset records in `lib/interview/types.ts`.
</objective>

  <name>Task 3: Build the validating resolver</name>
  <files>lib/interview/customization.ts</files>
  <action>
New file importing `getInterviewType` / `InterviewType` / `InterviewDifficulty` from
`./types` and the curated lists from `./customization-options`.

Export `MAX_PERSONA_LENGTH = 600` and:

```ts
export interface InterviewCustomizationInput {
  industrySlug?: string;
  roleSlug?: string;
  difficulty?: string;
  lengthSlug?: string;
  personalitySlug?: string;
  /** Pre-distilled persona text ONLY — never the student's raw pasted profile. */
  distilledPersona?: string;
}
```

`composePersona(base: InterviewType, input): string` —
- If `input.distilledPersona` is a non-empty string, return it trimmed and truncated to
  `MAX_PERSONA_LENGTH`, IGNORING the personality dial entirely. Per 08-CONTEXT.md the
  pasted-profile persona plays the named person directly; splicing a generic
  "pressure-testing" clause onto a named real person is incoherent. Document this
  branch in a comment.
- Otherwise look up `input.personalitySlug` in `PERSONALITY_DIALS`; on no match or on
  `neutral` (empty clause) return `base.interviewerPersona` unchanged; otherwise return
  `` `${base.interviewerPersona}, ${clause}` `` (keeping the preset sentence, not
  replacing it).

`resolveInterviewType(slug: string | undefined | null, customization?: InterviewCustomizationInput | null): InterviewType | null` —
Returns `getInterviewType(slug)` unchanged when `customization` is null/undefined.
Otherwise returns a NEW object spread from the base with:
- `defaultIndustry`: `promptValue` of the `CURATED_INDUSTRIES` entry whose `slug`
  matches, else `base.defaultIndustry`
- `defaultRoleTitle`: same lookup against `CURATED_ROLES`, else `base.defaultRoleTitle`
- `difficulty`: `input.difficulty` only if it is a member of `INTERVIEW_DIFFICULTIES`,
  else `base.difficulty`
- `targetMinutes` / `targetQuestionCount`: from the matching `SESSION_LENGTH_PRESETS`
  entry, else the base's two values (both from the same source — never mix a preset's
  minutes with a base's question count)
- `interviewerPersona`: `composePersona(base, customization)`
Every fallback is silent (no throw) — REQ-20's "a blank or cleared field falls back to
the preset's default" means an unknown or empty value is indistinguishable from absent.
This function is pure and must do no I/O: the same inputs must always produce a deeply
equal object, which is exactly what keeps the OpenAI prefix cache hitting across turns.

`resolveCustomizationRecord(resolved: InterviewType)` — returns the six values that
`session/start` will persist on the report row:
`{ industry, roleTitle, difficulty, targetMinutes, targetQuestionCount, interviewerPersona }`,
read straight off the already-resolved `InterviewType`. Do NOT re-derive from the raw
input here; the resolved object is the single source of truth.

Do NOT introduce zod or any validation library — the codebase validates with plain
membership and regex checks inline (08-RESEARCH.md "Don't Hand-Roll").
  </action>

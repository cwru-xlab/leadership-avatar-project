<task type="auto">
  <name>Task 2: Build the Customize panel over the curated lists</name>
  <files>components/interview/CustomizePanel.tsx</files>
  <action>
New client component taking the selected `InterviewType` and an
`onChange(input: InterviewCustomizationInput)` callback.

COLLAPSED BY DEFAULT (REQ-19, locked): render the preset's defaults as a read-only
one-line summary (e.g. "Intermediate · ~20 min · technology · a software engineering
role · neutral & professional"), with a "Customize" disclosure button. Controls mount
only when opened. The fast path — pick a preset, press Start — must not require
opening this panel.

When open, render, pre-filled from the preset's defaults:
- Industry: a HeroUI `Select` over `CURATED_INDUSTRIES`. No free-text input anywhere.
- Role: a `Select` over `CURATED_ROLES` (flat list, not filtered by industry).
- Difficulty: a `Select`/segmented control over `INTERVIEW_DIFFICULTIES`, with helper
  copy stating it changes follow-up depth and how hard the interviewer presses — NOT
  the number of questions (REQ-20).
- Session length: a `Select` over `SESSION_LENGTH_PRESETS` showing each option's label
  and its "~N min · N questions". Not a free number field and not a slider.
- Interviewer personality: a dial over `PERSONALITY_DIALS`.

Defaults pre-fill: the initial selection for each control is the preset's own value
(match `defaultIndustry`/`defaultRoleTitle` against each list's `promptValue`; fall back
to showing the preset's raw value as a non-selectable current state if no list entry
matches). Every control needs a "Use preset default" escape that clears the override —
per REQ-20 a cleared field falls back to the preset default, so clearing emits
`undefined` for that key rather than an empty string. `onChange` must never emit `""`.

Pasted-profile persona (REQ-22):
- A `Textarea` labelled "Who is interviewing you? (optional)" with a paste-or-type
  helper. Cap the input at 4000 chars client-side to match the endpoint.
- An explicit "Build persona" button POSTs `{ profileText }` once to
  `/api/interview/persona/distill`, shows a spinner, then displays the returned persona
  as read-only text with a "Clear" control. Never call the endpoint on keystroke.
- While a distilled persona is present, DISABLE the personality dial with visible
  helper copy explaining the pasted persona is being played directly — this matches
  `composePersona`'s server-side behavior of ignoring the dial in that branch, so the
  UI must not imply a dial that has no effect.
- Rehearsal framing, required copy near the paste box: this is a rehearsal simulation,
  the AI will invent details it was not given, and it is not a portrait of the real
  person. Do not offer any URL field — no LinkedIn or other URL is fetched (deferred).

The component emits an `InterviewCustomizationInput` shaped exactly as plan 08-01
defined it (`industrySlug`, `roleSlug`, `difficulty`, `lengthSlug`, `personalitySlug`,
`distilledPersona`) — slugs, never labels or prompt text. It stores nothing in
localStorage: customization deliberately does NOT persist between sessions (Claude's
discretion per 08-CONTEXT.md — resetting to preset defaults each time is the accepted
simple answer and keeps a third party's pasted description from lingering).
  </action>

- Manually in `npm run dev`: the panel is collapsed on load showing a read-only summary; opening it shows five dropdowns pre-filled with the selected preset's values; switching the selected preset resets the panel to the new preset's defaults; pasting text and pressing "Build persona" returns a persona and visibly disables the personality dial.

<task type="auto">
  <name>Task 3: Hand the resolved customization to the wizard</name>
  <files>app/interview/page.tsx</files>
  <action>
Wire Start on the active preset card to (1) write the current
`InterviewCustomizationInput` to `sessionStorage` under the key
`interview:customization:{slug}` as JSON, then (2) `router.push(\`/interview/${slug}\`)`.

Use `sessionStorage`, not query params: the persona string can run to hundreds of
characters and `[type]` must stay a clean slug (the report page compares
`report.typeSlug !== params.type`). Plan 08-06 reads the key once on wizard mount and
removes it immediately, so a mid-wizard refresh falls back cleanly to preset defaults
rather than silently reusing stale settings — which is also what "settings lock when
the session begins" means in practice.

Write nothing when the student never opened the Customize panel — the absence of the
key is the "use preset defaults" signal, and keeps the fast path free of stale state.
Guard the write in a try/catch: a `sessionStorage` failure (private-mode quirks) must
still navigate, degrading to preset defaults rather than blocking the start.

Document the handoff contract in a comment at the write site, naming the reader
(`app/interview/[type]/page.tsx`) and the read-once-then-remove rule, so the two halves
stay in sync.
  </action>

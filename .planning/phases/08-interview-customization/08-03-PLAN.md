<objective>
Build the one-shot endpoint that turns a student's pasted "who is interviewing you"
text into a short persona string the system prompt can use.

Purpose: REQ-22. The persona must be distilled exactly ONCE, before the session starts
— mirroring `POST /api/interview/upload-resume`, which runs once and hands the client a
processed string it then holds for the rest of the flow. Distilling per chat turn would
be slow, expensive, and would break the session-constant prompt guarantee (REQ-23).

Explicitly out of scope (deferred in 08-CONTEXT.md): fetching a LinkedIn or any other
URL server-side. This endpoint accepts pasted TEXT only and must contain no outbound
HTTP fetch of a student-supplied address.

Output: `app/api/interview/persona/distill/route.ts`.
</objective>

  <action>
New route. Copy the auth and response scaffolding from
`app/api/interview/upload-resume/route.ts` verbatim in shape: `export const runtime = "nodejs"`,
`export const maxDuration = 60`, the local `response(body, status)` helper that sets
`Cache-Control: no-store`, and the guard reading
`request.cookies.get(siteConfig.auth.cookie.name)?.value` into `getCurrentUser`,
returning 401 `{ error: "Unauthorized" }` before anything else happens.

Request body: `{ profileText: string }` (JSON, not FormData).
- Reject a missing/non-string/blank `profileText` with 400.
- Truncate the input to `MAX_PROFILE_TEXT_LENGTH = 4000` chars BEFORE the LLM call.

Make one non-streaming OpenAI call using the same wiring as
`attemptEvaluation` in `lib/interview/evaluation.ts` — dynamic
`const OpenAI = (await import("openai")).default;`, `new OpenAI({ apiKey: process.env.OPENAI_API_KEY, timeout, maxRetries: 0 })`,
`openai.chat.completions.create({ model, messages: [system, user], max_tokens: 300 })`.
Model: `process.env.INTERVIEW_PERSONA_MODEL || "gpt-4.1"`. Timeout ~20s. No new SDK, no
new client module, no prompt-chaining abstraction.

The system prompt must produce a persona sentence in the SAME register and grammatical
shape as the `interviewerPersona` strings in `lib/interview/types.ts` — a second-person
noun-phrase continuation that reads correctly after "playing the role of: " (read
`buildInterviewSystemPrompt` in `lib/interview/prompts.ts` to confirm the exact
sentence it slots into). Per 08-CONTEXT.md the persona plays the named person directly:
instruct the model to take the person's name, role and background from the pasted text
and write the interviewer as that person, using only detail present in the paste and
not inventing biography. Also instruct it to emit plain prose with no markdown, no
preamble, and no quotes.

Response: `{ persona: string }`, with the output trimmed and hard-truncated server-side
to 600 chars (matching `MAX_PERSONA_LENGTH` in `lib/interview/customization.ts`; define
the number locally rather than importing, to keep this route independent of plan 08-01).
On an empty/failed model response return 502 with a plain student-readable message.

RETENTION (REQ-22, locked): the route must not write `profileText` OR the distilled
persona to Prisma, to S3, or to any cache. It must not `console.log` the pasted text
(logging a third party's personal information to server logs violates the retention
constraint) — log only `{ userId, inputLength, outputLength }` on success and the error
class on failure.

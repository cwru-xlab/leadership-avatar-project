<objective>
Give the S3 `CaseStudy` a `published` flag, let staff set it from the case editor, and let
the case list endpoint return published-only results on request.

Purpose: This is what drops the cohort dependency from the student case path. Students will
browse published cases with no assignment and no cohort membership (REQ-15).

Output: `published?: boolean` on the `CaseStudy` interface, a `?publishedOnly=true` mode on
`GET /api/case/list`, and a publish control in the case editor. The student-facing
`/case-play` index that consumes this is plan 07-05.
</objective>

**types/index.ts** — add to the `CaseStudy` interface (around line 202):

```ts
  /**
   * Discovery-layer visibility. `true` means students can find this case in the
   * /case-play index. Absent or false means draft: hidden from browsing, but still
   * playable by direct URL so staff can preview. This is NOT an access control.
```

Optional, not required — every case already in S3 predates this field and must keep type
checking. Do NOT touch the adjacent `cohortIds` field: it is dead (written once as `[]`,

**app/api/case/list/route.ts** — the handler currently takes no arguments and returns
`s3Storage.listCases()` unfiltered. Change the signature to `GET(request: NextRequest)` and:

```ts
const publishedOnly = new URL(request.url).searchParams.get("publishedOnly") === "true";
const cases = await s3Storage.listCases();
const visible = publishedOnly
  ? cases.filter((c) => c.published === true)
  : cases;
```

Return `visible` in the existing response envelope; leave the error handling untouched.

Use `=== true` explicitly, NOT a truthy check — the whole point is that `undefined`
(every pre-existing case) reads as unpublished. Staff republish existing cases manually
after ship; there is deliberately NO backfill script, since backfilling to `true` would
defeat the flag.

Default (no query param) stays unfiltered so `/case-management` keeps seeing drafts with no
change to the staff page's fetch.
